### Track 70 — Module trust
- [x] Signed catalog: release-time `catalog.json` (canonical
  `json.MarshalIndent`) + `catalog.json.sig` (base64 Ed25519) verified
  against a Rhizome release pubkey baked into `pkg/modules` (stdlib
  `crypto/ed25519` — no new dep; signing key = `MODULE_CATALOG_SIGNING_KEY`
  GitHub secret, base64 seed; minisign-format compat optional).
- [x] Remote curated index (`pkg/modules/remote.go`): sibling
  `module_index = {url, enabled}` config — *not* `modules.catalog_url`,
  which collides with the `map[string]ModuleConfig` shape. HTTPS fetch →
  signature verify → cache under `<RHIZOME_HOME>/catalog-cache/` (~1 h
  TTL) → `module list`/`Lookup` merge embedded+remote with `source`
  provenance; embedded wins id collisions (counted in the merged event);
  unsigned/bad-sig → hard refuse + `module.catalog.rejected` event.
- [x] `rhizome module verify <id>` — re-hash installed binary against the
  sha256 recorded at install time in `<id>/<version>/.binary-digest`
  (drift detection; daemonless). *As-built change*: the catalog pin covers
  the release archive, not the extracted binary, so install records the
  extracted binary's digest and verify compares against that record.
- [x] Release plumbing: catalog emit command + secret-gated
  `release.yml` signing step (Docker-Hub pattern — absent key → skip);
  key-gen doc under `docs/operations/module-catalog-signing.md`; events
  `module.catalog.merged|rejected|stale`, `module.verify.ok|failed`.
- [ ] (stretch) Upstream cosign/GPG verification where upstreams actually
  sign — deferrable.

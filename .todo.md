### Track 61 — ACP server (`rhizome acp`)
- [x] `pkg/acp` over `github.com/coder/acp-go-sdk` **v0.13.5** (June 2026, ≥7d). All SDK usage stays inside `pkg/acp`. Binary delta: **+593,920 B (+0.57%)** on `rhizome.exe` (104,644,096 → 105,238,016, CGO_ENABLED=0 goolm,stdjson windows/amd64).
- [x] `rhizome acp [--agent <id>]` command — the editor-facing agent process. stdout is protocol-only: `main()` skips the banner/TZ diagnostics under `stdioProtocolCommand()` and the command calls `logger.DisableConsole()` *before* `LoadConfig` (diagnostics via `RHIZOME_LOG_FILE` or slog→stderr). `--agent` injects a leading `agents.dispatch.rules` entry (`when.channel == "acp"`), so normal routing machinery applies.
- [x] Handlers: `initialize` (protocolVersion negotiation; promptCapabilities text+image); `authenticate` → method-not-found (no auth methods advertised); `session/new` → Rhizome session key **`agent:<agent-id>:acp:<session-id>`** (legacy explicit form so `resolveScopeKey` preserves it — an `acp:<uuid>` key would silently share the route session); `session/prompt` → `ProcessInbound` on channel `acp` + chatID=sessionId, streamed `agent_message_chunk`/`agent_thought_chunk` + `tool_call`/`tool_call_update`; `session/cancel` via the SDK's per-session ctx cancel; `session/load` not implemented (SDK only dispatches it for `AgentLoader`, so `loadSession:false` is honest).
- [x] Streaming via a new **`AgentLoop.ProcessInbound`** seam (full `bus.InboundMessage` — media refs + explicit session key, unlike `ProcessDirectWithChannel`) plus `Server` as an in-process `bus.StreamDelegate` for channel `acp` only. Suffix-diffing `bus.Streamer`+`ReasoningStreamer` turns accumulated provider output into deltas; unstreamed finals flush as one chunk. Model streaming is force-enabled on `cfg.ModelList` and a process-local `Channels["acp"]` entry (no global channel type registered — config decode stays safe).
- [x] Permission bridge: `toolApprover` (in-process `agent.ToolApprover`) claims only channel-`acp` approvals; `acp.server.permission_policy` = `prompt|allow|deny`, default `prompt` → `session/request_permission`; `allow_always`/`reject_always` cached per tool per session; unreachable client/cancel/timeout → deny (fails closed). `ToolApprovalRequest` + `ToolExecStart/End/Skipped` payloads gained **`CallID`** (`tc.ID`) so permission prompts and tool updates share one correlation id.
- [x] Non-goals kept: no client-side `fs`/`terminal` capability consumption; no `session/set_mode`/`set_config_option` handling (no-ops); image blocks materialize to `media://` refs via `FileMediaStore`.
- [x] `docs/guides/acp.md` — Zed `agent_servers` + JetBrains snippets, policy table, `RHIZOME_LOG_FILE` diagnostics.
- [x] Verified: unit tests (`pkg/acp` fake runner/conn + real `EventBus`), and a real stdio smoke — `initialize`/`session/new`/`session/prompt` against a fake SSE OpenAI endpoint produced three `agent_message_chunk` notifications + `stopReason:"end_turn"` with a clean stdout protocol stream.

# Rhizome v0.4.5 Release Notes

**Focus:** Daemon bootstrap override for the live Network status API. The dashboard can now query arbitrary peers from the running daemon instead of falling back to a temporary libp2p node.

## New Features

- **Daemon `/network/status` supports `?bootstrap=...`**:
  - `pkg/gateway/networkapi.go` parses `bootstrap` and `timeout` query parameters.
  - Each multiaddr is validated before any dial attempt.
  - The daemon calls `Mesh.Connect` for each bootstrap concurrently, then returns the updated `NetworkStatus` snapshot.
  - Invalid `bootstrap` values return `400 Bad Request`.
- **Launcher passes `bootstrap` to the daemon**:
  - `web/backend/api/network.go` now forwards `bootstrap` and `timeout` to the daemon endpoint.
  - `?bootstrap=...` no longer forces a CLI fallback when a daemon is running.
  - `?listen=...` still forces the CLI fallback because a running daemon cannot change its listen addresses.
- **Shared mesh connection helper**:
  - `pkg/rhizome/mesh/mesh.go` adds `Mesh.Connect(ctx, addr)` so the gateway handler can ask the mesh's node to dial a peer without touching private fields.

## Fixes

- The Network dashboard no longer spawns a temporary node for a bootstrap override when a `rhizome daemon` is already running.

## Known Limitations

- Bootstrapped peers are connected but not automatically trusted. Their capabilities may not appear until the remote advertises them on a subsequent poll.
- `?listen=...` overrides still require the CLI fallback.
- The daemon endpoint does not currently persist or validate `bootstrap` peers against the config; each request connects independently.

## Build

No CGO on core builds. Use:

```powershell
$env:CGO_ENABLED='0'
go build -tags goolm,stdjson ./...
go test -tags goolm,stdjson ./...
```

For the frontend:

```bash
cd web/frontend
pnpm install
pnpm build:backend
```

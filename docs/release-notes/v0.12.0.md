# Rhizome v0.12.0 Release Notes

## Sprint theme

**Agentic Web3.** Web3 Stage 2 lands: Rhizome agents can hold keys, sign
transactions, and drive contracts — every write gated by policy and a
durable human approval. Plus carried depth: role-aware mesh routing and a
topology view, a much deeper ACP surface, and credential-scheme polish.

- **Wallet + gated signing** — secp256k1 keys, EIP-1559 sends, and a
  pending-approval queue so no agent spends without a human decision.
- **Contract interaction** — ABI registry, `web3_contract_call`/
  `web3_contract_send`, ERC-20/721 helpers, ENS resolution.
- **Wallet ops** — CLI wallet management, balances, log watches, and
  scope-bound channel approvals.
- **Mesh depth** — worker/full node roles feed routing and swarm
  coordinator election; the dashboard gains a live topology panel.
- **ACP deepening** — `session/load` persistence, client-declared MCP
  passthrough, and a policy-gated terminal bridge.
- **Security polish** — `enc2://` XChaCha20-Poly1305 credential blobs and
  a verified headless OAuth matrix.

Design doc: `docs/design/v0.12.0-sprint.md`.

## Features

### Web3 wallet + gated signing (Tracks 77a/77b)

- `pkg/web3` grew a write path: secp256k1 keys (`dcrec/secp256k1`, no
  go-ethereum), Keccak-256/EIP-55 addresses, minimal RLP + EIP-1559 and
  legacy transaction build/sign, `eth_sendRawTransaction` broadcast.
  Keys live in `<RHIZOME_HOME>/web3/keys.json` (0700) encrypted via the
  identity `KeyProvider` posture — keyring default, passphrase fallback.
- `tools.web3.signing` is a **second gate** (default off) on top of
  `tools.web3.enabled`: `from_addresses` (mandatory explicit signer
  list), `allow_contracts`, `allow_methods` (selectors or
  `label:method`), `max_value_wei_per_tx`/`max_value_wei_per_day`
  (decimal wei strings, enforced by a bounded ledger), `chain_ids`, and
  `approval_timeout_seconds`.
- Every write goes through the durable pending queue
  (`<RHIZOME_HOME>/web3-pending.json`, ~100-entry bound, atomic writes):
  policy check → `hook.approve_tool` veto → enqueue → `{pending_id}` →
  human resolves via `rhizome web3 approve|reject`, the daemon API, or
  the dashboard — then sign + broadcast. Timeout/cancel denies.
- New tools: `web3_send`, `web3_sign`, `web3_approve`, `web3_wallet`,
  `web3_pending`, `web3_send_status`.
- `rhizome wallet create|import|list|reveal` (masked output, `--confirm`
  for reveal) and `rhizome web3 pending|approve|reject` — daemon-proxied
  with a daemonless fallback.
- Daemon endpoints (bearer auth): `GET /web3/pending[/id]`,
  `GET /web3/wallet`, `POST /web3/approvals/<id>`; `web3.*` runtime
  events feed the activity stream. Launcher mirrors under `/api/web3/*`.
- Dashboard `/web3` page: wallet card + approve/reject dialog, sidebar
  pending-count badge.

### Contract interaction (Track 78)

- `<RHIZOME_HOME>/web3-abis.json` ABI registry: `rhizome web3 abi
  add|list|show|remove`, per-chain binding, selector index.
- `web3_contract_call` (read) and `web3_contract_send` (queued write);
  `web3_erc20`/`web3_erc721` helpers (read actions ungated,
  transfer/approve queued); `web3_ens` forward/reverse resolution.
- `allow_methods` accepts readable `label:method` entries (e.g.
  `usdc:transfer`) — resolved to selectors at eval time and bound to the
  label's contract address, so a readable allowlist is actually
  enforceable.

### Wallet ops depth (Track 79)

- `rhizome wallet set-default|rename`; `web3_wallet` marks the default
  address and reports balances; `GET /web3/wallet?balances=true` and the
  dashboard wallet card show ETH balances.
- **Log watches**: `tools.web3.watches[]` — daemon-polled `eth_getLogs`
  subscriptions (nimbus proxy has no subscription support) emitting
  `web3.event` runtime events; `watch_confirmations` delays emission for
  reorg protection; per-watch cursors persist across restarts. The
  `web3_watch` tool manages entries (persisted to `config.json`).
- **Channel approvals** (off by default): `tools.web3.approval_channels`
  lists the only `channel[:chat_id]` scopes whose `/web3
  pending|approve|reject` commands are honored — `resolved_by` records
  the approving scope on the pending entry.

### Mesh depth (Track 80)

- Nodes advertise `full`/`worker` roles through capability manifests and
  swarm rosters. `mesh.routing.role_aware` (default on) gives workers a
  ranking bonus for task ops (`delegate`/`spawn`) and fulls the same for
  infra ops (`sync`) in `Mesh.PickPeer`; direct connectivity still
  dominates. Peers without a role are treated as `full` for
  compatibility.
- Swarm coordinator election prefers full members (role change triggers
  re-election; peer id remains the deterministic tie-breaker) and
  `rhizome swarm members` shows roles.
- Dashboard Network page gains an SVG **topology panel**: local node at
  center, peers on a radial ellipse, transport-colored edges (QUIC/TCP/
  relay), latency-scaled stroke width, direction markers, and a
  click-through peer detail sheet.

### ACP deepening (Track 81)

- **`session/load`**: `rhizome acp` now persists session metadata to
  `<RHIZOME_HOME>/acp-sessions.json` (0600, atomic, 256-entry FIFO),
  advertises `loadSession`, and replays history as `session/update`
  chunks on load — cached `allow_always`/`reject_always` permission
  decisions restore too.
- **MCP passthrough**: clients may declare stdio `mcpServers` on
  `session/new`/`session/load` (≤4, 30 s connect bound, env-only child
  environments). Tools appear as `mcp_acp-<session>-<server>_<tool>`,
  visible to and callable by only the owning session, and are torn down
  on session close. http/sse/acp variants are refused.
- **Terminal policy**: `acp.client.terminal_policy = deny` (default) |
  `allow` — when allowed, `terminal/*` requests bridge onto a private
  guarded exec session pool (same deny patterns, workspace-restricted
  cwd, bounded output); terminal ids are session-bound and die with the
  agent process.

### Security polish (Track 82)

- **`enc2://`** credentials: XChaCha20-Poly1305 with `salt(16)|nonce(24)|
  ct` blobs and HKDF info `rhizome-credential-v2`. Legacy `enc://`
  (AES-256-GCM) decrypts transparently; new writes are `enc2://`.
- **`rhizome auth login` flag matrix**: `--device-code` is openai-only,
  `--setup-token` anthropic-only, `--no-browser` browser flows only —
  unsupported combinations now fail with a clear error. Headless matrix
  documented in `docs/guides/providers.md`.

## Upgrade notes

- **`enc2://` is a one-way door.** Values re-saved by v0.12.0 cannot be
  read by older builds — don't downgrade after saving config with this
  release. `enc://` values keep working indefinitely; they are upgraded
  to `enc2://` the next time they're written. See
  `docs/security/credential_encryption.md`.
- **Signing is double-gated.** `tools.web3.enabled` alone grants only
  reads; writes additionally need `tools.web3.signing.enabled` plus a
  non-empty `from_addresses`, and every write still waits for a human
  approval.
- **ACP `terminal/*` stays off** unless `acp.client.terminal_policy=allow`
  — external agents cannot proxy shells by default.
- **Channel approvals stay off** unless `tools.web3.approval_channels`
  names scopes explicitly.

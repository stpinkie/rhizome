# Rhizome v0.14.0 Release Notes

## Sprint theme

**The Open Agent Work Market** — mutually untrusted operators buying and
selling agent work: priced offers, on-chain escrowed sessions, sandboxed
execution, signed receipts. Ships **experimental**: the settlement rail
defaults to a local fixture, discovery is direct-peer adverts, and the
recorded testnet E2E + curated index/DHT/reputation graduate in v0.16.0.

The sprint also landed the module system's biggest additions (the
llama.cpp ondemand modules and catalog schema v5), an upstream
cherry-pick sweep, the ACP-over-HTTPS transport that opens the market to
non-Rhizome buyers, and the localization/integration-verification tail.

- **Market module** — `rhizome-market` companion daemon: sell-side
  escrow-gated sessions, buy-side async purchases, signed receipts.
- **Settlement** — `pkg/settlement` Smart Invoice rail + wallet/direct/
  approval signer modes, chain pinning, per-purchase escrow watches.
- **llama.cpp modules** — `llama-cpp` + `llama-cpp-vulkan` ondemand
  `llama-server` entries; catalog schema v5 (layout-preserving
  `binary_path`, arch aliases, digest-pinned weight fetches).
- **ACP-over-HTTPS** — `serve_https_listen` wss transport with TOFU
  fingerprint pinning — buyers no longer need a mesh identity.
- **Seams** — `acp.runtime` exec/sandbox/container modes, module stream
  bridge + `acp.remote`, `ModuleAdverts` in the signed manifest.

Design docs: `docs/design/v0.14.0-sprint.md`,
`docs/design/mesh-economy-module.md`,
`docs/design/llama-cpp-module.md`. Operator guide:
`docs/guides/market.md`.

## Features

### ACP runtime modes + network isolation (Track 97)

- `acp.client.runtime`: `exec` (unchanged default), `sandbox`
  (`pkg/isolation` wrapper over a per-agent scratch root;
  `sandbox.network=none` refuses to run unsandboxed where the platform
  can't enforce it), `container` (docker/podman stdio ACP —
  `container.engine=auto`, `pull=missing|never`, `network=none|bridge`).
- Per-binding override via `agents.list[].acp.runtime`.

### Module stream bridge + `acp.remote` (Track 98, PR #46)

- Modules declare libp2p `protocols` in the catalog (schema v4); the
  daemon runs a loopback bridge (`RHIZOME_BRIDGE_ADDR`/`_TOKEN`) that
  splices declared streams byte-for-byte — outbound dials and inbound
  accepts, mesh-trust-gated, works under `--no-gateway`.
- `acp.server.remote` serves ACP to *trusted* mesh peers over
  `/rhizome/acp/1.0.0`; `agents.list[].acp.remote` binds a trusted peer's
  served agent as a local agent id.

### Module capability adverts + `rhizome market` CLI (Track 99)

- `<module_dir>/advert.json` (≤16 KiB, module-defined) merges into the
  **signed** capability manifest as `ModuleAdverts` + `allows.
  market_serve` — only when the module is enabled and `serve_enabled`
  is truthy. The daemon journals every peer's adverts to
  `peer-adverts.json` for direct-peer discovery.
- `rhizome market find|buy|session|receipt|dispute|refund|release` —
  thin verbs over the module's loopback API; a clean not-installed
  message when the module is absent.

### `rhizome-market` skeleton (Track 100, PR #55)

- First-party `kind:daemon` module built from `cmd/rhizome-market`
  (separate goreleaser archives — never in the base binary). Self-reads
  `modules.rhizome-market.{fields,secrets}` — no Arg/Env mappings, so
  secrets never enter argv/env. Loopback API, bridge client, advert
  writer, `market-audit.jsonl`.

### Escrow survey + `SettlementRail` (Track 101, PR #54)

- `docs/design/escrow-survey.md` — the adopt-existing-contract survey;
  canonical Sepolia pins recorded.
- `pkg/settlement`: `SettlementRail` interface (`VerifyLock`, `Open`,
  `Release`, `Lock`, `Withdraw`, `Claim`), fixture rail (in-memory
  default), Smart Invoice binding, `QueuedSender`/`DirectSender`/
  `WalletSender` signing modes.

### Sell-side: session manager + receipts (Track 102, PR #56)

- `_rhizome.session_open` extension method — `{session_id, task_hash,
  offer_id, buyer, terms}` where `session_id` is the escrow clone.
- The gate rejects before any spawn: `serve_enabled`, per-peer open rate
  limit, offer enabled, `amount` == offer price, then `VerifyLock` —
  escrow exists, holds ≥ locked amount, unreleased, `details` carries the
  same `task_hash`.
- `session/new` spawns the offer's `agent_binding` via `acp.SpawnBound`
  — deny-all permissions, scratch cwd, forced no-egress; single-prompt
  sessions; `session/update` relays verbatim.
- `_rhizome.receipt` — Ed25519-signed JSON (`duration_ms`, `usage`,
  `result_sha256`, `terms`, `settlement`, `interrupted`) persisted to
  `receipts/`; conn-drops mint honest interrupted receipts.

### Buy-side: purchases + export policy (Track 103)

- `market buy <provider> <offer> <task>` is asynchronous — a persisted
  `purchases/<id>.json` record drives escrow open → dial →
  `session_open` → prompt → verified receipt → release in the
  background; `session` reports the live state machine.
- Discovery: `peer-adverts.json` journal by default; opt-in signed index
  (`market_index_enabled`/`_url`/`_pubkey`, Ed25519-verified, 1 h cache,
  stale-serve on outage).
- Controls: `buy_max_cost_per_task`/`_per_day`/`--max-cost` exact-decimal
  caps; `export_redact` over task text; `export_allow_attachments`
  denies URI blocks outright (bytes never leave the module);
  `export_require_review` mints a binding `review_id` replayed by
  `buy --confirm`.
- Disputes: `buy_auto_release=false` parks verified purchases for manual
  `release`; failures park `disputable` — `dispute` locks the escrow,
  `refund` withdraws after the window.

### Wallet-signing settlement + escrow watcher (Track 104, PR #58)

- `settlement_signer=wallet`: decrypts the shared web3 wallet key,
  `FillTxDefaults` → `SignTx` → `eth_sendRawTransaction`, key material
  zeroed per send — autonomous buys with `buyer_address` required to
  resolve a wallet-store key.
- Chain pinning: live `eth_chainId` must equal `escrow_chain_id` at rail
  assembly *and* on every wallet sign; chain 1 refused unless
  `escrow_allow_mainnet=true`.
- `pkg/web3.DecodeSignedTx` + FakeChain `eth_sendRawTransaction` — wallet
  signing is exercised end-to-end in tests, not mocked.
- Per-purchase `eth_getLogs` escrow watcher (`escrow_watch_interval`,
  persisted `watch_block`): observed Release/Lock/Withdraw/Resolve
  transition the purchase; `disputed` stays watched for arbiter resolves.

### ACP tail (Track 106)

- `thought_level` config category; http/sse `mcpCapabilities` forwarding.

### Upstream cherry-pick sweep (Tracks 108/108b)

- Re-triaged `main..upstream/main`; picked fixes recorded in

### llama.cpp modules (Track 109, PR #63)

- Catalog schema v5: `binary_path(s)` layout-preserving extraction
  (nested `llama-bNNNNN/` dirs keep their shared libraries adjacent), tar
  symlink/hardlink refusal, per-GOOS `arch_aliases` (`amd64`→`x64`), the
  `fetch` list (digest-pinned downloads outside the version dir —
  reinstalls don't re-pull gigabytes), `Split` fields (whitespace argv).
- `llama-cpp` (CPU — macOS builds already carry Metal) and
  `llama-cpp-vulkan` (discrete GPU), pinned at upstream `b11280` with
  real per-platform digests. CUDA deferred — upstream ships it as a
  companion `cudart` archive the single-pin model can't express.
- Ondemand lifecycle: `module start` launches once — exit is final, no
  restart supervision; required-field validation runs before multi-GB
  weight downloads; unresolved `{placeholders}` stay literal and fail
  loudly rather than silently emptying.
- Consumer story: an `openai-compatible` provider profile pointing at
  `http://127.0.0.1:{port}/v1`.

### ACP-over-HTTPS transport (Track 110, PR #64)

- `serve_https_listen` binds an optional TLS listener; `wss://` upgrades
  at `/rhizome/acp` adapt to a raw byte stream so ACP ndjson flows
  byte-identical into the shared session gate — the
  `_rhizome.session_open` → `VerifyLock` → sandboxed-spawn path is
  literally the same code as the libp2p splice.
- Self-signed ECDSA pair persisted under the module dir (or configured
  `serve_https_cert`/`_key`); the advert's `tls_fingerprint` + `endpoints`
  emit only while the listener is bound and `serve_enabled`.
- Buyers prefer an advertised `wss://` endpoint and pin the connection to
  the fingerprint byte-exactly — CA bypassed, leaf sha256 must match
  (TOFU; persisted as `dial_tls_fp`). Wildcard listens without
  `serve_https_advertise` honestly advertise nothing.
- Bounds: `serve_https_max_conns`, ~15 s upgrade→first-message bound,
  4 MiB message cap, per-IP rate limits identical to mesh peers.

### Localization tail + integration verification (Track 111, PR #65)

- All 9 locale README h1s retranslated to the rebranded tagline
  ("Your AI Agent, Everywhere"); remaining `PicoClaw` mentions are
  legitimate fork-provenance mirroring the English canonical.
- `scripts/integration-mesh.sh` + `integration-swarm.sh` both verified
  green — ping, bidirectional workspace sync, reconnect catch-up; swarm
  join, roster exchange, presence, restart persistence. Windows/Git-Bash
  runners need `MSYS2_ARG_CONV_EXCL='/ip4'` (multiaddr args escape path
  conversion while `mktemp` paths still resolve).

## Upgrade notes

- **No breaking changes.** New config keys are additive with inert
  defaults: `acp.client.runtime`, `sandbox.*`, `container.*`,
  `modules.rhizome-market.*` (incl. `serve_https_*`),
  `modules.llama-cpp.*`. `config.example.json` documents all of them.
- `rhizome-market` installs from release archives —
  `rhizome-market_{goos}_{goarch}.{tar.gz,zip}` covered by
  `checksums.txt`; the catalog digest pin lands post-tag.
- The market is **experimental**: fixture rail by default, direct-peer
  discovery, no reputation. Read `docs/guides/market.md` *Threat model*
  before serving or buying.

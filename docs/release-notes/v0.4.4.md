# Rhizome v0.4.4 Release Notes

**Focus:** Live Network status API — serve mesh/DHT state from the running daemon instead of spawning a temporary libp2p node for every dashboard refresh.

## New Features

- **Unified backend endpoint** `GET /api/network/status`:
  - Returns a single `NetworkStatusResponse` with identity, connected peers, and DHT snapshot.
  - When a `rhizome daemon` is running, the launcher proxies to the daemon's `GET /network/status` endpoint.
  - The daemon endpoint is served in-process by `pkg/gateway/networkapi.go` and reads live state from `Mesh.NetworkStatus()`.
  - Endpoint is protected by the PID file token (`Authorization: Bearer <pid-token>`).
- **Combined CLI status source**:
  - `cmd/rhizome/internal/network/status.go` now uses `Mesh.NetworkStatus()` to build its JSON output.
  - `pkg/rhizome/mesh` gained `NetworkStatus`, `PeerStatus`, `PeerCapability`, `SetName`, and `Name` so the same status JSON is produced in one place.
- **Compatibility aliases**:
  - `GET /api/network/peers` and `GET /api/network/dht` still work and now return the combined response.
- **Frontend simplification**:
  - `web/frontend/src/api/network.ts` now exports `getNetworkStatus`.
  - `web/frontend/src/hooks/use-network.ts` uses a single `useQuery`.
  - `web/frontend/src/components/network/network-page.tsx` feeds both panels from the same `statusQuery`.
- **Gateway registration**:
  - `pkg/channels.Manager` gained `RegisterHTTPHandler` for non-channel routes.
  - `cmd/rhizome/internal/daemon/command.go` sets the mesh node name so `NetworkStatus()` reports it.

## Fixes

- Reduced temporary libp2p node churn: the dashboard no longer spawns a temp node on every refresh when the daemon is running.

## Known Limitations

- The daemon's `/network/status` currently does not honor `bootstrap` or `listen` query parameters. Passing them forces the launcher back to the single CLI-spawn fallback.
- If the running gateway is `rhizome gateway` (no mesh) or the daemon has mesh disabled, the endpoint falls back to the CLI.

## Build

No CGO on core builds. Use:

```powershell
$env:CGO_ENABLED='0'
go build -tags goolm,stdjson ./...
go test -tags goolm,stdjson ./...
```

For the frontend:

```bash
cd web/frontend
pnpm install
pnpm build:backend
```

# Rhizome v0.8.5 Release Notes

## Sprint theme

Post-v0.8.4 stabilization: the first full release gate on a
properly-provisioned Linux runner, plus the product fixes it surfaced in the
swarm roster, the mesh skill-share path, and the reliable-stream transport.

`v0.8.4` shipped the small-VM script fixes; its tag (`f0e7339b`) predates the
two follow-up script repairs (`1d8dc6fd`) and everything below. This release
carries all of that plus the defects found when the Linux gate finally ran
end-to-end.

No new product features.

---

## Defects fixed

### Swarm roster convergence (`pkg/rhizome/swarm`)

- **Periodic re-announce heals diverged rosters.** The JOIN/JOIN_ACK exchange
  previously ran only on connect events and once at startup; a single lost
  exchange left rosters permanently diverged (observed in CI as "daemon B
  never saw A in the ops roster", twice). `reannounceLoop` now re-announces
  joined swarms to connected trusted peers every ~3 heartbeat intervals
  (minimum 5 s), letting rosters self-heal without a reconnect. Regression
  coverage: `TestSwarmRosterReconvergesAfterTrustGrant`.
- **Concurrent `save()` can no longer delete the roster.** Announce acks,
  presence pings, and expiry all persist `swarms.json` from their own
  goroutines, and every save wrote the same fixed `swarms.json.tmp`: two
  interleaved saves could remove `swarms.json` after its tmp was already
  renamed away. `saveMu` now serializes the sequence, each save uses a unique
  `os.CreateTemp` file (matching `runStore`), and the destination is renamed
  over rather than removed first — the remove+rename fallback only handles a
  held-open destination. Regression coverage: `TestSaveConcurrentKeepsRoster`.

### Reliable-stream transport (`pkg/rhizome/stream`)

- **`ReadFrame` no longer drops a frame queued before the peer's close.** The
  reader can deliver a data frame to `recvCh` and then observe the peer's
  close frame in the same scheduling quantum — the exact wire sequence of
  every request/response `Call`. `ReadFrame`'s bare `select` over `done` and
  `recvCh` then had both cases ready and picked randomly, so ~50 % of the time
  it returned `reliable conn closed` and discarded a response the peer had
  already ACKed. On a contended runner the application goroutine is
  descheduled long enough for this to be frequent (seen as
  `TestIdempotentDuplicateCorrelationID` failing with "read response:
  reliable conn closed", and plausibly the root cause of the lost JoinAcks
  behind the swarm roster divergence above). `ReadFrame` now drains `recvCh`
  once more when `done` wins the select, mirroring `waitForAck`. Regression
  coverage: `TestReadFrameDeliversFrameQueuedBeforeClose`.

### Mesh (`pkg/rhizome/mesh`)

- **`SkillShare` data race fixed.** `shareableSkills()` read
  `cfg.SkillShare` from announce/capability goroutines while it could be
  mutated post-`Start`. Accesses are now guarded by `skillShareMu`, with a
  `SetSkillShare` setter that copies the caller's slice.

### Shell sandbox (`pkg/tools/shell`)

- **Canonicalized the sandbox root.** Candidate paths were symlink-resolved
  but the workspace root was not, so `filepath.Rel` falsely flagged escapes —
  the Windows CI failure came from `RUNNER~1` 8.3 short names, and macOS
  `/var`→`/private/var` hit the same path. Both sides are now canonical, and
  `expandLeadingTildes` replaces a blanket `~` substitution that was itself
  corrupting 8.3 names. A workspace-internal symlink pointing outside still
  resolves outside and is still rejected — the sandbox is unchanged in what
  it allows.

### CLI output (`cmd/rhizome`)

- **`swarm members|list|status|offers` now write to stdout.** Cobra's
  `cmd.Print*` writes to `OutOrStderr()`, which falls back to stderr when
  `SetOut` is unset — so piping the roster to `grep` in
  `scripts/integration-swarm.sh` could never match on POSIX. The commands now
  print via `fmt.Fprint(cmd.OutOrStdout())`, which also makes them
  `SetOut`-testable.

### Lint

- Removed an `unconvert` violation (`uint64(st.Bavail)` — the field is already
  `uint64` on all Linux arches).

### Frontend

- Reformatted 11 files that were failing the `pnpm format` CI gate on `main`.
- The swarms panel/tasks hooks now read daemon roster state via the API
  instead of assuming local persistence paths.

## CI policy changes

- **govulncheck gate** exempts `GO-2024-3218` (Kademlia DHT content
  censorship): every `go-libp2p-kad-dht` release is affected and no fixed
  version exists, so there is no upgrade that clears it. The gate still fails
  on any other reachable finding — and now also fails when the scan itself
  errors, rather than passing on empty output.
- **Retry policy for documented libp2p timing flakes:** failed Windows test
  packages are retried individually (up to 2 additional attempts); the swarm
  integration script is retried once. The retry applies to the known
  scheduler/dial-timing contention documented in `.todo.md`, not blanket
  re-runs.
- `integration-swarm.sh` roster timeouts raised (60 s→120 s, 120 s→180 s) and
  a roster failure now dumps both daemon logs and both `swarms.json` files.

- **PR #3 merged with 11/11 CI checks green** on `c552a427`, including the
  first-attempt pass of Swarm Integration after the fixes above.
- The deferred Linux re-verification of the Windows-flaky mesh timing tests is
  closed: `TestMeshFanoutQuorumPending`, `TestSwarmOfferClaimAssign`, and
  `TestMeshTaskSpawnDisabled` passed in every Linux run; remaining flakes are
  scheduler/dial-timing contention under parallel `go test`, not
  Windows-specific.

## Compatibility

- The swarm re-announce sends additional periodic signed JOIN envelopes over
  the existing `/rhizome/swarm/1.0.0` protocol — wire-compatible, and receivers
  already deduplicate joins.
- `swarms.json` is still a single JSON document at the same path; only the
  write path changed. Temp files are now named `swarms.json.tmp.*` instead of
  `swarms.json.tmp`.
- No config schema changes.

## Remaining blocked/deferred items

- Logo/branding asset replacement, translated README rebrand, `nightly.yml`
  and `docker-build.yml` release credentials, and QEMU/Android 4.4 hardware
  smoke tests remain blocked or deferred as documented in `.todo.md`.
- `GO-2024-3218` remains accepted until a fixed `go-libp2p-kad-dht` release
  exists; the exemption is re-checked on every security scan.

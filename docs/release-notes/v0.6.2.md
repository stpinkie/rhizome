# Rhizome v0.6.2 Release Notes

## Mesh follow-through part 2: resilient remote task routing and config UX

### Peer performance scoring and resilient routing

- Added `PeerScoreStore` at `<RHIZOME_HOME>/mesh-peer-scores.json` to persist observed call quality (success/failure counts and exponential moving average latency) across daemon restarts.
- `Mesh.PickPeer` now uses `PeerScoreStore` quality, active task count, and direct/relayed connection state to rank capable peers.
- `Mesh.CallRemote`, `Mesh.SubmitRemoteTask`, and the task protocol calls record call outcomes and latency to update peer scores.
- `Mesh.SubmitRemoteTaskWithPeer` exposes the actual peer that accepted an async task so callers can poll or cancel on the right peer after failover.

### Remote task retry and failover

- Added `mesh.task_retries` (default `3`) and `mesh.task_failover` (default `true`) configuration fields.
- `Mesh.SubmitRemoteTask` and `Mesh.CallRemote` now try the preferred peer first, then fail over to the next-best capable peer when `task_failover` is enabled.
- Failover skips non-retryable errors (e.g. local signing failures, missing system prompt, context cancellation) and reuses the same correlation ID across peers for idempotent resubmit on a given peer.
- Sync calls stop on task execution failure (`remote agent failed`) to avoid duplicate execution.
- The daemon `/network/tasks` submit endpoint and `rhizome mesh route` / `rhizome mesh spawn` return the actual peer used after failover.

### Web console Mesh config UX

- Replaced the raw `trusted_peers` and `bootstrap_peers` textareas with inline, validated peer list inputs (`MeshPeerList`):
  - Bare peer IDs are validated against the libp2p base58btc Ed25519 format.
  - Bootstrap multiaddrs are validated for a `/p2p/<peer-id>` suffix.
  - Add/remove buttons provide an inline editing experience.
- Added Mesh config controls for `task_retries` and `task_failover`.

### Fixes carried over from the v0.6.2 review

- `PeerScoreStore` now coalesces disk writes (1-second debounce) instead of rewriting on every call.
- `OpResult` long-poll calls no longer record their latency as peer responsiveness, avoiding score bias from slow tasks.
- Evicted running tasks in the local `TaskStore` are marked `StatusError` with an event published before removal.
- SSE setup errors in the gateway now return proper HTTP status codes before committing to a 200 event stream.
- Removed unused `TaskStore.dirty` and `peerScoreFile` dead code.

## Compatibility

- No breaking changes to the `/network/tasks` HTTP API shape. The submit response continues to include `task_id` and `peer_id`.
- The `Mesh.SubmitRemoteTask` Go API is unchanged; it now accepts an empty peer ID to trigger automatic peer selection and failover.

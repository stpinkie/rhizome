# Rhizome v0.9.1 Release Notes

## Sprint theme

Post-v0.9.0 hardening patch. Remote validation on a resource-constrained
runner (4 GB overlay, 2 GiB cgroup) surfaced two product-code concurrency
bugs plus a set of test-timing races; all are fixed here. No new features,
no behavior changes to the v0.9.0 feature set.

---

## Defects fixed

### Sync (`pkg/rhizome/sync`)

- **`Syncer.Stop` no longer panics under load.** Every `wg.Add` call site
  (inbound announces, watcher callbacks, `OnConnected`, anti-entropy
  per-peer spawns) could fire while `Stop`'s `wg.Wait` was blocked, and a
  0→1 counter transition during `Wait` trips Go's misuse detector —
  "WaitGroup is reused before previous Wait has returned". The race existed
  on production daemon shutdown mid-sync-cycle, not just tests. A
  `stopping` flag under an RWMutex now gates all `Add`s via a `spawn()`
  helper, and `Stop` is idempotent. Regression test:
  `TestSyncerStopConcurrentAnnounce`.

### Swarm work queue (`pkg/rhizome/swarm`)

- **In-window claims can no longer be dropped when the window closes.**
  `resolveOffer`'s claim collector used `select` between the window timer
  and the claims channel; when both were ready the timer could win and an
  in-time claim was discarded, wrongly expiring the offer (terminal — no
  retry) instead of assigning it. The collector now drains `claimsCh` once
  more after the window closes before declaring zero claims.

## Test & infra hardening

- `TestSwarmOfferRetryThenDeadLetter` injects claims directly via
  `onClaim` instead of the libp2p broadcast round trip — deterministic
  under CPU starvation (~10s vs previous 60s+ waits).
- `TestSetContextCoordinatorOnly` waits for a *converged* coordinator
  election rather than any non-empty result per node.
- `TestAgentManifestAdvertisedInCapability` asserts stored-manifest
  authenticity (signature, peer binding) instead of fingerprint equality
  across two capability snapshots — each capability build re-signs with a
  fresh `IssuedAt`, so cross-snapshot fingerprints legitimately differ.
- `scripts/validate-small-vm.sh`: `GOMAXPROCS` default capped at 2 and
  `GOMEMLIMIT` at 1500MiB — golangci-lint's default worker count
  (host CPU count) OOMed under the validator's 2 GiB cgroup.
- Lint sweep: `golangci-lint fmt` applied (gci/golines/gofmt/gofumpt),
  `canonicalheader` fix, dir/file perms tightened to `0700`/`0600` in
  blackboard/agentmanifest, `errcheck`/`nilerr`/`gosec` annotations.

## Validation

Remote Linux runner (Go 1.26.6, golangci-lint v2.13.2): full lint clean,
all targeted packages green sequentially, and the parallel flake hunt
shows only the documented timing-flake family — no new flags.

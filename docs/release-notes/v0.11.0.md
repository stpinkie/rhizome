# Rhizome v0.11.0 Release Notes

## Sprint theme

**Reads & trust.** Web3 Stage 2 begins with read-only Ethereum JSON-RPC
agent tools riding verified endpoints, and the module system gains a
signed remote catalog plus drift verification. This release ships the
merged scope of the v0.11.0 sprint — four of nine tracks; the remainder
(wallet + gated signing, ACP deepening, mesh routing depth, security
polish) moved to v0.12.0, where signing becomes the spine of an
agentic-web3 sprint.

- **Web3 read tools** (`web3_*`) give agents read-only Ethereum access
  over operator-configured endpoints — including the verified
  `nimbus-verified-proxy` module.
- **Module trust** adds an Ed25519-signed remote catalog index and
  `rhizome module verify` install-drift detection.
- **New module tenants**: `helios` (Ethereum light client) and
  `ipfs-kubo` (IPFS node) join the catalog on schema v2.

Design doc: `docs/design/v0.11.0-sprint.md`.

## Features

### Web3 read tools (Track 68) — `pkg/web3`, `pkg/tools/web3`

A dependency-free, read-only Ethereum JSON-RPC layer. Seven agent tools
— `web3_chain`, `web3_balance`, `web3_call`, `web3_block`,
`web3_transaction`, `web3_logs`, `web3_rpc` — **disabled by default**
(`tools.web3.enabled`). No send/sign path exists; `web3_rpc` passthrough
is restricted to a hard-coded read-only method allowlist (`eth_call`,
`eth_get*`, `net_*`, `web3_*`; `eth_accounts` deliberately excluded).

Endpoint resolution is operator-config only — tools never accept URLs:

1. `tools.web3.endpoint` (+ `tools.web3.api_key` Bearer — a SecureString
   that migrates to `.security.yml` and joins the
   `SensitiveDataReplacer`)
2. `modules.ethereum-rpc` `fields.endpoint_url` (+ secret `api_key`)
3. A running `nimbus-verified-proxy` module (verified light-client RPC)

`tools.web3.allow_private_endpoints` opts into loopback/private-IP
endpoints (required for the nimbus proxy's `http://127.0.0.1:8545`
default); otherwise the safe-dial SSRF guard blocks private/restricted
IPs and DNS-rebinding at dial time. `tools.web3.chain_ids` restricts
which networks tools will query; `max_log_range` caps `web3_logs`
span (default 10 000 blocks); per-call timeout default 30 s.

### Module trust (Track 70) — signed remote catalog + `module verify`

- `module_index = {enabled, url}` (a sibling of `modules`) enables a
  remote catalog: `<url>/catalog.json` + `catalog.json.sig` — an
  Ed25519 signature over the served bytes, verified against the
  baked-in release public key. Unsigned or bad-signature content is
  refused outright; embedded catalog entries win id collisions.
- Verified remote catalogs cache under
  `<RHIZOME_HOME>/catalog-cache/` (1 h TTL; stale-serve only on fetch
  failure).
- `rhizome module verify <id>` re-hashes an installed module binary
  against its install-time sha256 record — daemonless drift detection.
- Releases sign the catalog via the `MODULE_CATALOG_SIGNING_KEY`
  secret; see `docs/operations/module-catalog-signing.md`.

### New module tenants (Track 71) — `helios`, `ipfs-kubo`, catalog v2

- `helios` (a16z/helios Ethereum light client — linux/darwin) joins the
  catalog as an alternative to `nimbus-verified-proxy`, configured via
  env vars behind its `ethereum` subcommand.
- `ipfs-kubo` (IPFS node — all platforms) exercises the new `.zip`
  extraction path, `ipfs init` behind `init_marker`, and per-launch
  `ipfs config Addresses.*` via `setup_args`; `IPFS_PATH`/`repo_dir`
  resolve under the module dir through the new `{module_dir}`
  placeholder.
- Catalog schema v2: zip extraction guards, asset-suffix dispatch,
  env-var field injection, init-marker lifecycle.

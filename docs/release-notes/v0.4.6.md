# Rhizome v0.4.6 Release Notes

**Focus:** Bootstrap trust, eager capability exchange, and persistent mesh peers. The Network dashboard can now opt in to trusting a bootstrapped peer, see its capabilities immediately, and have the daemon reconnect and trust it on the next run.

## New Features

- **Daemon `/network/status` supports `?trust=true`**:
  - `pkg/gateway/networkapi.go` parses the `trust` query parameter.
  - After a successful `Mesh.Connect`, the daemon:
    - extracts the peer ID from the multiaddr,
    - calls `Mesh.TrustPeer` and `Mesh.TrustAndDiscover` to fetch and store the remote capability,
    - advertises the local capability back to the peer,
    - appends the multiaddr to `config.Mesh.BootstrapPeers` and the peer ID to `config.Mesh.TrustedPeers`, then saves `config.json`.
- **Launcher forwards `trust=true`**:
  - `web/backend/api/network.go` passes `trust` to the daemon endpoint.
  - When the daemon is unavailable, the CLI fallback runs `rhizome network status ... --trust` so the peer is still persisted.
- **CLI `network status --trust`**:
  - `cmd/rhizome/internal/network/status.go` persists the bootstrap multiaddr and peer ID to `config.json` when the flag is set.
- **Persistent mesh bootstraps**:
  - `pkg/config/config.go` adds `mesh.bootstrap_peers`.
  - `cmd/rhizome/internal/daemon/command.go` merges `cfg.Mesh.BootstrapPeers` into the libp2p node bootstrap list on startup.
  - `pkg/rhizome/mesh/mesh.go` already loads `cfg.Mesh.TrustedPeers` on `Start`.
- **Network dashboard "Trust & remember" toggle**:
  - `web/frontend/src/components/network/bootstrap-input.tsx` adds a switch.
  - The toggle sets `trust=true` on the `getNetworkStatus` request.

## Fixes

- Bootstrapped peers no longer appear with `trusted: false` and empty capabilities when the dashboard is set to trust them.
- Bootstrap multiaddrs are now persisted so the daemon reconnects on restart.

## Known Limitations

- Trust is opt-in; the default v0.4.5 connect-only behavior is unchanged.
- A custom `?listen=...` still forces the CLI fallback because the daemon cannot change its bound listeners at runtime.
- Untrusting or deleting a saved peer from the UI is not yet supported; use `rhizome network untrust <peer-id>` and edit `mesh.bootstrap_peers` manually.

## Build

No CGO on core builds. Use:

```powershell
$env:CGO_ENABLED='0'
go build -tags goolm,stdjson ./...
go test -tags goolm,stdjson ./...
```

For the frontend:

```bash
cd web/frontend
pnpm install
pnpm build:backend
```

# v0.6.1 — Mesh operations follow-through

This release hardens the v0.6.0 mesh task surface for real-world operation.

## Highlights

- **Persistent task store.** The daemon persists owned remote tasks to
  `<RHIZOME_HOME>/mesh-tasks.jsonl`. If the daemon restarts while tasks are
  still running, those tasks are marked `error: daemon restarted` on the next
  startup so remote callers get a terminal state instead of a silently dropped
  task. Storage is atomic (temp file + rename) and coalesces rapid mutations.

- **Live task events.** The daemon exposes `GET /network/tasks/events` as an
  authenticated Server-Sent Event stream. The launcher proxies it at
  `GET /api/network/tasks/events?peer=<id>`. The Network page Remote Tasks
  panel now opens this stream, updates task status as events arrive, and shows
  toast notifications when a task reaches `done`, `error`, or `cancelled`.

- **Mesh task persistence API additions:**
  - `pkg/rhizome/mesh.TaskStore` gains `Load`, `save`, `SetPath`, and
    `NewTaskStoreWithPath`.
  - `pkg/rhizome/mesh.Mesh` gains `SetTaskStorePath` and `TaskEvents`.
  - `cmd/rhizome/internal/daemon` enables the store at
    `<home>/mesh-tasks.jsonl` when mesh is enabled.

## Compatibility

No breaking changes. The SSE endpoint and persistence are additive. Existing
`/api/network/tasks` request/response shapes are unchanged.

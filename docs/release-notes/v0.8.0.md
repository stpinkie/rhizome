# Rhizome v0.8.0 Release Notes

## Sprint theme

Tracks 33–42: **Mesh/Swarm Depth** — secure autonomous multi-agent
coordination gets substantially more capable: file transfer, task
attachments, media, a real work queue, DAG orchestration, trust pairing,
skill distribution, a first-class Context7 MCP preset, and a native Go CDP
browser client.

---

## Track 33 — Mesh Blob Transfer (`/rhizome/blob/1.0.0`)

- `pkg/rhizome/blob` — content-addressed blob store + protocol:
  `blob://<peer-id>/<sha256>` refs, hash-verified fetch, metadata stat,
  size/TTL caps (`mesh.blob_enabled`, `mesh.blob_max_bytes`, `mesh.blob_ttl`).
- Signed, trusted-only, replay-protected, rate-limited — same envelope as the
  task protocols; audited with `mesh.blob.*` ops and `mesh.blob.put/get`
  events.

## Track 34 — Remote Task Attachments

- `agentrpc`/`agenttask` wire types carry `Media` refs; `network delegate`,
  `spawn`, `route`, `mesh route`, and `swarm offer` accept repeatable
  `--attach <path>` — files push over blob transfer and localize into the
  callee's media store; result artifacts return as blob refs.

## Track 35 — Attachment Deep Capability

- `tools.media.vision_mode` (`auto`/`tool`/`off`) attaches user-sent images
  inline when the model is vision-capable; `load_video` extracts ffmpeg
  keyframes (`tools.media.max_video_frames`, `tools.media.ffmpeg_path`);
  `transcribe_audio` runs on-demand ASR via the configured transcriber.
- Telegram inbound video arrives as thumbnail image + file; audio refs on
  remote tasks transcribe to `[voice: ...]` annotations.

## Track 36 — Swarm Queue Maturity

- Offer cancellation, retry with dead-letter, and capability-aware claims
  (offers may require agent/model/skills a claimant must advertise).
- `rhizome swarm offer --cancel`, dead-letter introspection, and
  `swarm.offer.*` lifecycle events.

## Track 37 — Orchestration v2

- `swarm run` goals decompose into DAG subtasks (`depends_on`); wave-based
  dispatch runs dependency-free tasks first and skips dependents of failures.
- Per-subtask lifecycle events (`swarm.run.start/end/subtask`), persisted run
  records in `~/.rhizome/swarm-runs.jsonl`, `swarm runs` / `swarm run-status`
  CLI, `GET /network/swarms/<id>/runs`, launcher proxy, and run inspection in
  the Network dashboard.

## Track 38 — Trust Pairing (`/rhizome/pair/1.0.0`)

- `rhizome network pair --create [--ttl]` mints a single-use, expiring,
  signed pairing bundle; `--accept <bundle>` verifies the signature/code and
  persists the peer into `mesh.trusted_peers` + `bootstrap_peers`.
- Daemon endpoints + launcher proxies + a web pairing panel; tests cover
  round-trip, single-use, expiry, bad signature, unknown code.

## Track 39 — Mesh Skill Distribution

- `pkg/skills/bundle.go` — skills pack into validated zip bundles (name +
  path-traversal checks, no symlink escapes) transferred over the blob
  protocol: `mesh.skill` protocol (`/rhizome/skill/1.0.0`) with an opt-in
  `mesh.skill_share` allowlist (default deny-all).
- `mesh skill list <peer>` / `mesh skill pull <peer> <name>` (mirrored under
  `rhizome network skill`); pulled bundles are guard-scanned (`pkg/guard`)
  for prompt-injection, installed under `~/.rhizome/skills/`, and stamped
  with `.skill-origin.json` (`origin_kind: "mesh"`, `mesh:<peer-id>`) — the
  web skills page shows a Mesh badge.
- Daemon `GET /network/skills?peer=<id>` + `POST /network/skills/pull`;
  `mesh.skill.pull/push` events + audit.

## Track 40 — Context7 MCP Preset

- `tools.mcp.presets.context7` — `{enabled, api_key}` expands to the hosted
  Context7 server (`https://mcp.context7.com/mcp`, `CONTEXT7_API_KEY`
  header). The key is a `SecureString` (never reprinted; `config.security.yml`
  / `file://` / `enc://` supported, `CONTEXT7_API_KEY` env fallback).
- `MCPConfig.EffectiveServers()` merges presets into `servers` (explicit
  entries win); `rhizome mcp preset context7 --key … --enable`; presets card
  on the web Tools page (`GET/PUT /api/tools/mcp-presets`).

## Track 41 — Native Go CDP Client

- `pkg/browser/cdp` — a built-in Chrome DevTools Protocol client
  (gorilla WebSocket): `Target`/`Page`/`Runtime`/`DOM`/`Input` domains,
  named tab sessions, snapshot refs (`@eN`), click/fill/screenshot/eval/wait.
- New `rhizome-cdp` backend (kind `native-cdp`) — drives any CDP endpoint
  with **no Node.js/agent-browser**: `endpoint_url` takes `ws(s)://` or an
  `http(s)://` debug base, and `api_key` becomes an `Authorization: Bearer`
  WebSocket handshake header for authenticated endpoints like Cloudflare
  Browser Rendering connect.

## Compatibility

- All wire protocols are additive new libp2p protocols
  (`/rhizome/blob/1.0.0`, `/rhizome/pair/1.0.0`, `/rhizome/skill/1.0.0`) —
  older peers simply don't speak them.
- `mesh.skill_share` defaults to deny-all: no skill content leaves a node
  unless explicitly allowed.
- `tools.mcp.presets` and the `rhizome-cdp` backend are opt-in; existing
  `mcp.servers` and browser backend configs are unchanged.

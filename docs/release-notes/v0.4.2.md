# Rhizome v0.4.2 Release Notes

**Focus:** Web backend network API — live mesh and DHT status for the launcher dashboard.

## New Features

- **Web backend network endpoints**:
  - `GET /api/network/peers` returns connected peers, addresses, trust status, and advertised capabilities.
  - `GET /api/network/dht` returns the live DHT status snapshot.
  - Both endpoints are authenticated behind the launcher dashboard middleware.
  - Both endpoints accept `bootstrap`, `timeout`, and `listen` query parameters and always return JSON.
- **Endpoint implementation**:
  - The web backend runs `rhizome network status --peers --json` / `--dht --json` as a subprocess.
  - The launcher passes `RHIZOME_HOME` and `RHIZOME_CONFIG` to the subprocess automatically.
  - A 5-second in-memory cache prevents multiple overlapping temporary node spawns.
- **CLI reuse**: endpoints mirror the existing `rhizome network status --peers` and `rhizome network status --dht` output, so the dashboard and CLI stay consistent.

## Fixes

- No user-facing fixes in this release.

## Known Limitations

- These endpoints spawn a temporary libp2p node for each request (cached for 5 seconds). Heavy dashboard polling can generate node churn.
- A valid node identity is required. Call `rhizome network onboard` first if the endpoints return "no identity found".
- In-process P2P status (without a subprocess) is not yet exposed through the web backend.

## Build

No CGO on core builds. Use:

```powershell
$env:CGO_ENABLED='0'
go build -tags goolm,stdjson ./...
go test -tags goolm,stdjson ./...
```

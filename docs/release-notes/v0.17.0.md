# Rhizome v0.17.0 Release Notes

## Sprint theme

**Paired Settlement** — the trusted tier of the economy story. Two
operators who already pair their meshes can now bill each other for
remote work on a bilateral mutual-credit ledger: `mesh.economy` price
sheets meter successful billed tasks, `bill_peers` scopes who may be
charged, and accrued balances close out through a signed settle
handshake — off-band (`ledger`) or on-chain (`web3` two-phase through
the pending-approval queue). Meters the internal task protocols only;
paid sessions between untrusted operators stay on the `rhizome-market`
escrow path.

- **Manifest-negotiated billing** — `Capability.Economy` advertises
  seller terms; `econ`/`charge` wire fields appear iff both sides run
  economy builds. Unnegotiated calls stay byte-identical.
- **Event-sourced ledger** — `economy-ledger.jsonl` folds
  accrued → settled/disputed/written_off per bilateral pair, deduped
  and restart-safe.
- **Signed settle handshake** — `/rhizome/econ/1.0.0` converges both
  ledgers under a shared `settle_id`; forged or divergent offers reject
  with `ledger_query` reconciliation.
- **Web3 close-out** — `awaiting_tx` → verified confirmed receipt,
  journaled crash-safe so a restart never double-pays.
- **Cost-aware dispatch** — `--max-cost` spend caps, `est_cost`
  ranking, and swarm `max_price`/`quote` claim filtering.
- **Observability + reputation** — `econ_*` peer-score outcomes,
  threshold/grace-period overdue pressure, `GET /network/economy`,
  and a Network-page Economy panel.

Design doc: `docs/design/v0.17.0-sprint.md` (seed:
`docs/design/mesh-economy-module.md` appendix). Operator guides:
`docs/guides/economy.md`, `docs/operations/economy-reconcile.md`.

### `mesh.economy` config + `Capability.Economy` advert (Track 138, PR #93)

- `MeshConfig.Economy`: `enabled`, `unit`, `price_sheet{per_task,
  per_1k_prompt_tokens, per_1k_completion_tokens, per_second,
  min_charge}`, `accept_units`, `bill_peers`, `max_cost_per_{task,day}`,
  `settle_threshold`, `settle_backend` (`ledger`|`web3`),
  `payout{chain_id,address,asset}`, `settle_signer`, `settle_from` —
  strict-loader + validated, fully inert unless `enabled`.
- The signed capability's emit-when-set `economy` field and the pairing
  bundle's `economy`/`econ_sig` block advertise **seller terms only**
  (`unit`, `price_sheet`, `accepts`, `payout`, `settle_backends`) —
  `bill_peers`/cost caps/settle policy never leave config. Peers'
  adverts journal to `peer-adverts.json`; pre-economy joiners still
  verify the legacy pair `sig`.

### Charge negotiation + signed charge fields (Track 139, PR #94)

- Callers negotiate `econ{accept,max_charge,unit}` on signed
  `agentrpc`/`agenttask` requests — emitted only when the peer's stored
  manifest advertises `economy` and local economy is on, so
  unnegotiated requests are byte-identical to pre-sprint encodings.
- The callee refuses `bill_peers` callers that omit terms (`econ:`) or
  cap below `min_charge` (`price_floor:`) — pre-execution rejections
  that fail over cleanly. A successful billed run returns
  `charge{unit,amount,usage,sheet_digest,truncated}`; the caller
  verifies digest + recompute bound, violations land
  `econ:charge_mismatch` + a recorded failure.
- `economy`-advertising manifests fail verification on pre-v0.17.0
  builds (fixture-pinned) — no silent downgrade.

### Bilateral ledger store (Track 140, PR #95)

- `pkg/rhizome/econ`'s `Ledger` appends to
  `<RHIZOME_HOME>/economy-ledger.jsonl` (10 MB × 3 rotation, atomic
  lines; latest line per `entry_id` is its state).
- Callee books `receivable` at charge emit; caller books `payable`
  after verification; dedupe on `(direction|peer|task|corr)` makes
  resubmits and result re-fetches idempotent.
- Lifecycle: accrued → settled | disputed; disputed → accrued
  (`--credit`) | written_off (`--drop`); written entries never settle.
  `Balance`/`CommittedSince` feed the 24 h `max_cost_per_day` window.

### Operator verbs + gateway economy API (Track 141, PR #96)

- `rhizome mesh economy` / `rhizome network economy`:
  `balance [peer]`, `ledger --peer/--since/--state/--json`,
  `invoice <peer>` (emits the signed `SettleOffer` doc — dry-run),
  `settle <peer>` (`--unit`, `--mark-only`, `--backend`),
  `dispute <task-id>`, `resolve <task-id> --credit|--drop`.
- Reads stay daemonless (`econ.ReadEntries`); mutations prefer
  `POST /network/economy/{dispute,resolve,settle}` and fall back to
  direct ledger writes — the ledger resyncs external appends.

### Settle handshake `/rhizome/econ/1.0.0` (Track 142, PR #98)

- Signed-envelope request/response on the shared `serveSignedStream`
  helper: `settle_offer` carries the signed `SettleOffer` (work refs,
  canonical-decimal total, cutoff, nonce, ts); answers
  `settle_ack{accepted,settle_id}` or `settle_reject{reason}`.
- The payee verifies issuer, self-binding, signature, freshness, then
  `econ.MatchReceivables` requires every offered ref to hit exactly one
  accrued receivable for the issuer/unit with matching sum — divergence
  answers `settle_reject` + `econ:diverged` audit on both sides.
- On ack both ledgers transition the covered rows to `settled` under
  `settle_id = sha256(signed offer)` with `settle_tx=econ-handshake`.
  `ledger_query{unit,since}` → `ledger_view{entries_digest,balance}` is
  the read-only reconcile view.

### Web3 close-out backend (Track 143, PR #99)

- `settle_backend=web3` turns the handshake into a real payment in two
  phases on the same protocol: phase 1 adds `backend:"web3"` + a signed
  `payment{chain_id,address,asset,from}` commitment from the payee's
  advertised `payout`; the payee matches receivables and acks
  `awaiting_tx`.
- The payer transfers through the web3 machinery —
  `settle_signer=approval` queues a human-gated `web3-pending.json`
  entry; `settle_signer=wallet` signs inline from `settle_from`.
  `<RHIZOME_HOME>/economy-settle-inflight.json` journals the state
  machine *before* each side effect; a mesh watcher re-drives live
  records and a crash resume re-broadcasts the same raw — never
  double-pays.
- Phase 2 re-sends the offer + `tx_hash`; the payee verifies the
  confirmed receipt (chain id, sender == committed `payment.from`,
  destination, exact base-unit amount, successful receipt) before both
  ledgers settle under `settle_tx=<tx hash>`. `web3`+`mark-only` is a
  400.

### Cost-aware dispatch + `--max-cost` (Track 144, PR #100)

- `RemoteCall.MaxCost`/`FanoutRequest.MaxCost` carry an optional
  per-call spend cap; the wire cap resolves `min(call max,
  max_cost_per_task)` into `econ.max_charge`.
- Candidates whose advertised `min_charge` exceeds the cap are filtered
  pre-send; a ≤256-point proportional `est_cost` bonus reorders only
  billed candidates — unpriced peers rank as cost zero, never
  deprioritized.
- `--max-cost` lands on `route`/`scatter`/`delegate`/`spawn`/
  `task submit`, `max_cost` on the `delegate`/`spawn` agent tools and
  `POST /network/tasks` (400 on malformed); `price_floor:`/`econ:`
  rejections fail over without burning same-peer retries.

### Swarm price surface (Track 145, PR #101)

- `Offer.MaxPrice` (`swarm offer --max-price`, decomposer subtask
  `max_price`, gateway `POST /network/swarms/<id>/offers`) is the
  offerer's spend cap.
- Claims carry `quote` — the claimant's advertised-sheet estimate
  (`per_task` + prompt-token task-size hint, floored at `min_charge`;
  `"0"` when the offerer isn't on `bill_peers`, absent when the economy
  is off or the member runs an old build).
- `filterClaimsByPrice` drops `quote > max_price` before the
  (score, load) pick; all-over-cap offers expire with reason
  `max_price` + the filtered count. Unpriced/unparseable quotes stay
  eligible — additive `omitempty` fields.

### Economy observability + reputation (Track 146, PR #102)

- In-core `econ_charge`/`econ_settle`/`econ_dispute` op counters +
  bounded `Outcomes` refs (session ids + sha256 `value_hash`
  commitments — never raw amounts): verified/failed charges, settle
  ack/reject/divergence on both handshake sides, web3 phase outcomes,
  dispute pending/terminal, mark-settled attest, the overdue penalty.
- `econ.PeerSummary` (charges issued/received, settled/disputed/
  written_off counts, per-unit balances, `over_threshold`/`overdue`
  flags) rides `PeerScoreView.econ` into `mesh peer` and anchors
  `GET /network/economy` — the snapshot adds a recent-charge tail +
  live in-flight web3 records.
- `settle_grace_period` (validated, requires `settle_threshold`) backs
  the overdue sweep: `mesh.econ.settle_due` fires edge-triggered on a
  crossing payable; an over-threshold receivable past grace emits
  `mesh.econ.overdue` + one `econ_settle` failure per debt epoch
  (deduped on the contributing entry set, restart-safe).
- The three missing `mesh.econ.*` kinds join `knownKinds`; econ audits
  carry unit/amount/entry_ids. `economy balance` prints a
  settle-due hint; launcher `GET /api/network/economy` proxies or
  derives daemonless via the shared `econ` helpers; the Network page
  gains an Economy panel + peer-detail econ rows.

## Upgrade notes

- **No config changes required.** The economy is fully inert unless
  `mesh.economy.enabled` is set — no wire fields, adverts, or ledger
  writes otherwise.
- New additive config: `mesh.economy.*` (see
  `config/config.example.json`); `settle_grace_period` is a duration
  string (`"72h"`), validated non-negative and requiring
  `settle_threshold`.
- One new protocol id: `/rhizome/econ/1.0.0`. No new Go dependencies.
- `economy-ledger.jsonl` and `economy-settle-inflight.json` appear
  under `~/.rhizome/` when the economy runs — bounded/rotated, no
  operator maintenance.
- Wire compatibility: negotiated `econ`/`charge`/`quote`/`max_price`
  fields are additive `omitempty` — mixed-fleet calls with pre-v0.17.0
  peers behave exactly as before; an `economy`-advertising manifest
  fails verification on old builds rather than downgrading silently.

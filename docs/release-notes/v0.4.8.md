# Rhizome v0.4.8 — Provider Protocol Refactor

## Highlights

- The LLM provider layer is now **protocol-based**, not vendor-based.
- All OpenAI-compatible providers are constructed from catalog metadata, eliminating the giant per-provider `switch` in the factory.
- First-class support for **Ollama**, **vLLM**, **LM Studio**, and **LiteLLM** local servers, with correct default API bases and optional API keys.
- The legacy `pkg/providers/httpapi` and `pkg/providers/anthropic` SDK packages have been removed.
- OAuth Claude now uses the native Anthropic Messages protocol implementation.

## Backend

### Provider catalog

- `ModelProviderOption` now carries construction metadata:
  - `ProtocolFamily` — `openai-compatible`, `anthropic-messages`, `gemini`, `azure`, `bedrock`, `oauth`, `cli`, `asr`, etc.
  - `StripModelPrefix` — removes the leading `provider/` segment from model names.
  - `ExtraBodyDefaults` — per-protocol default body fields (e.g. `minimax` reasoning split).
  - `DefaultMaxTokensField` — reserved for per-protocol max-token field overrides.
- All OpenAI-compatible providers are marked `ProtocolFamily: openai-compatible` with `StripModelPrefix: true`.
- `openrouter` keeps its model prefix intact because OpenRouter model IDs embed the upstream provider.
- Local protocols (`ollama`, `vllm`, `lmstudio`, `litellm`, `gpt4free`, `github-copilot`, `claude-cli`, `codex-cli`) set `Local: true` and `EmptyAPIKeyAllowed: true`.

### Factory

- `pkg/providers/factory_provider.go` now dispatches on `ProtocolFamily` from the catalog instead of a giant `switch` over provider IDs.
- OpenAI-compatible providers are created by a single `createOpenAICompatibleProvider` helper.
- Extra body defaults are merged with user-supplied `extra_body` (user values win).
- Anthropic Messages, Gemini, Azure, Bedrock, CLI, and OAuth providers keep small explicit constructors.

### Package cleanup

- Removed `pkg/providers/httpapi` and its `HTTPProvider` facade.
  - Moved `GeminiProvider` to a new `pkg/providers/gemini` package.
  - OpenAI-compatible construction now uses `pkg/providers/openai_compat` directly.
- Removed `pkg/providers/anthropic` (Anthropic SDK wrapper).
  - OAuth Claude now wraps `pkg/providers/anthropic_messages`.
  - `anthropicmessages.Provider` gained token-source support (`NewProviderWithTokenSource`) for OAuth token refresh.
  - `anthropicmessages.Provider` also strips the leading `provider/` segment when configured to.
- `go.mod` no longer depends on `github.com/anthropics/anthropic-sdk-go`.

### Model prefix stripping

- `openai_compat.Provider` gained `WithStripModelPrefix` and a per-provider `stripModelPrefix` flag.
- The hardcoded `stripModelPrefixProviders` map has been removed; prefix stripping now checks whether the model's leading segment matches the configured provider's own ID (`WithProviderName`).
- `openrouter` endpoints are automatically excluded from prefix stripping.

### Config migration

- Legacy `providers.anthropic` and `providers.claude` sections now migrate to `anthropic-messages` with the model `claude-sonnet-4.6`.
- Legacy local provider sections (`ollama`, `vllm`, `litellm`) continue to migrate with their protocol-prefixed defaults and optional API keys.

## Frontend

- Provider combobox already showed a "local" badge for local providers; it is now backed by catalog `local` flags for the new first-class local protocols.
- Add/edit model sheets now auto-fill the default `api_base` when a provider is selected and the field is empty.
- The API key field is marked as optional and shows a hint for providers with `empty_api_key_allowed`.
- Model validation already allowed any catalog provider, so `ollama/...`, `vllm/...`, etc. are accepted.

## Web backend

- `POST /api/models/fetch` already derived `api_base` from the catalog and allowed empty API keys for local providers; it now works for the new first-class local protocols out of the box.
- `validateIncomingModelConfig` accepts any provider in the catalog, including the new local protocols.

## Tests

- Updated `pkg/providers/factory_test.go` and `pkg/providers/factory_provider_test.go` to assert `*openai_compat.Provider` and `*gemini.GeminiProvider` instead of the removed `HTTPProvider` types.
- Updated `pkg/providers/openai_compat/provider_test.go` to use the `WithStripModelPrefix` option.
- Rewrote `pkg/providers/oauth/claude_provider_test.go` to test the `anthropic_messages` native implementation.
- `pkg/providers` and `pkg/config` test suites pass.

## Docs

- Updated `README.md`, `docs/guides/providers.md`, and `docs/migration/model-list-migration.md` to describe the new protocol-based provider model and first-class local server support.
- Updated `AGENTS.md` with build/test tag notes and provider architecture guidance.
- Updated `ROADMAP.md` to mark the Provider Architecture Upgrade as completed for v0.4.8.

## Upgrade notes

- If you previously used the `anthropic` protocol (OpenAI-compatible wrapper) for real Anthropic endpoints, switch to `anthropic-messages` or edit your model to use `anthropic-messages/claude-sonnet-4.6`.
- Legacy configs are migrated automatically; no manual action is required.
- For local providers, leave the API key blank and the default `api_base` will be filled in automatically.

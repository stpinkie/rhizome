# Rhizome v0.13.0 Release Notes

## Sprint theme

**Agent interoperability.** The ACP surface goes both ways — Rhizome as a
richer server for editors, and as a client driving external ACP agents
bound to `agents.list[].acp` — plus the seams the Open Agent Work Market
needs later: remote-task usage metering, signed curated skill index,
module release signatures, AEAD key stores, and an MCP *server* surface.

- **ACP spine** — session modes, per-session model config options,
  external-agent `authMethods`, session depth + media + mode forwarding.
- **Mesh metering** — negotiated `want_usage`/`usage_report` returns a
  summed token/call report on remote tasks.
- **Supply chain** — signed curated skill index (`rhizome` registry) and
  catalog schema v3 upstream release signatures.
- **`rhizome mcp serve`** — expose allowlisted local tools to MCP clients
  over stdio.
- **enc2 key stores** — `node.json` and `web3/keys.json` migrate to
  XChaCha20-Poly1305 via per-entry `cipher` markers.

Design doc: `docs/design/v0.13.0-sprint.md`. The mesh-economy concept is
replaced by the **Open Agent Work Market** — `docs/design/v0.14.0-sprint.md`.

## Features

### ACP session modes (Track 85)

- `rhizome acp` advertises session modes (`ask`, `auto`, `read-only`) and
  answers `session/set_mode`: switching mode changes the live tool
  permission posture, clears cached `allow_always`/`reject_always`
  decisions so approvals can't leak across modes, and persists in
  `acp-sessions.json` so the mode survives `session/load`.
- `acp.server.permission_policy=deny` caps the advertised set at
  `read-only`; `prompt`/`allow` unlock the full set.

### ACP config options + per-session model (Track 86)

- Sessions expose a `category:model` select via
  `session/set_config_option`: every enabled `model_list` entry plus an
  **inherit** entry. Picking a model sets a *per-session* override — a
  second session keeps the agent default; the override persists in
  `acp-sessions.json` and is restored by `session/load` (a model removed
  from `model_list` falls back to inherit).

### External-agent `authMethods` (Track 87)

- `agents.list[].acp` bindings honor the agent's advertised
  `authMethods`: `env_var` is satisfied from the binding's `env` map
  (named-missing produces a clear error), `terminal` is gated by
  `acp.client.terminal_policy`, and `agent`-type flows run under the
  client permission policy — allowed or refused clearly.

### External-agent session depth (Track 88)

- `agents.list[].acp.session_mode`: `oneshot` (default) opens a fresh
  session per delegation; `persistent` reuses one session per agent id so
  the remote agent keeps context.
- `agents.list[].acp.mode` requests `session/set_mode` after creation
  when the agent advertised that mode id (unadvertised ids warn and
  continue — agents own their mode vocabularies).
- `media://` attachments (e.g. mesh task attachments) are sent as ACP
  image blocks when the agent advertises `promptCapabilities.image`;
  image-in-capable agents get a text fallback.
- Client-declared `mcpServers` passthrough is honored for external agents
  where supported.

### `rhizome mcp serve` (Track 89)

- New `rhizome mcp serve` command: a daemonless MCP *server* over stdio
  exposing the operator's local tool registry to any MCP client.
  Configured by `tools.mcp_server = {enabled, allow}` — disabled by
  default, empty `allow` is deny-all, and there is no allow-all mode.
- Agent-loop tools (`delegate`, `acp_run`, `spawn`, swarm verbs,
  `message`, `send_*`) are never in the serve registry. stdout is kept
  protocol-pure (same stderr-drain rule as `rhizome acp`).

### Signed curated skills index (Track 90)

- New first-party **`rhizome` skill registry** (enabled by default):
  `index.json` + `index.json.sig` fetched from release assets,
  Ed25519-verified byte-exact against the baked-in release key — the same
  trust root as the module catalog (`pkg/sigverify` now owns it).
- Trust posture: unsigned/malformed/bad-signature indexes are refused
  outright; verified indexes cache ~1 h under
  `<RHIZOME_HOME>/skills-index-cache/`; a stale verified cache is served
  only on fetch failure (`skill.index.stale` event) — trust/schema
  failures never fall back.
- Installs delegate to the GitHub installer (`source.github` entries,
  optional sha256 archive pinning) and record `origin_kind: "curated"`
  across CLI/agent/web paths — teal Curated badge in the Hub.
- `rhizome skills index [--out f] [--sign-with-env VAR]` emits the
  canonical signed index from the embedded
  `pkg/skills/curated_index.json` (9 first-party skills) — daemonless,
  mirrors `rhizome module catalog`. Releases sign/upload the assets under
  the existing `MODULE_CATALOG_SIGNING_KEY` gate; see
  `docs/operations/skill-index-signing.md`.

### CI/DevEx automation (Track 91)

- PR labeler workflow + workflow run concurrency groups — cheaper,
  clearer CI signal.

### Remote-task usage metering (Track 94)

- Peers advertising `allows.usage_report` in their capability manifest
  get `want_usage` on delegate/spawn/task-submit and return a summed
  `usage` report (`llm_calls`, `prompt_tokens`, `completion_tokens`,
  `total_tokens`, `duration_ms`) on the response/result.
- Wire-compatible: unnegotiated calls exchange exactly today's bytes —
  mixed-version meshes are unaffected; external ACP agents report no
  usage.
- Surfaces: `delegate`, `route`, `scatter`, and `task result` print a
  `Usage:` line; usage lands in `mesh-tasks.jsonl`, `mesh-audit.jsonl`,
  and `mesh peer <id>` recent-task detail.

### Module trust tail (Track 95)

- Catalog schema **v3**: `ReleasePin.signature` declares an optional
  upstream detached signature (`cosign-blob`, `minisign`, or `gpg` kind +
  URL + public key). When declared, install verifies the signature after
  the digest check and **fails closed**; catalogs declaring signatures
  carry a `min_required_catalog_version` floor so binaries too old to
  verify refuse rather than silently skip.
- Verified via `aead.dev/minisign` and `ProtonMail/go-crypto` (both were
  already in the module graph — no new dependency trees).
- Today no upstream tenant publishes signatures — this ships the
  mechanism plus signed fixtures; the digest remains the mandatory floor.
- `docs/design/llama-cpp-module.md` lands: the authoring pattern for a
  local-inference companion module (extraction shape, weights trust,
  ondemand lifecycle, GPU fields).

### enc2 key-store migrations (Track 96)

- `node.json` (mesh identity) and `web3/keys.json` (wallet) join the
  `enc2://` world: per-entry `cipher` markers
  (`"aes-256-gcm"` legacy / `"xchacha20poly1305"` current), legacy
  entries decrypt transparently, new writes emit the new cipher —
  stores migrate entry-by-entry on save. Keyring/scrypt/SSH-key sources
  unchanged. See `docs/security/credential_encryption.md`.

## Upgrade notes

- **Key stores are a one-way door.** Once `node.json` or
  `web3/keys.json` entries re-save under `xchacha20poly1305`, pre-v0.13.0
  binaries can't open them — don't downgrade after first run (the files
  aren't corrupted; upgrade again to regain access).
- **`mcp serve` is off and deny-all by default** — nothing is exposed
  until `tools.mcp_server.enabled` + a non-empty `allow` list are set.
- **The `rhizome` skill registry is enabled by default.** Until a release
  ships `index.json{,.sig}` assets it warns on fetch and is inert;
  disable via `tools.skills.registries.rhizome.enabled=false` if
  unwanted.
- **ACP mode/model choices persist** in `acp-sessions.json` — a session
  loaded later resumes its mode and model override.

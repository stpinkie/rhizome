# Rhizome v0.5.0 — Mesh Maturity: NAT Traversal, Async Tasks, Security, Sync Robustness

## Highlights

- **NAT traversal**: nodes behind home NATs can now connect automatically via AutoNAT reachability detection, hole punching (DCUtR), and circuit relay v2 — including self-organizing relay behavior where publicly reachable nodes volunteer as relays.
- **Asynchronous remote tasks**: remote agent work is now a first-class task with an id, status, result retrieval, cancellation, and a CLI — no more holding a libp2p stream open for a whole agent turn.
- **Mesh security hardening**: all mesh requests carry signed nonces and timestamps (replay protection), capability manifests are signed, and remote execution gains per-peer ACLs, rate limits, and a persistent audit trail.
- **Sync robustness**: workspace Git sync now honors `commit_interval`, protects uncommitted local work before merging, applies per-pull timeouts with retry backoff, and re-announces on reconnect.
- **Honest remote dispatch**: `TargetAgentID`, `Model`, and `Tools` in remote requests are now actually honored by the callee instead of being silently ignored.

## Backend

### NAT traversal and reachability (T12)

- `pkg/rhizome/network` enables AutoNATv2, hole punching, circuit relay v2 client support, and AutoRelay reservations out of the box (`mesh.nat_traversal`, on by default).
- Publicly reachable nodes run the relay service (`mesh.relay_service`, on by default) and the AutoNAT dial-back service (`mesh.nat_service`, on by default), so the mesh self-organizes: reachable peers relay for unreachable ones.
- New config: `mesh.static_relays` (always-reserve relay multiaddrs), `mesh.force_reachability` (`public`/`private`), `mesh.public_addrs` (extra advertised addresses).
- Reachability, advertised addrs, and relayed `/p2p-circuit` addrs are surfaced in `Mesh.NetworkStatus`, `rhizome network status`, and the Network dashboard.
- Reconnect and DHT dialing now treat relayed (`Limited`) connections as usable via `IsConnectednessUp`.

### Async remote tasks (T13)

- New libp2p protocol `/rhizome/agent-task/1.0.0` (`pkg/rhizome/agenttask`) with ops: `submit`, `status`, `result` (long-polling), `cancel`, `list`.
- Callee-side bounded `TaskStore` with owner isolation, idempotent submit by `correlation_id`, cancellation propagation into the running context, and expiry/cleanup.
- Caller-side Mesh APIs: `SubmitRemoteTask`, `RemoteTaskStatus`, `RemoteTaskResult`, `CancelRemoteTask`, `ListRemoteTasks`; `CallRemote(Async: true)` submits + long-polls and falls back to the synchronous protocol for older peers.
- `RemoteSpawner` is genuinely async: it forwards the requested model and tool set along with the target agent.
- `rhizome network task` / `rhizome mesh task` CLI: `submit`, `status`, `result`, `cancel`, `list`.
- Runtime events: `mesh.task.submit` and `mesh.task.update` on both caller and callee.
- The gateway now dispatches remote requests to the requested registry agent with model override and tool allowlisting (`pkg/agent/remote.go`), and capability `Agents` reflect the live agent registry.

### Mesh security (T14)

- `agentrpc.Request` and `agenttask.Request` carry `Nonce` + `Timestamp`, both covered by the request signature; responses echo the nonce so they are bound to the request they answer.
- Callees reject stale/future timestamps beyond `mesh.request_max_skew` (default `2m`) and reject reused nonces via a bounded per-peer nonce cache.
- Task-protocol requests are strictly replay-protected, and the `/rhizome/agent/1.0.0` protocol now requires the signed nonce/timestamp on every request — requests without them are rejected and audited.
- Capability manifests are signed by the node key; incoming manifests are verified against the sender's public key, must claim the sender's peer id, and must be fresh (10m). Unsigned manifests are rejected by default (`mesh.require_signed_caps`, default `true`); a `mesh.cap.unsigned` event is emitted either way, and setting `require_signed_caps: false` restores acceptance for trusted peers.
- Per-peer ACL via `mesh.acl`: `[{peer_id, allow_delegate, allow_spawn, agents, rate_limit}]`; absent entries fall back to `allow_remote_delegate`/`allow_remote_spawn`.
- Per-peer rate limiting (`mesh.rate_limit_per_peer`, default 30/min, ACL-overridable) plus a global inbound cap (`mesh.rate_limit_global`, default 300/min).
- Append-only audit trail at `~/.rhizome/mesh-audit.jsonl` (10 MB × 3 rotation, disable via `mesh.audit_log: false`) plus a `mesh.remote.audit` runtime event for every remote operation.
- The `agentrpc` idempotency result cache is bounded at 1024 entries in addition to its TTL, and is now keyed by the authenticated peer id so a cached response can never be served to a different peer.
- Submit retries share one correlation id, so a resubmission after a lost response is deduplicated by the callee's task store instead of spawning a duplicate task.
- Rejections carry machine-readable error prefixes: `forbidden:` for ACL denials and `rate_limited:` for rate limiting.

### Sync robustness (T15)

- `commit_interval` is now wired into a commit loop — periodic commits actually happen.
- Merging protects uncommitted local work: local changes are committed before applying remote packfiles, and sync fails safely instead of hard-resetting over local edits.
- Pulls and packfile fetches have per-operation timeouts with exponential backoff + jitter; concurrent pulls for the same peer share one in-flight fetch.
- On reconnect, each peer announces its head so offline-time changes are caught up.
- Sync status persists (`sync-status.json`) with last error, peer heads, workspace state, and conflict paths; `rhizome sync status` shows it all.

### Stream reliability fix

- Fixed a first-frame ACK bug in `ReliableConn`: the initial ACK watermark could make `waitForAck` return before any real ACK arrived, so the first data frame was never retransmitted on loss.
- `waitForAck` now wakes on incoming ACKs and aborts immediately when the connection shuts down, instead of busy-polling until the write timeout — so a peer closing after an error frame no longer masks the real send error with "reliable conn closed".
- NACK-triggered retransmits are now serialized with normal writes under the write mutex so a retransmit can never interleave bytes mid-frame.

## Tests

- New mesh security suite: replayed nonce, stale timestamp, missing nonce/timestamp rejection, ACL denials, rate limiting, capability spoofing/tampering, audit log.
- Task lifecycle suite: submit/status/result/cancel, ownership isolation, untrusted rejection, spawn-disabled rejection.
- New sync suites: transport round-trip/error/timeout, packfile handling, three-peer convergence, divergent-conflict convergence, reconnect catch-up, bidirectional sync.
- Stream fault-injection tests for loss/duplication/reorder.
- `scripts/integration-mesh.{sh,ps1}` now verifies bidirectional sync and post-reconnect catch-up.

## Compatibility

- `/rhizome/agent/1.0.0` is unchanged at the protocol level; new fields are additive — but callers must populate them: signed requests **without** `nonce`/`timestamp` are rejected (and audited) as of this release.
- Async calls to peers without `/rhizome/agent-task/1.0.0` fall back to the synchronous protocol.
- Signed capability manifests are enforced by default (`mesh.require_signed_caps: true`). This is the first tagged release carrying signed manifests, so no released peer emits unsigned ones; set `require_signed_caps: false` to accept them from trusted peers (a `mesh.cap.unsigned` event is emitted either way).
- Mesh callers on untracked pre-release builds that omit nonce/timestamp will be rejected — upgrade both sides together.

## Upgrade notes

- Nothing required; defaults are safe. To lock down remote execution, add `mesh.acl` rules and/or lower `mesh.rate_limit_per_peer`.
- If you run a public node, leave `relay_service` and `nat_service` enabled — they help NAT'd peers reach you.

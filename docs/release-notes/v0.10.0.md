# Rhizome v0.10.0 Release Notes

## Sprint theme

Extensibility and interoperability cycle: Rhizome grows sidecar modules,
speaks ACP in both directions, and gets the mesh observability +
resource-tier work needed to leave nodes running everywhere — secure,
autonomous, and cheap.

- **Companion modules** (`rhizome module`) extend the node without growing
  the base binary.
- **ACP** connects Rhizome to external agents and editor clients in both
  directions.
- **Mesh observability** exposes connections, scores, bandwidth, and a live
  activity feed end-to-end (daemon API → launcher → dashboard → CLI).
- **Worker-node tier** drops routing infrastructure for the smallest
  always-on footprint; the footprint is now measured, not guessed.
- **First Web3 tenant** — `nimbus-verified-proxy` brings verified Ethereum
  JSON-RPC as a companion module.

Design doc: `docs/design/v0.10.0-sprint.md`.

## Features

### Companion modules (Track 60) — `pkg/modules`, `rhizome module`

A catalog-driven sidecar system: modules install under
`~/.rhizome/modules/<id>/<version>/`, are verified against pinned release
digests, and run as supervised daemons, on-demand tools, or config-only
endpoint descriptors — generalizing the `pkg/browser` backend
install pattern.

- `rhizome module list|status|install|uninstall|enable|disable|
  start|stop|restart|logs|set|validate`; lifecycle commands proxy to the
  running daemon, everything else works offline.
- `modules.<id>.enabled` + `modules.<id>.fields` in `config.json`; secret
  fields (provider URLs with embedded keys, tokens) persist to
  `.security.yml` via `module set --secret` and are masked in logs/UI.
- Daemon API: `GET /modules`, `GET /modules/<id>`,
  `GET /modules/<id>/logs?tail=N`, `POST /modules/<id>` (`{"action": …}`),
  `PUT /modules/<id>/{fields,secrets}` — bearer auth, constant-time token
  compare. Launcher proxies under `/api/modules*` with a local fallback for
  reads/config/install when no daemon runs.
- Supervisor restarts daemon-kind modules with backoff; logs are bounded;
  `module-state.json` keeps status accurate across daemon restarts.
  `module.*` runtime events flow into the mesh activity feed.
- New dashboard **Modules** page (`/modules`).
- Guide: `docs/guides/modules.md`.

### Web3: `nimbus-verified-proxy` + `ethereum-rpc` (Track 65)

- `nimbus-verified-proxy` — verified Ethereum JSON-RPC via
  `status-im/nimbus-eth1`: a consensus light client that proves execution
  API responses against beacon-chain proofs (the untrusted EL endpoint and
  beacon API are both secrets). Pinned v0.4.1; linux amd64/arm64, windows
  amd64, macos arm64. JSON-RPC health probe (`eth_chainId`).
- `ethereum-rpc` — config-only sibling for pointing at a remote endpoint
  (any platform, zero binary).
- Catalog plumbing gained `SHA512` digests (upstream publishes sha512, not
  sha256), `OSAliases` for asset naming (`darwin`→`macos`), `.exe`
  resolution on Windows, and archive flattening for nested binaries.
- Scope guard: modules expose endpoints for user scripts/dapps only — no
  `web3_*` agent tools yet (Stage 2, `ROADMAP.md` §9).

### ACP server (Track 61) — `rhizome acp`

Rhizome now speaks [Agent Client Protocol](https://agentclientprotocol.com)
to editors (Zed, JetBrains IDEs, …) via `coder/acp-go-sdk` over
newline-delimited stdio JSON-RPC.

- `rhizome acp [--agent <id>]`: `initialize` → `session/new` → `session/prompt`
  with streamed `agent_message_chunk` updates, `tool_call`/`tool_call_update`
  lifecycle notifications, and `session/request_permission` bridging every
  tool call (`acp.server.permission_policy`: `prompt`|`allow`|`deny`,
  fail-closed on disconnect).
- Sessions map to `agent:<id>:acp:<uuid>` keys — normal session history,
  routing, and provider fallback apply. Streaming is force-enabled per
  process; non-streaming providers degrade to a single chunk.
- stdout is protocol-clean: console logging is disabled and the startup
  banner is suppressed in protocol mode; `RHIZOME_LOG_FILE` captures
  diagnostics.
- Binary-size delta ≈ +0.6%.

### ACP client (Track 62) — external agents as agent ids

`agents.list[].acp` binds an external ACP agent (`gemini --acp`,
`claude-code acp`, …) to a first-class Rhizome agent id:

- Routable like any local agent — `delegate`/`subagent`/`spawn` tools,
  `acp_run`, and trusted mesh peers can all dispatch into it (the mesh
  checker treats ACP-bound ids as local so they never route off-box).
- The external process spawns lazily, is reused across delegations, and is
  terminated on gateway shutdown; each delegation opens a fresh
  `session/new`.
- Client-bound requests are served defensively: `fs/*` goes through the
  workspace sandbox (64 KiB read cap; writes disabled under
  `allow-read-only`), `session/request_permission` answers via
  `acp.client.permission_policy` (default `deny`), `terminal/*` is refused,
  and `authMethods` agents are rejected — credentials go in `env`.
- Guide: `docs/guides/acp.md` (both directions).

### Mesh observability (Track 63)

`PeerStatus` now carries live detail: per-connection transport (`quic`,
`tcp`, `relay`), direction, stream count, opened-at; peerstore latency EWMA;
peer score (successes/failures/avg-latency/last-error → computed score);
last-seen; and per-peer + aggregate bandwidth from a libp2p
`BandwidthReporter` wired into the host.

- Daemon: `GET /network/activity?tail=N` and `GET /network/events` (SSE)
  join the extended `GET /network/status`; launcher proxies under
  `/api/network/*`.
- A bounded (200-entry) in-memory activity feed captures `mesh.*`/`swarm.*`
  runtime events; the durable trail stays `mesh-audit.jsonl`.
- CLI: `rhizome mesh activity [--tail N] [--json]`, `rhizome mesh peer
  <id> [--json]`, and richer `mesh status` rows.
- Dashboard: transport/relay badges, score+latency tooltips, a peer detail
  drawer (connections, bandwidth, capabilities, manifests, recent tasks),
  aggregate node bandwidth, and a live Activity panel (SSE with polling
  fallback).

### Worker-node tier + footprint measurement (Track 64)

- `mesh.role: "full"|"worker"` (default `full`). Workers join the mesh to
  serve work without running routing infrastructure: the role forces
  `dht_enabled`, `relay_service`, and `nat_service` off, wins over explicit
  config, and warns at startup on contradictions. Pair with
  `rhizome daemon --no-gateway` for the smallest always-on node — the
  gateway stays a separate flag since some workers still want the local
  HTTP API.
- `role` is signed into the capability manifest — **emitted only for
  `worker`** because the signature covers the re-marshaled manifest; an
  always-present field would fail verification on pre-v0.10.0 peers.
  Surfaces in `mesh status`/`mesh peer` output and dashboard badges.
- `scripts/measure-footprint.sh`: Linux/WSL2 harness — stripped build or
  `RHIZOME_BINARY` prebuilt; three profiles (one-shot CLI, worker daemon,
  full daemon); `/proc/<pid>/status` VmRSS sampling + cold-start timing;
  JSON out.
- `docs/architecture/footprint-audit.md` refreshed with v0.10.0
  measurements: **74.5 MB** stripped linux/amd64 binary, worker ≈ **50 MB**
  vs full ≈ **55 MB** steady RSS, full-daemon cold start ≈ 0.7–1.4 s to
  gateway-port. libp2p remains the dominant steady-state contributor.
- Seam kept open: role-aware `PickPeer`/coordinator preference is queued
  for a later track.

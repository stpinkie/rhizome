# Rhizome v0.9.0 Release Notes

## Sprint theme

Feature cycle after five stabilization releases: burn down the confirmed
inherited PicoClaw defects, complete the channel attachment matrix, ship
first-run onboarding (CLI + web), and add the first two multi-agent depth
features — swarm shared context and signed agent identity manifests.

This release is primarily a defect + platform release: every confirmed
upstream issue that still reproduces in Rhizome code is fixed, and the mesh
now carries a verifiable per-agent identity layer.

---

## Defects fixed (inherited from upstream `sipeed/picoclaw`)

All seven issues below were traced into Rhizome source and confirmed present
before fixing. See `docs/project/upstream-issue-triage.md` for the full
provenance audit.

### Config (`pkg/config`)

- **`SaveConfig` no longer drops API keys after the first** (#3373). Multi-key
  expansion created `__key_i` virtual model entries that were filtered out on
  save, silently discarding every credential after the first on any
  load→save (including `onboard`). `collapseMultiKeyModels` now merges
  virtual keys back into the primary entry's `APIKeys`, preserving each
  `SecureString`'s raw `enc://`/`file://` form; orphan virtuals demote to real
  entries so no credential is ever dropped.
- **`sensitiveCache` lazy-init race fixed** (#3374). Two goroutines could race
  the nil-check in `initSensitiveCache`, leaving a nil `*strings.Replacer`
  that panicked `FilterSensitiveData`. The pointer swap is now serialized by
  a package-level mutex (`Config` itself cannot host a `sync.Once` — it is
  value-copied in `normalizedConfigForSave`).
- **Channel flat-key compatibility** (#3355). `channel_list.<type>.app_id`
  and other flat keys no longer fail strict unknown-field validation or get
  silently dropped: `Channel.UnmarshalJSON` folds non-base keys into
  `Settings`, and the diagnostics walker exempts channel nodes.

### Channels

- **Telegram tool-feedback animator bounded** (#3343). A failed turn could
  leave the animator editing forever (228k edits, hour-long rate limits
  observed upstream). The animator now aborts after consecutive errors,
  respects a `tool_feedback_max_duration` timeout, and self-detaches on exit.
- **QQ channel 401s fixed** (#3365). botgo v0.2.1 + resty ≥2.17 sent
  `Authorization: Bearer` where the QQ API requires `QQBot`. A
  `RegisterReqFilter` hook now rewrites the auth scheme on every request.
- **Web chat input lag** (#3350). Composer state (`input`, attachments, drag)
  moved from `ChatPage` into `ChatComposer` so keystrokes no longer
  re-render the whole message list; `AssistantMessage`/`UserMessage` are
  memoized.
- **Session history is archived before rewrite** (#3351). `SetHistory`/
  `Compact` used to physically overwrite the session `.jsonl`; rewrites now
  snapshot the original to `*.archive-N.jsonl` first, tracked in
  `SessionMeta`.
- **IRC long messages no longer truncated mid-character** (#3287). The shared
  splitter cuts at 400 *runes* but IRC enforces ~512 *bytes* per line — CJK
  and emoji text could be cut mid-message or mid-UTF-8. `Send` now splits
  each PRIVMSG line at ≤400 bytes on rune boundaries, preferring spaces.

## Features

### Attachment matrix (Track 55)

- `SendMedia` implemented for **whatsapp (bridge)**, **whatsapp_native**
  (whatsmeow upload + `waE2E`), **VK**, and **DingTalk** — outbound
  `media://` refs resolve through the media store to local paths, then to
  the channel API.
- Inbound media ingested into the media store **before** the empty-content
  early return on whatsapp_native, VK (photo/doc/voice), and DingTalk
  (`downloadCode` → `robot/messageFiles/download`), so media-only messages
  are no longer dropped.
- `docs/channels/media-matrix.md` documents per-channel in/out support.

### Onboarding (Track 56)

- **Interactive `rhizome onboard` wizard** (terminals only; `--non-interactive`
  /`--yes` unchanged): detects API-key env vars for 18 providers, detects a
  reachable local Ollama, lists catalog providers, supports custom
  OpenAI-compatible endpoints via the new `openai-compatible` preset, reads
  keys securely, fetches models where supported, probes connectivity without
  blocking save, and sets the configured model as default.
- **Web `/setup` first-run page** + `GET /api/setup/status` (`needs_setup` =
  no credentialed model or no default model). Provider → API key/base →
  model fetch → test → save + set default; skippable once per browser
  session; English and Chinese locales.

### Multi-agent depth (Tracks 57–58)

- **Swarm shared context (blackboard)** — two-tier shared state in the synced
  workspace: `notes.jsonl` (any member appends) + `context.md`
  (coordinator-curated). Notes propagate over signed swarm envelopes; the
  `swarm_context` tool, `rhizome swarm context|note` CLI, and daemon HTTP
  endpoints expose reads/writes; a context digest is injected into
  `RunGoal`; `swarm.context` config controls the feature.
- **Signed agent identity manifests** (`pkg/rhizome/agentmanifest`) —
  AIEOS-style per-agent identity documents (agent id, name, persona, models,
  skills, peer id, issued-at), signed with the node's Ed25519 identity and
  embedded in capability announcements — no new wire protocol. Model/skill
  fields honor `advertise_models`/`advertise_skills`; receivers verify each
  manifest after the outer capability signature check and drop forgeries.
  The gateway persists signed manifests to `<workspace>/agents/` so they
  sync to peers; status surfaces expose per-agent fingerprints.
  Manifests prove *who* issued an identity claim — execution authorization
  remains governed by trust + ACL.

### Provider polish (Track 59)

- **`session_header` model field** (#3369) — names an HTTP header that
  carries the turn's session key on every request, e.g.
  `"session_header": "x-opencode-session"` for OpenCode Go.
- **`openai-compatible` provider preset** (#3366) — named catalog entry for
  any OpenAI chat-completions endpoint; `api_base` required, `api_keys`
  optional.

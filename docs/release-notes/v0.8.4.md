# Rhizome v0.8.4 Release Notes

## Sprint theme

Tooling hardening for the small-VM validation path and the cross-compile
Makefile targets.

This patch release fixes the `build-core` / `build-all` target inversion,
reuses the Go build cache on large host mounts, removes cross-compile artifacts
when running on a 4 GB overlay, expands `build-core` to the full tier-one
cross-compile matrix, and clarifies how to run the small-VM validation on a host
with a large cache mount.

No product behavior or protocol changes.

---

## Tracks

### Fix `build-core` / `build-all` target inversion

- `make build-all` now builds the full 15-target desktop/server matrix
  (`linux/{amd64,386,arm,arm64,loong64,riscv64,mipsle}`, `darwin/{amd64,arm64}`,
  `windows/{amd64,386}`, `freebsd/amd64`, `openbsd/amd64`, `netbsd/{amd64,arm64}`).
- `make build-core` now only calls `scripts/build-core-targets.sh` and builds
  the 12 core targets, removing each binary from the overlay when the build
  directory is on the small root filesystem.
- Removed the redundant `freebsd`/`openbsd` extra step from the
  `cross-compile` CI job because `make build-all` now covers them.
- Removed the duplicate `linux-armv7` build line.

### Smart cache and build-output management

- Added `scripts/rhizome-small-vm-helpers.sh` with helpers to detect whether
  `GOCACHE` and `BUILD_DIR` are on a small overlay.
- `scripts/build-core-targets.sh` now:
  - Skips `go clean -cache` when `GOCACHE` is on a large volume, reusing the
    cache across targets.
  - Removes each cross-compiled binary after building when `BUILD_DIR` is on
    the small overlay (or when `RHIZOME_BUILD_CLEAN=1`).
  - Expands the core matrix from 7 to 12 targets.
- `scripts/validate-small-vm.sh` now:
  - Places `TEMP` and `TMP` under `GOCACHE` so test temp files go to the same
    volume as the build cache.
  - Honors `RHIZOME_BUILD_DIR` for build output.
  - Only runs `go clean -cache` when the cache is on a small overlay.

### Documentation

- Updated `AGENTS.md` with the host-mount cache example and an explanation of
  `GOCACHE`, `GOMODCACHE`, `RHIZOME_BUILD_DIR`, and `RHIZOME_BUILD_CLEAN`.

## Verification

- `make lint-slim` — 0 issues.
- `make build-core` — builds the 12 core targets and cleans artifacts on a
  small overlay.
- `make build-all` — builds the full 15-target matrix on a large-volume runner.
- `go build -tags goolm,stdjson ./...` and `go test -p 1 -tags goolm,stdjson -count=1 ./...`
  remain green on Windows.

## Validation report (v0.8.3)

The previous `v0.8.3` build was validated on the 4 GB overlay / 2 GB memory
Docker container with `GOCACHE`/`GOMODCACHE` redirected to a 7 TB host mount.
All five small-VM stages passed: `cmd/rhizome` build, `go vet`, in-scope
`go test`, `make lint-slim`, and the core cross-compile matrix. The
65-minute cross-compile runtime and the 100 % full overlay at completion were
the motivation for the v0.8.4 fixes above.

## Compatibility

- No product behavior, config schema, or protocol changes.
- `build-all` no longer builds `android/arm64` (it remains in the separate
  Android CI job) and no longer emits a `rhizome-linux-armv7` binary separate
  from `rhizome-linux-arm`; release artifact consumers should use the
  `rhizome-linux-arm` binary.

## Remaining blocked/deferred items

- Full release gate (race tests, integration scripts, 15-target `make build-all`)
  still requires a CI runner with ≥ 10 GB free disk and ≥ 4 GB of memory.
- Logo/branding asset replacement, translated README rebrand, `nightly.yml` and
  `docker-build.yml` release credentials, and QEMU/Android 4.4 hardware smoke
  tests remain blocked or deferred as documented in `.todo.md`.

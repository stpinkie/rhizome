# Rhizome v0.4.1 Release Notes

**Focus:** Multi-agent / P2P mesh — Mesh observability & DHT hardening.

## New Features

- **Runtime event bus** wired through `rhizome daemon` for mesh, DHT, and remote agent events.
  - New event domains: `mesh.*`, `dht.*`, and `remote.*`.
  - Events emitted for peer connect/disconnect, DHT bootstrap, DHT discoveries, capability exchange/queried, and remote delegate/spawn calls.
- **DHT hardening**:
  - DHT status snapshot (`DHTStatus`) with routing table size, discovered peer count, last provide/discover times, and provided/discovered flags.
  - Backoff on repeated DHT provide errors with `mesh.error` events.
  - `DHTConfig.Validate()` guards for negative intervals and missing rendezvous.
- **Capability query protocol** on `/rhizome/caps/1.0.0`.
  - `Mesh.QueryCapability` lets a trusted node pull the latest capability from a peer.
  - The capability handler responds to queries only from trusted peers.
- **CLI observability**:
  - `rhizome network status --peers` shows live connected peers, their addresses, trust status, and advertised capabilities.
  - `rhizome network status --dht` shows live DHT state.
  - New `rhizome mesh status` and `rhizome mesh peers` shortcuts defaulting to live mesh output.
- **Mesh/DHT config validation** in `LoadConfig` and `NewNode`.
- `Mesh.IsTrusted` exported for CLI and external consumers.

## Fixes

- `agentrpc.Request` now carries an `async` flag so the mesh can distinguish remote `delegate` and `spawn` calls for event reporting.

## Known Limitations

- `network status --peers` may need an explicit `--bootstrap` peer or working DHT/mDNS to discover other nodes.
- Capability discovery still relies on trust; untrusted peers are filtered in `QueryCapability` and in query responses.

## Build


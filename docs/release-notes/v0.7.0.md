# Rhizome v0.7.0 Release Notes

## Swarm Mode: named groups of trusted peers

Tracks 21–30. Builds on the v0.6.x mesh layer to coordinate groups of
Rhizome nodes: presence, a distributed work queue, deterministic
coordinator election, goal orchestration, and an optional GossipSub
broadcast backend.

### Swarm core (Track 21)

- New `pkg/rhizome/swarm` package: signed JSON envelopes over a new
  `/rhizome/swarm/1.0.0` protocol on `ReliableConn` streams.
- `Envelope` carries `swarm_id`, `type`, `from`, `nonce`, `timestamp`,
  `payload`, and an Ed25519 signature over the canonical encoding.
- Membership is strictly subordinate to the mesh trust set — only trusted
  peers can join or appear in a roster.
- JOIN/JOIN_ACK handshake with roster gossip, LEAVE push, bounded rosters
  (`swarm.max_members`, default 32), and per-message size caps
  (`swarm.max_message_bytes`, default 256 KiB, enforced after frame read).
- Membership registry persisted to `<RHIZOME_HOME>/swarms.json` (atomic
  write) so rosters survive daemon restarts.
- `Broadcaster` interface separates swarm semantics from transport; the
  default backend fans out over per-member streams.
- CLI: `rhizome swarm join|leave|list|members|status` plus
  `offer`/`offers`/`run` (daemon-backed).

### Scatter-gather fan-out (Track 23)

- `Mesh.FanoutTask` submits one task to up to N capable trusted peers and
  aggregates per-branch results with `first` / `quorum` / `all` strategies.
  `first` best-effort cancels losing branches; `quorum` picks the plurality
  result by content.
- CLI: `rhizome network scatter <agent-id> <task> --n --strategy --k` (also
  under `rhizome mesh scatter`).
- Emits `mesh.fanout.start` / `mesh.fanout.end` runtime events.

### Presence and roster (Track 22)

- Members heartbeat signed PING envelopes with a capability digest and
  active task count (`swarm.presence.heartbeat_interval`, default 15s).
- Members silent past `swarm.presence.expire_after` (default 45s) are
  evicted with a `swarm.member.expired` event; coordinator re-election runs
  on every roster change.
- `GET /network/swarms/<id>/members` (daemon) and
  `GET /api/network/swarms` (launcher) expose the live roster.

### Distributed work queue (Track 24)

- Offer/claim/assign over the broadcast channel: an offerer broadcasts a
  signed offer; members evaluate it locally and reply with point-to-point
  claims during `swarm.queue.claim_window` (default 5s); the offerer picks
  the least-loaded claimer and submits the task over the existing mesh task
  protocol (retry/failover included).
- Open offers expire after `swarm.queue.offer_ttl` (default 2m); up to
  `swarm.queue.max_offers` (default 100) are tracked locally.
- `swarm offer <swarm> <agent> <task>` and `swarm offers <swarm>` require a
  running daemon.

### Observability API (Track 25)

- Daemon: `GET /network/swarms`, `GET /network/swarms/<id>`,
  `/members`, `/offers`, `POST /network/swarms` (join/leave, persisted to
  `swarm.memberships`), `POST /network/swarms/<id>/offers`,
  `POST /network/swarms/<id>/run`, and an SSE stream at
  `GET /network/swarms/events[?swarm=<id>]`.
- Launcher: `GET|POST /api/network/swarms[/<id>[/<sub>]]` proxies the
  daemon; GET falls back to `swarms.json` + config, POST join/leave falls
  back to a config edit. `GET /api/network/swarms/events` streams through.

### Per-swarm security (Track 29)

- `swarm.acl[]` rules scoped by `swarm_id` + `peer_id` control
  `allow_offer`/`allow_claim`, restrict `agents`, and override
  `rate_limit`. Missing rules default to "trusted peers may offer/claim".
- Per-peer and global inbound swarm rate limits
  (`swarm.rate_limit_per_peer` 60/min, `swarm.rate_limit_global` 600/min).
- Replay guard scopes nonces by (peer, swarm); envelope timestamps are
  bounded by `swarm.request_max_skew` (default 2m).
- Swarm operations audit into the shared `mesh-audit.jsonl` trail with
  `swarm.`-prefixed ops (disable with `swarm.audit_log=false`).

### Coordinator election and shared state (Track 27)

- Deterministic coordinator: the lexicographically smallest peer id among
  members. No extra election traffic — every node computes the same answer
  from its roster.
- The coordinator writes `swarm/<id>/state.json` into the synced workspace
  every `swarm.coordination.state_interval` (default 30s) and on roster
  changes, so all members converge on the same shared state through the
  existing Git sync. Opt out with `swarm.coordination.enabled=false`.

### Orchestrator (Track 28)

- `swarm run <swarm> <goal>` (and `POST /network/swarms/<id>/run`) asks the
  local agent to decompose a goal into subtasks, offers each on the work
  queue, waits for the winning claimants' results, and synthesizes a
  summary with the local agent. Without a decomposer the goal runs as a
  single subtask.
- Emits `swarm.run.start` / `swarm.run.end` events.

### Swarm dashboard (Track 26)

- New **Swarms** panel on the Network page: join/leave controls, live
  member roster with coordinator crown and per-peer load, offer/goal
  forms, tracked offers, and run summaries.
- The panel subscribes to `/api/network/swarms/events` for instant updates
  and polls as a fallback when the daemon is offline.

### Optional GossipSub transport (Track 30)

- `swarm.transport: "gossipsub"` swaps broadcast fan-out for one pub/sub
  topic per swarm (`rhizome/swarm/<id>`). Envelope signatures and all
  inbound checks are unchanged — the pub/sub layer only replaces the
  member fan-out, not authentication.
- Default remains `direct`; GossipSub adds `go-libp2p-pubsub` and suits
  larger swarms or denser chatter. Join/leave/ping traffic stays on direct
  streams either way.

## Configuration

```json
{
  "swarm": {
    "enabled": true,
    "memberships": ["ops"],
    "max_members": 32,
    "max_message_bytes": 262144,
    "request_max_skew": "2m",
    "transport": "direct",
    "presence": { "heartbeat_interval": "15s", "expire_after": "45s" },
    "queue": { "offer_ttl": "2m", "claim_window": "5s", "max_offers": 100 },
    "coordination": { "enabled": true, "state_interval": "30s" },
    "rate_limit_per_peer": 60,
    "rate_limit_global": 600,
    "audit_log": true,
    "acl": [
      {
        "swarm_id": "ops",
        "peer_id": "*",
        "allow_offer": true,
        "allow_claim": true,
        "agents": ["main"],
        "rate_limit": 0
      }
    ]
  }
}
```

Swarm requires `mesh.enabled` — trust is inherited from
`mesh.trusted_peers`.

## Verification

- `scripts/integration-swarm.ps1` spins up two daemons, verifies mutual
  roster exchange over signed envelopes, and confirms roster persistence
  across a daemon restart.
- `pkg/rhizome/swarm` unit tests cover join/roster gossip, untrusted
  rejection, replay, persistence, presence expiry, offer/claim/assign,
  ACL denial, and deterministic coordinator election.

## Compatibility

- The `/rhizome/swarm/1.0.0` protocol is additive; mesh protocols and the
  `/network/*` HTTP shapes are unchanged.
- `swarm.enabled` defaults to `false`; nodes without it are unaffected.
- GossipSub is a new optional dependency (`go-libp2p-pubsub` v0.17.0),
  only active with `swarm.transport: "gossipsub"`.

## Track 31 — Stabilization & Security

### CI / test hardening

- Fixed flaky mesh, swarm, and sync tests by replacing peerstore-based protocol
  polling with a direct stream probe (`pkg/rhizome/p2putil.OpenProtocolStream`)
  and opening call/push/fetch streams with `host.NewStream` under the caller's
  context.
- `scripts/integration-swarm.ps1` / `.sh` verified green end-to-end (two-node
  join, roster gossip, restart persistence).
- Triaged `origin/fix-golangci-lint-failure-*` and
  `origin/freebuff/go-through-the-github-actions-*`: **superseded, kept for
  reference** — both diverged before v0.7.0 and their lint/CI fixes were
  applied to `main` in a different form (`4ac5b2d5`, `1936af9e`).
- `golangci-lint --build-tags=goolm,stdjson` reports 0 issues; CI pinned to
  v2.13.2; `make lint` wired (Go lint + `scripts/lint-docs.sh`).

### Security

- **Shared redaction (`pkg/redact`)**: generic masking of Bearer tokens,
  `api_key=`/`token=`/`secret=` key-values, `sk-*`/`rk-*`-style secret
  prefixes, Telegram bot tokens, and `Authorization:` headers — applied to
  **all** logger messages and field values, not just the 3rd-party adapter
  path. `config.SetGlobal` additionally registers the configured
  `SecureString` replacer so user secrets are masked in logs too.
- **Tool-result filtering**: `FilterSensitiveData` now chains configured-value
  replacement *and* generic secret-pattern masking before results reach the LLM.
- **Prompt-injection guard (`pkg/guard`)**: shared phrase patterns used by the
  shell-command screen (unchanged blocking behavior); tool-call JSON extracted
  from free-text model output (CLI providers) now **drops** calls whose
  arguments contain injection phrases; the tool registry warn-scans all tool
  arguments recursively (nested objects and arrays) so suspicious content is
  visible in logs.
- **SSRF**: audited and confirmed — `web_fetch` blocks private/loopback/
  link-local/metadata IPs both at pre-flight and at dial time (IPv4-mapped
  IPv6, 6to4, ISATAP, redirect targets covered), with `private_host_whitelist`
  overrides; `exec` scans embedded URLs; `browser_open` (and the optional
  `url` on `browser_snapshot`/`browser_screenshot`) rejects private hosts
  literally *and* after DNS resolution, via `tools.browser.private_host_whitelist`
  — note this covers the initial URL only; in-page redirects/subresources
  follow normal browser rules.
- **Filesystem sandbox**: audited — `restrict_to_workspace` (default on)
  covers `read_file`/`write_file`/`edit_file`/`append_file`/`list_dir`/`exec`
  through `buildFs`, with `allow_read_paths`/`allow_write_paths` whitelists;
  browser artifacts (screenshots) are constrained to the workspace.

### Known blockers (documented)

- `nightly.yml` / `docker-build.yml` remain disabled — release signing /
  notarization credentials are not configured.
- `assets/logo.webp` is still a placeholder pending real art assets.
- Two offer/fanout timing tests (`TestMeshFanoutQuorumPending`,
  `TestSwarmOfferClaimAssign`) pass in isolation but can flake under
  full-suite parallel load on Windows — suspected Windows Firewall prompt
  interference with libp2p listeners. Re-verify on a Linux host.

## Track 32 — Browser Automation

Browser automation is **opt-in** (`tools.browser.enabled: false` by default)
and adds **zero** dependencies or binary size: the driver shells out to the
external [`agent-browser`](https://github.com/vercel-labs/agent-browser) CLI.

### Architecture

- `pkg/browser` — backend **catalog** (12 backends, capability flags, license
  metadata, auth fields), endpoint **resolvers**, and a per-conversation
  **session manager** with timeout-based teardown and explicit cloud-session
  release (billing-safe).
- `AgentBrowserDriver` — invokes `agent-browser --json --session <key>`:
  local Chromium by default, remote endpoints via the `AGENT_BROWSER_CDP`
  env var (credential-bearing ws URLs stay out of argv), provider plugins
  via `-p <provider>` + env credentials.
- `pkg/tools/browser` — eight agent tools: `browser_open`, `browser_snapshot`
  (interactive `@eN` refs), `browser_click`, `browser_fill`,
  `browser_screenshot` (workspace-scoped), `browser_eval`, `browser_wait`,
  `browser_close`. URLs are SSRF-guarded; capability mismatches return clear
  errors.
- `tools.browser` config — `default_backend`, `session_timeout`,
  `private_host_whitelist`, per-backend `backends` (SecureString API keys →
  `.security.yml`-capable).
- Web console: `/browser` page (backend cards, status, install/uninstall,
  default selector, credential fields, disk-space warning) backed by
  `GET/PUT /api/browser`, `GET /api/browser/backends`,
  `POST /api/browser/install|uninstall`, `GET /api/browser/diskspace`.

### Backends

| Backend | Kind | Notes |
| --- | --- | --- |
| `agent-browser` | local | npm-managed, bundled Chromium (~400 MB, disk-gated) |
| `system-chrome` | local | installed Chrome/Edge, dedicated profile — no download |
| `clawbrowser` | local (BYO) | anti-detect; `clawctl` + API key |
| `custom-cdp` | remote | any `ws://`/`http://` CDP endpoint |
| `provider` | cloud | generic `agent-browser -p` passthrough |
| `browserbase`, `browserless`, `kernel` | cloud | provider plugins + env creds |
| `steel`, `hyperbrowser`, `tinyfish` | cloud | REST session → CDP ws URL; released on close |
| `cloudflare` | REST | **snapshot/screenshot/content only** — interactive ops return a clear unsupported error |

### Stealth path

Anti-detect automation is served by a **Patchright-based MCP server**
(`workspace/skills/stealth-browser`) rather than a CDP bridge — stealth lives
in the client driver, so plain CDP would lose it. Setup documented in
`docs/guides/browser-automation.md`.

### Dropped / deferred

- **LightPanda** — no Windows binary, WIP CDP, no real renderer, AGPL.
- **CamouFox direct** — Playwright/Juggler protocol; would need a Python bridge.
- **Donut** — CDP is Pro-gated; requires a running desktop app.
- **Own Go CDP client** — deferred to v0.8.0 (needed for Cloudflare's
  authenticated WebSocket handshake and a Node-free path).

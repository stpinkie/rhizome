# v0.6.0 — Mesh operations

This release makes the v0.5 mesh stack operationally usable: remote tasks are
now exposed over the daemon gateway, the launcher, the web console, and the
CLI, and capability manifests carry load so the mesh can pick a suitable peer
for you.

## Highlights

- **Remote task HTTP surface.** The daemon gateway serves `GET/POST
  /network/tasks` (list, status, long-poll result via `wait=`, submit,
  `action=cancel`) and `GET /network/audit?tail=N`, authenticated with the
  existing PID-file bearer token. Task peer parameters accept either a peer
  ID or a `/p2p/` multiaddr, which is dialed on demand.
- **Launcher proxying.** `GET/POST /api/network/tasks` and
  `GET /api/network/audit` proxy the daemon when it is running. Reads and
  cancels fall back to `rhizome network task …` against the peer's saved
  bootstrap address; audit falls back to reading `mesh-audit.jsonl` under
  `RHIZOME_HOME` directly.
- **Web console.** The Network page gained a Remote Tasks panel (peer picker,
  agent/model suggestions from the peer's advertised capability, submit,
  live status, cancel, result viewer) and a Mesh Audit Log panel showing the
  signed-operation trail.
- **CLI.** `rhizome network audit` / `rhizome mesh audit` print the audit
  tail (`--tail`, `--json`). `rhizome mesh route <agent-id> <task>` picks a
  connected, trusted peer that advertises the agent — preferring direct
  connections and least-loaded peers — and submits the task (`--sync` for a
  synchronous delegate, `--wait` to long-poll the result).
- **Capability-driven routing.** Capability manifests advertise
  `active_tasks` (signed, additive) and `Mesh.PickPeer(agentID, op)` ranks
  candidates by connection quality and advertised load. `network status` and
  the dashboard surface the load per peer.
- **Audit reader.** `mesh.ReadAuditTail` returns the last N valid JSONL
  entries without loading the rotated log file into memory.

## Hardening and tests

- New unit suites for `pkg/rhizome/agentrpc` (signing, nonce echo, handler
  errors, peer-scoped idempotency cache with TTL and 1024-entry bound) and
  `pkg/rhizome/agenttask` (op framing, malformed frames, correlation-id
  dedup, resubmit idempotency).
- New gateway tests covering auth, validation, and a live two-mesh
  submit → status → list → cancel round-trip, plus least-loaded `PickPeer`
  tests.
- Fixed a mesh test race: fixed `time.Sleep` connection waits were replaced
  with eventual connectedness assertions.
- Frontend formatting and typecheck pass.

## Notes

- All new fields are additive; manifests without `active_tasks` still
  verify, and peers without a stored manifest are simply not candidates for
  `PickPeer`.
- `active_tasks` is a snapshot taken at manifest signing and can go stale
  within the freshness window — it is a routing hint, not a guarantee.
- Remote ops still require mutual trust, pass through the callee's ACL and
  rate limits, and are recorded in the audit trail when `mesh.audit_log` is
  enabled.

# Rhizome v0.15.0 Release Notes

## Sprint theme

**Mesh & Swarm Depth** — the arc considered and deferred at the v0.14.0
sprint revision, shipped as its own sprint. The mesh learns to route by
what a peer *can do* (`--require-model` / `--require-skill`), to say no
when it's full (`capacity:` rejections with automatic failover), and to
resume what a dropped stream interrupted (offset-resumed blob transfers +
content-addressed dedup). Swarms gain a durable work queue that survives
restarts, score-weighted claim picks, run cancel/retry lifecycle, and a
diagnostics surface (`swarm doctor`) that makes a sick roster visible
from the CLI.

- **Requirement-aware dispatch** — `--require-model`/`--require-skill`
  on `route`/`scatter` filter picks and failover candidates by signed
  capability manifest.
- **Capacity controls** — global + per-peer inbound task caps; the
  `capacity:` rejection class steers callers to the next ranked peer.
- **Restart reconciliation** — running records sweep to `interrupted`,
  published offers re-drive from `swarm-offers.jsonl`.
- **Observability** — persisted activity feed with filters, `mesh/swarm
  trace` correlation, per-op score counters with half-life decay, and a
  dashboard that surfaces all of it.
- **Resumable blobs** — `.partial-<hash>` staging + offset handshakes;
  a 64 MiB transfer survives a dropped stream, and already-held blobs
  never re-send.

Design doc: `docs/design/v0.15.0-sprint.md`. Operator guides:
`docs/guides/swarm-ops.md`, `docs/guides/spawn-tasks.md`,
`docs/operations/debug.md`.

### Requirement-aware mesh dispatch (Track 113, PR #69)

- `mesh.Requirements{Models, Skills}` + `PickPeerWith` /
  `PickPeerRankedWith`: a manifest that omits a class never satisfies
  it — additive-safe, no new `Capability` fields.
- `RemoteCall.Requires` steers failover candidates (an explicit peer
  stays an explicit choice); `FanoutRequest.Requires` filters branch
  peers.
- `--require-model` / `--require-skill` (repeatable, any-of per class)
  on `mesh route` + `mesh scatter`; peers advertise via
  `mesh.advertise_models` / `mesh.advertise_skills` / `mesh.skill_share`.

### Inbound capacity controls (Track 114, PR #70)

- `mesh.max_concurrent_tasks` (default `8`, `0` = unlimited, negative
  rejected at validate) gates inbound remote-task submits.
- `mesh.acl[].max_concurrent` per-peer caps; negative exempts a peer
  from capacity checks entirely.
- Stable `capacity:` rejection class — callers stop burning same-peer
  retries and fail over to the next ranked candidate; correlation-id
  resubmits bypass the cap (dedup, not new work).

### Swarm claim scoring + subtask requirements (Track 115, PR #71)

- `Swarm.SetScoreLookup` → claims rank score desc → active tasks asc →
  claim order; unscored claimants last. `swarm offers --json` shows the
  ranked claim list — the pick rationale.
- `Subtask` gains `requires`/`tools`/`model`/`timeout`, forwarded
  through the decomposer into `OfferRequest`; per-offer TTL honored.

### Restart reconciliation + run lifecycle (Track 116, PR #72)

- `runStore.Load` sweeps `running` → `interrupted` +
  `swarm.run.interrupted` event — nothing resumes silently.
- `swarm-offers.jsonl` persists published offers (bounded 256); daemon
  start re-drives open offers with a fresh claim window, TTL-elapsed
  land `expired`.
- `swarm run-cancel` / `run-retry` (+ `POST
  /network/swarms/<id>/runs/{cancel,retry}`): cancel stops live offer
  loops; retry records a `retry_of`-linked run, dep-gated re-offers of
  failed/expired/dead_letter/timeout subtasks.

### Coordinator & roster diagnostics (Track 117, PR #73)

- `swarm doctor` — bounded `MsgQuery` per member: roster diff
  (asymmetric / undiscovered), coordinator reachability, per-member
  epochs (additive `epochs` payload).
- `SwarmInfo.last_state_write` + live coordination freshness in
  `swarm status`; `GET /network/swarms/<id>/doctor`.
- `swarm.coordination.prefer_connected` (opt-in): excludes disconnected
  members from election — availability over determinism.

### Observability depth (Track 118, PR #74)

- `mesh.activity_log` (default on) mirrors the feed to
  `mesh-activity.jsonl` with rotation + restart warm-load.
- Filters `--kind`/`--peer`/`--swarm`/`--since` on CLI and
  `GET /network/activity`.
- `GET /network/trace?task=|offer=|run=|id=` + `mesh trace` /
  `swarm trace` — correlate an id across task store, offers, runs,
  activity, audit.
- `PeerScore` per-op counters + read-time decay halving per idle
  `score_half_life` (default `168h`); `ops`/`decay` on `mesh peer`.

### Dashboard/API depth (Track 119, PR #75)

- `GET /network/swarms/<id>/health` alias; `/api/network/trace` proxy.
- Web: activity-panel filter bar (daemon-side fetch + client-mirrored
  SSE), peer-detail per-op score breakdown + decay notice, swarms-panel
  on-demand health card, offer claim details, run `retry_of` badge.

### Transfer & skill depth (Track 120, PR #76)

- `/rhizome/blob/1.0.0` signed `offset` on put/get: `.partial-<hash>`
  staging, get retries ×3 off the staged count, put resumes on the next

  full re-send.
- Content-addressed dedup (`offset==size` skips streaming); stale
  partials reap with the blob TTL.
- `mesh blobs [--json]` daemonless store listing; `mesh skill push`
  consentful offer → peer pulls through the normal allowlist/trust/
  guard path; `POST /network/skills/push`.

## Upgrade notes

- **No config changes required.** All new knobs default sanely:
  `max_concurrent_tasks: 8`, `activity_log: true`,
  `score_half_life: "168h"`, `prefer_connected: false`,
  `advertise_models/skills: false`.
- Requirement-filtered routing needs peers to opt into
  `mesh.advertise_models` / `mesh.advertise_skills` — otherwise their
  manifests omit the class and `--require-*` filters exclude them.
- The blob `offset` fields are additive: pre-upgrade peers answer
  `offset=0` and transfers restart from zero — same behavior as before,
  just without resume.
- `swarm-offers.jsonl` + `mesh-activity.jsonl` appear under
  `~/.rhizome/` — both bounded/rotated, no operator maintenance.

## Deferred

- `mesh skill push` lands as offer→pull only; a true server-push
  transport was considered and deliberately not added (pull keeps the
  recipient's trust/guard checks authoritative).
- RSS re-measurement stays a manual release-prep step
  (`scripts/measure-footprint.sh`); the standing watch is unchanged.
- `v0.15.0` tag + release artifacts on explicit go-ahead.

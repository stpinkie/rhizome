# v0.13.0 Sprint Plan — Agent Interop Depth

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **Agent interop depth.** Rhizome already speaks ACP in both
directions — `rhizome acp` serves editors (Track 61), `agents.list[].acp`
binds external agents as routable agent ids (Track 62), and v0.12.0 Track 81
adds `session/load` persistence, per-session MCP passthrough, and a
policy-gated terminal bridge. This sprint makes those surfaces real: editors
get session modes and a model picker, external agents get auth and session
continuity, any MCP client can drive allowlisted Rhizome tools, and skill
discovery gains a signed first-party index. First, we land the v0.12.0 stack.

## Decisions

- **Modes reuse the existing permission vocabulary.** ACP session modes map
  onto the `PermissionPolicy` set (`prompt`/`allow`/`deny`) as
  `ask`/`auto`/`read-only` — no second policy language, and the mode is a
  per-session override, never a weakening of a stricter server policy floor
  (impl-time check: a server started with `permission_policy=deny` may cap
  the advertised mode list rather than allow escalation past it — pick the
  conservative shape).
- **Mode changes are fail-closed.** Switching modes clears the session's
  cached `*_always` decisions — a `deny`→`prompt` change must not inherit
  stale approvals, and an `allow`→`deny` change must not keep allowing.
- **The model picker is agent-global, documented.** `session/set_config_option`
  category `model` drives the same machinery as `/switch model to <name>`
  (`rt.SwitchModel` → `agent_command.go`), which mutates the agent
  instance's model/candidates — it is not session-scoped. Per-session model
  override is a named follow-up: it needs an `InboundMessage`-level override
  plumbed into `selectCandidates`/`pipeline_setup.go`, which is a deeper
  change than this sprint's interop surface justifies.
- **External auth supports what we can satisfy locally.** `env_var` methods
  are satisfied from the operator-configured `acp.env` binding (the env we
  already inject at spawn); `terminal` methods only when
  `acp.client.terminal_policy=allow`; `agent` methods are refused with a
  clear error. We never fabricate credentials.
- **`mcp serve` is deny-all by default.** `tools.mcp_server =
  {enabled:false, allow:[]}` — an empty allowlist exposes nothing. This is
  the `mesh.skill_share` posture: the tool surface is opt-in per tool.
- **The skill index is signed, not just curated.** Same Ed25519 pattern as
  the module catalog (Track 70): `index.json` + `index.json.sig` verified
  against the baked-in release pubkey; unsigned or bad-sig content is
  refused outright. Curation without signature would be a trust regression
  relative to the module system.
- **No new dependencies.** The MCP server uses the vendored
  `modelcontextprotocol/go-sdk`; signing uses stdlib `crypto/ed25519`;
  everything else is existing plumbing.

## Track 85 — ACP session modes (`session/set_mode`)

Per-session permission posture, visible and switchable in the editor's mode
picker:

- `acpSession` gains `mode string` (empty = inherit `s.policy`).
  `toolApprover.ApproveTool` reads `sess.mode` first, falls back to
  `srv.policy` — the mode is a per-session override of the server policy.
- Advertise `Modes *SessionModeState{CurrentModeId, AvailableModes}` on
  `NewSessionResponse` and `LoadSessionResponse` (Track 81 already returns
  those types). Mode set: `ask` (prompt — default), `auto` (allow),
  `read-only` (deny). When `permission_policy=deny`, advertise only
  `read-only` — no escalation past a stricter server floor.
- `SetSessionMode`: look up session → validate `ModeId` against the
  advertised set (unknown → `NewInvalidParams` listing candidates) → set
  `sess.mode` → clear `sess.allow`/`sess.deny` (fail-closed) → emit
  `session/update` `CurrentModeUpdate` → return.
- Persist `mode` in the Track-81 session record (`acp-sessions.json` /
  `pkg/acp/session_store.go`) so `session/load` restores the posture.
- Wire-compat: none — modes are a session-scoped server feature.

## Track 86 — ACP session config options (`session/set_config_option`)

A model picker for editors, on the SDK's `SessionConfigOptionSelect` with
`category: model`:

- `ConfigOptions []SessionConfigOption` on `NewSessionResponse`/
  `LoadSessionResponse`: one select option listing `cfg.ModelList[].ModelName`
  entries; `CurrentValue` = the agent's active model
  (`rt.GetModelInfo` equivalent).
- `SetSessionConfigOption`: `configId == "model"` → drive the same
  resolve/validate path as `/switch model` — inject
  `Options.ModelSwitcher func(value string) (old string, err error)` on
  `Server` (wired in `cmd/rhizome/internal/acp` to the
  `agent_command.go:370` machinery: `model_list` lookup →
  `resolveModelCandidates` → provider init → swap under `modelStateMutex`).
  Unknown `configId` or value → `NewInvalidParams` listing candidates.
  Response echoes the refreshed `configOptions` list.
- Documented scope: agent-global (matches `/switch model` semantics); a
  per-session model override is a named follow-up needing an
  `InboundMessage` field plumbed into `selectCandidates`/`pipeline_setup.go`.

## Track 87 — External-agent `authMethods`

Kill the hard-fail in `ClientManager.spawn` when `initResp.AuthMethods` is
non-empty (`client.go:325`):

- After `initialize`: if the agent advertises auth methods, pick one —
  `agents.list[].acp.auth_method` (explicit method id) wins, else the first
  satisfiable method — then `conn.Authenticate(ctx, {MethodId})` before any
  `session/new`.
- `env_var` methods: satisfiable iff every advertised required var is
  already present in `binding.Env` (the env spawn injects); missing vars →
  error naming them. `terminal` methods: attempted only when
  `acp.client.terminal_policy=allow` — the agent's auth flow runs through
  the Track-81 terminal bridge. `agent` methods: refused with a clear
  "not supported" error (delegated-auth is a follow-up).
- Failure posture unchanged: unsatisfiable or rejected auth → kill the
  process + descriptive error. No fabricated credentials; `binding.Env`
  values are operator-configured, and `SecureString` hygiene applies where
  config already provides it.

## Track 88 — External-agent session depth + media

- **Session persistence**: `agents.list[].acp.session_mode` =
  `oneshot` (default — today's create/prompt/close per `RunAgent`) |
  `persistent` (one session per agent id, reused across delegations so the
  external agent accumulates context). On respawn after a process death:
  `session/load` when the agent advertised `LoadSession`, else fresh
  `session/new`. `session/close` moves to `ClientManager.Close`.
- **Media passthrough**: `RunRemote`/`RunAgent` currently drop media
  (`client.go` warns and discards `req.Media`). Plumb `media://` refs →
  `ContentBlockImage` prompt blocks when the agent's advertised
  `PromptCapabilities.Image`; degrade to a text reference otherwise.
- **Per-binding policy overrides**: `agents.list[].acp.permission_policy`
  and `agents.list[].acp.terminal_policy` fall back to the `acp.client.*`
  globals — lets a trusted binding get `allow` while the fleet default
  stays `deny`.
- Wire-compat: none — all client-side behavior.

## Track 89 — `rhizome mcp serve` (Rhizome as MCP server)

Rhizome consumes MCP today (`tools.mcp`, `pkg/mcp/manager.go` on the
vendored `modelcontextprotocol/go-sdk`) but cannot serve it. This completes
the interop triangle: ACP server (editors drive Rhizome), ACP client
(Rhizome drives external agents), MCP server (any MCP client drives
allowlisted Rhizome tools — Claude Desktop, Cursor, other agents).

- `pkg/mcp/server.go` (new): `mcp.NewServer` over the SDK's stdio
  transport; register tools from a freshly built `ToolRegistry` filtered by
  `tools.mcp_server.allow` (default empty = deny-all). Rhizome tool
  `Parameters()` is already JSON Schema — maps directly to MCP
  `inputSchema`; tool names pass through unchanged (they're already flat
  and namespaced: `web3_*`, `read_file`, …).
- `cmd/rhizome/internal/mcp/serve.go`: `rhizome mcp serve` — daemonless;
  builds the tool registry the same way other CLI paths do; errors out
  unless `tools.mcp_server.enabled`. stderr logging only — stdout is the
  protocol channel (the ACP stderr-drain rule applies here).
- Config: `tools.mcp_server = {enabled:false, allow:[...]}`. Agent-loop-
  dependent tools (`delegate`, `acp_run`, swarm verbs) are excluded by the
  allowlist shape, not special-cased.
- Smoke: MCP inspector or a second Rhizome with `tools.mcp` pointed at
  `rhizome mcp serve` — dogfoods both halves.

## Track 90 — Signed curated skill index

A first-party `rhizome` registry provider in `pkg/skills`, signed like the
module catalog:

- `pkg/skills/rhizome_registry.go` (new provider via
  `RegisterRegistryProviderBuilder("rhizome", …)`): fetch `index.json` +
  `index.json.sig` from `registries.rhizome.base_url` (default: the
  `stpinkie/rhizome-skills` repo raw URL — impl-time detail: dedicated repo
  vs `docs/`-hosted file, decide with repo creation); verify Ed25519 via
  `modules.VerifyCatalogSignature` (extract the verify helper to a shared
  spot — `pkg/sigverify` or export-and-call, impl-time call); unsigned or
  bad-sig → refuse + warn.
- Index entries: `{slug, display_name, summary, version,
  source:{github:"owner/repo[@ref][/path]"}, sha256?}`. Install resolves
  `source` → delegates to the existing GitHub installer path (guard scan +
  provenance apply unchanged); optional `sha256` pins the bundle when the
  publisher supplies one.
- Cache the verified index under `<RHIZOME_HOME>/skills-index-cache/`
  (~1 h TTL, stale-serve on fetch failure — the `catalog-cache/` pattern
  from Track 70). Enabled-default matches clawhub's posture.
- Content: initial `rhizome-skills` index + signing via the existing
  `MODULE_CATALOG_SIGNING_KEY` secret; `docs/operations/
  skill-index-signing.md` mirrors `module-catalog-signing.md`. Hub UI gains
  a "curated" source badge (the violet Mesh-badge precedent).
- Events/audit: `skill.index.merged|rejected|stale` mirroring
  `module.catalog.*`.

- `go build -tags goolm,stdjson ./...` green; `go test -p 1 -tags
  goolm,stdjson ./...` green on touched packages; `golangci-lint` v2.13.2 →
  0 issues; `lint-docs.sh` OK; no new dependencies (binary-size delta ≈ 0).

  pull, `rhizome version` in an artifact).

  approving), emits `current_mode_update`, and survives `session/load`.
- Model config-option: lists `model_list` entries, switching takes effect
  on the next prompt, unknown ids/values error cleanly.
- External-agent auth: a mock/stdio agent advertising `env_var` auth
  authenticates when vars are present in `acp.env`, fails with a
  named-missing-vars error otherwise; `terminal` method honored only under
  `terminal_policy=allow`; `agent` method refused clearly.
- External-agent sessions: `persistent` mode reuses one session across two
  `acp_run` calls (verified via the mock agent's session count); media
  blocks reach an image-capable agent.
- `rhizome mcp serve`: a real MCP client lists only allowlisted tools and
  can call one end-to-end; deny-all default proven (enabled=false → error;
  empty allow → zero tools).
- Skill index: signed index installs a skill end-to-end; tampered/unsigned
  index refused; stale-cache path serves on fetch failure.
- Locale sweep: zero PicoClaw/mascot/🦐 hits in `docs/project/README.*.md`.
- Networked tests keep the AGENTS.md isolation posture;
  `integration-mesh`/`integration-swarm` green.

## Impl-time verification checklist

- `SessionModeState`/`SessionConfigOption` field names in the pinned SDK
  (v0.13.5) — generated union types differ from the spec's JSON shape.
- Whether `permission_policy=deny` should cap advertised modes at
  `read-only` or simply clamp overrides — pick the conservative shape.
- `rt.SwitchModel`/`GetModelInfo` reachability from `cmd/rhizome/internal/
  acp` — the machinery lives behind the command runtime; the clean seam is
  an injected func, not a registry reach-through.
- ACP `Authenticate` semantics in the SDK — whether the client calls it or
  the agent initiates, and whether `env_var` methods expect a client-side
  response payload.
- `session/load` client-side shape — what `LoadSessionRequest` needs (cwd,
  mcpServers echo) for external agents that advertise it.
- `media://` ref → base64 image materialization path — the server side
  stores into `media.MediaStore`; the client side needs the read inverse.
- `mcp.NewServer` + stdio transport API in go-sdk v1.6.1 — server-side
  call sites exist only in SDK tests today.
- Whether the skills index lives in a dedicated `stpinkie/rhizome-skills`
  repo or a `docs/`-hosted file — decide with repo creation in Track 90.
- `SkillRegistryConfig.Enabled` default for a new provider — match
  clawhub's posture (`applySkillsRegistryEnvCompat` overlay point).

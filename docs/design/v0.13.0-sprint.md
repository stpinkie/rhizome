# v0.13.0 Sprint Plan — Agent Interop Depth

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **Agent interop depth.** Rhizome already speaks ACP in both
directions — `rhizome acp` serves editors (Track 61), `agents.list[].acp`
binds external agents as routable agent ids (Track 62), and v0.12.0 Track 81
adds `session/load` persistence, per-session MCP passthrough, and a
policy-gated terminal bridge. This sprint makes those surfaces real: editors
get session modes and a model picker, external agents get auth and session
continuity, any MCP client can drive allowlisted Rhizome tools, and skill
discovery gains a signed first-party index. The v0.12.0 stack has landed
(Track 84 done; release verification still open).

## Decisions

- **Modes reuse the existing permission vocabulary.** ACP session modes map
  onto the `PermissionPolicy` set (`prompt`/`allow`/`deny`) as
  `ask`/`auto`/`read-only` — no second policy language, and the mode is a
  per-session override, never a weakening of a stricter server policy floor
  (a server started with `permission_policy=deny` caps the advertised mode
  list at `read-only`).
- **Mode changes are fail-closed.** Switching modes clears the session's
  cached `*_always` decisions — a `deny`→`prompt` change must not inherit
  stale approvals, and an `allow`→`deny` change must not keep allowing.
- **The model picker is per-session, not agent-global** (revised). The
  merged plan drove `/switch model`'s agent-global machinery; this revision
  makes `session/set_config_option` `category:model` a *session* override:
  `acpSession.model` → `bus.InboundMessage.ModelOverride` → `processMessage`
  applies it on a shallow agent copy via the `applyRemoteModelOverride`
  machinery (`pkg/agent/remote.go`, generalized/shared) — router and
  light-model disabled on the copy, **without** the remote path's
  ephemeral-session swap (ACP history must persist on the session key).
  `CurrentValue` reflects the override; an unset value means inherit the
  agent's active model. Persisted on the `SessionRecord` so `session/load`
  restores it.
- **External auth supports what we can satisfy locally** (extended).
  `env_var` methods are satisfied from the operator-configured `acp.env`
  binding (the env we already inject at spawn); `terminal` methods only when
  `acp.client.terminal_policy=allow` (or the per-binding override);
  **`agent` methods are now attempted under that same terminal-allow gate**
  — the agent drives its own auth flow through the Track-81 terminal bridge
  — and refused with a clear error otherwise. We never fabricate
  credentials.
- **`mcp serve` is deny-all by default.** `tools.mcp_server =
  {enabled:false, allow:[]}` — an empty allowlist exposes nothing. This is
  the `mesh.skill_share` posture: the tool surface is opt-in per tool.
- **The skill index is signed, not just curated.** Same Ed25519 pattern as
  the module catalog (Track 70): `index.json` + `index.json.sig` verified
  against the baked-in release pubkey; unsigned or bad-sig content is
  refused outright. Curation without signature would be a trust regression
  relative to the module system.
- **Metering negotiates through the `Allows` map, not a new struct field.**
  `agenttask`/`agentrpc` signatures cover the re-marshaled envelope, so a
  populated new field breaks verification on peers running older builds.
  `Capability.Allows` is `map[string]bool`: a new key survives an old
  build's unmarshal/re-marshal byte-identically (Go maps marshal with
  sorted keys), so `Allows["usage_report"]=true` advertises support without
  breaking manifest verification on mixed fleets — strictly safer than the
  `Role` emit-when-non-default precedent. The `want_usage`/`usage` wire
  fields stay `omitempty` and populate only when both sides negotiated.
- **enc2 for the identity/web3 stores is an AEAD swap, not a format
  reuse.** `pkg/credential`'s `enc2://` derives keys via passphrase+SSH-key
  HKDF; `node.json` and `web3/keys.json` use `KeyProvider`
  (keyring/scrypt). The migration adds a `cipher` marker field (`""` =
  aes-256-gcm legacy, `"xchacha20poly1305"` new writes) and shares only
  `chacha20poly1305.NewX` — key sources are unchanged.
- **Module upstream signatures are additive to the digest.** The
  catalog-pinned sha256/sha512 stays mandatory; a declared
  `signature{kind,url}` verifies where the upstream actually publishes one
  — never a substitute, and its absence is not an error.
- **No new dependencies.** The MCP server uses the vendored
  `modelcontextprotocol/go-sdk`; XChaCha20-Poly1305 is already in the
  module graph via `pkg/credential`; signing uses stdlib `crypto/ed25519`;
  everything else is existing plumbing.

## Track 85 — ACP session modes (`session/set_mode`)

Per-session permission posture, visible and switchable in the editor's mode
picker (SDK v0.13.5 types verified: `SessionMode{Id,Name,Description}`,
`SessionModeState{AvailableModes,CurrentModeId}`, `SessionCurrentModeUpdate`
for `session/update`):

- `acpSession` gains `mode string` (empty = inherit `s.policy`).
  `toolApprover.ApproveTool` reads `sess.mode` first, falls back to
  `srv.policy` — the mode is a per-session override of the server policy.
- Advertise `Modes *SessionModeState{CurrentModeId, AvailableModes}` on
  `NewSessionResponse` and `LoadSessionResponse` (Track 81 already returns
  those types). Mode set: `ask` (prompt — default), `auto` (allow),
  `read-only` (deny). When `permission_policy=deny`, advertise only
  `read-only` — no escalation past a stricter server floor.
- `SetSessionMode`: look up session → validate `ModeId` against the
  advertised set (unknown → `NewInvalidParams` listing candidates) → set
  `sess.mode` → clear `sess.allow`/`sess.deny` (fail-closed) → emit
  `session/update` `CurrentModeUpdate` → return.
- Persist `mode` in the Track-81 session record (`acp-sessions.json` /
  `pkg/acp/session_store.go`) so `session/load` restores the posture.
- Wire-compat: none — modes are a session-scoped server feature.

## Track 86 — ACP config options + per-session model override

A model picker for editors — now **session-scoped** (revised from the
merged plan's agent-global scope):

- `ConfigOptions []SessionConfigOption` on `NewSessionResponse`/
  `LoadSessionResponse`: one `select` option with
  `category: SessionConfigOptionCategoryModel` listing
  `cfg.ModelList[].ModelName` entries plus an inherit/default entry;
  `CurrentValue` = the session's override, else the agent's active model.
- `SetSessionConfigOption`: `configId == "model"` → validate the value
  against `model_list` (unknown → `NewInvalidParams` listing candidates) →
  set `sess.model` (the empty/inherit value clears it) → echo the refreshed
  `configOptions` in the response.
- **Per-session override plumbing** (the previously-deferred follow-up,
  now in scope): `bus.InboundMessage` gains `ModelOverride string` (or the
  equivalent on `DispatchRequest` — impl-time pick; it must survive
  `processMessage`'s route/session allocation in `agent_message.go`).
  `Prompt` sets it from `sess.model`. In `processMessage`, after
  `resolveMessageRoute` returns the agent: when the override is set, take a
  shallow copy and apply the `applyRemoteModelOverride` machinery
  (`pkg/agent/remote.go` — generalize to a shared `applyModelOverride`
  used by both remote dispatch and inbound override): `model_list` lookup
  → `resolveModelCandidates` → provider init on the copy. The remote
  path's ephemeral-session swap does **not** apply — ACP history lives on
  the session key. Router/light-model nil on the copy (an explicit choice
  is never re-routed), same as remote.
- Persist `model` on the `SessionRecord`; `session/load` restores it.
- The `Options.ModelSwitcher` seam from the merged plan is dropped — the
  override path replaces it.
- (stretch) A second config category (`thought_level` exists in the SDK)
  only if a real Rhizome knob maps cleanly — otherwise stays queued.

## Track 87 — External-agent `authMethods` (incl. agent-type)

Kill the hard-fail in `ClientManager.spawn` when `initResp.AuthMethods` is
non-empty (`client.go`). SDK union verified: `AuthMethod{EnvVar{Id,Name,
Vars []AuthEnvVar}, Terminal{Id,Name,Args,Env}, Agent{Id,Name}}`;
`conn.Authenticate(ctx, {MethodId})` exists on `ClientSideConnection`.

- After `initialize`: if the agent advertises auth methods, pick one —
  `agents.list[].acp.auth_method` (explicit method id) wins, else the first
  satisfiable method — then `conn.Authenticate(ctx, {MethodId})` before any
  `session/new`.
- `env_var` methods: satisfiable iff every advertised required var is
  already present in `binding.Env` (the env spawn injects); missing vars →
  error naming them. `terminal` methods: attempted only when
  `terminal_policy=allow` — the agent's auth flow runs through the
  Track-81 terminal bridge. **`agent` methods** (extended): attempted under
  the same terminal-allow gate — the agent manages its own auth flow
  (typically a TUI); refused with a clear "requires terminal_policy=allow"
  error under `deny`.
- Selection order when nothing explicit is configured: prefer `env_var`,
  then `terminal`, then `agent` (impl-time tiebreak — document it).
- Failure posture unchanged: unsatisfiable or rejected auth → kill the
  process + descriptive error. No fabricated credentials; `binding.Env`
  values are operator-configured, and `SecureString` hygiene applies where
  config already provides it.

## Track 88 — External-agent session depth + media + mode forwarding

- **Session persistence**: `agents.list[].acp.session_mode` =
  `oneshot` (default — today's create/prompt/close per `RunAgent`) |
  `persistent` (one session per agent id, reused across delegations so the
  external agent accumulates context). On respawn after a process death:
  `session/load` when the agent advertised `LoadSession`, else fresh
  `session/new`. `session/close` moves to `ClientManager.Close`.
- **Media passthrough**: `RunRemote`/`RunAgent` currently drop media
  (`client.go` warns and discards `req.Media`). Plumb `media://` refs →
  `ContentBlockImage` prompt blocks when the agent's advertised
  `PromptCapabilities.Image`; degrade to a text reference otherwise.
- **Per-binding policy overrides**: `agents.list[].acp.permission_policy`
  and `agents.list[].acp.terminal_policy` fall back to the `acp.client.*`
  globals — lets a trusted binding get `allow` while the fleet default
  stays `deny`.
- **`session/set_mode` forwarding** (new, folded tail): `agents.list[].acp
  .mode` — after `session/new` (and after `session/load` on persistent-
  session respawn), when the agent's response advertises `Modes`, call
  `conn.SetSessionMode{ModeId}`. An id the agent didn't advertise → warn
  and continue (agents own their mode vocabularies; a typo shouldn't kill
  the binding).
- **`mcpCapabilities` honesty** (new, folded tail): `Initialize`
  advertises `AgentCapabilities.McpCapabilities{Http:false, Sse:false}`
  explicitly (stdio is implicit in ACP — the Track-81 passthrough already
  serves it; http/sse/acp variants stay refused per-entry). Client side:
  read the external agent's advertised `McpCapabilities` before forwarding
  any MCP servers; unsupported transports refuse with a per-entry error
  rather than silently dropping.
- Wire-compat: none — all client-side behavior (plus the capability
  advertisement).

## Track 94 — Remote-task usage metering (new; observability only)

Implements the mesh-economy seed doc's "missing primitive" standalone —
remote task responses carry no usage report today. **No pricing, caps, or
billing** — the economy stays deferred in `docs/design/
mesh-economy-module.md`; this track is observability that any later
economy work also needs.

- `RemoteUsage` in `pkg/tools/shared/types.go` beside `ToolResult` (the
  leaf type both wire packages already import):
  `{llm_calls, prompt_tokens, completion_tokens, total_tokens,
  duration_ms}`.
- Turn accumulator: `turnState` gains a summed `usage` (an `AddUsage`
  beside `SetLastUsage` — the existing field is last-call-only);
  `DispatchRequest` gains `UsageSink *RemoteUsage` mirroring `MediaSink`
  (`pkg/agent/dispatch_request.go`); `ProcessRemoteDispatch` fills it;
  the ACP external runner reports nil (external agents can't be metered).
- Wire: `agentrpc.Request.WantUsage` / `Response.Usage` and
  `agenttask.Request.WantUsage` + the task record stores usage →
  `Response.Usage` on result. All `omitempty`, populated **only when
  negotiated**.
- Negotiation: `localCapability` sets `Allows["usage_report"]=true` (map
  key — additive-safe through old builds' re-marshal; see Decisions).
  Callers set `want_usage` only when the target's stored manifest
  advertises it; callees fill `usage` only when requested. Old↔new mixes
  produce today's wire bytes exactly.
- Surfaces: `rhizome mesh task result`, `network delegate|route|scatter`
  print a usage line when present; `mesh-tasks.jsonl` /
  `mesh-audit.jsonl` records; `mesh peer <id>` recent-task detail.
- Pin the load-bearing assumption with a fixture test: an old-struct
  (no `want_usage`/`usage` fields) marshal of a manifest/request carrying
  `Allows["usage_report"]` still verifies.

## Track 96 — enc2 key-store migrations (new)

Both at-rest key stores still seal with AES-256-GCM while `pkg/credential`
writes XChaCha20-Poly1305 (`enc2://`). This track migrates the two stores —
an AEAD swap, not the `enc2://` format (their key derivation is
`KeyProvider`, not passphrase+SSH-key HKDF; see Decisions).

- `NodeIdentity` (`pkg/rhizome/identity/store.go`) gains
  `Cipher string` (`""` = aes-256-gcm legacy, `"xchacha20poly1305"`) — the
  version-prefix scheme the queue item calls for. `encrypt`/`decrypt` in
  `identity/encrypt.go` dispatch on it; new writes seal via
  `chacha20poly1305.NewX`. Keyring/scrypt `KeyProvider` paths unchanged —
  they yield the 32-byte key either way.
- `walletKey` (`pkg/web3/keys.go`) gains a per-entry `cipher` field with
  the same scheme — entries can be mixed within one file; `walletEncrypt`/
  `walletDecrypt` dispatch per entry. A `walletFile.Version` bump is
  unnecessary when markers are per-entry (impl-time call — document the
  choice).
- Migration posture: transparent load → decrypt → re-encrypt on next
  write, the same one-way door as Track 82's `enc://`→`enc2://`; document
  that a downgraded binary cannot read migrated records.

## Track 89 — `rhizome mcp serve` (Rhizome as MCP server)

Rhizome consumes MCP today (`tools.mcp`, `pkg/mcp/manager.go` on the
vendored `modelcontextprotocol/go-sdk`) but cannot serve it. This completes
the interop triangle: ACP server (editors drive Rhizome), ACP client
(Rhizome drives external agents), MCP server (any MCP client drives
allowlisted Rhizome tools — Claude Desktop, Cursor, other agents).
go-sdk v1.6.1 server API verified: `mcp.NewServer(*Implementation,
*ServerOptions)` + `StdioTransport`.

- `pkg/mcp/server.go` (new): `mcp.NewServer` over the SDK's stdio
  transport; register tools from a freshly built `ToolRegistry` filtered by
  `tools.mcp_server.allow` (default empty = deny-all). Rhizome tool
  `Parameters()` is already JSON Schema — maps directly to MCP
  `inputSchema`; tool names pass through unchanged (they're already flat
  and namespaced: `web3_*`, `read_file`, …).
- `cmd/rhizome/internal/mcp/serve.go`: `rhizome mcp serve` — daemonless;
  builds the tool registry the same way other CLI paths do; errors out
  unless `tools.mcp_server.enabled`. stderr logging only — stdout is the
  protocol channel (the ACP stderr-drain rule applies here).
- Config: `tools.mcp_server = {enabled:false, allow:[...]}`. Agent-loop-
  dependent tools (`delegate`, `acp_run`, swarm verbs) are excluded by the
  allowlist shape, not special-cased.
- Smoke: MCP inspector or a second Rhizome with `tools.mcp` pointed at
  `rhizome mcp serve` — dogfoods both halves.

## Track 95 — Module trust tail (new)

Two deliverables — upstream signature verification where it exists, and the
llama.cpp tenant design:

- Catalog schema v3: optional per-release `signature {kind, url}` —
  `minisign`/`cosign-blob`/`gpg`. `installRelease` (`pkg/modules/
  download.go`) verifies the pinned digest AND the declared upstream
  signature; missing `signature` is not an error, declared-but-failing is
  fatal. The pinned digest remains the mandatory floor — signatures add
  provenance, not replace integrity.
- Scope to reality: survey which tenants publish verifiable signatures
  (nimbus/helios/kubo release assets — impl-time). If none do, the track
  ships the mechanism + a signed fixture test and documents the posture
  honestly rather than dead fields.
- `docs/design/llama-cpp-module.md` (design-only): symlink-safe
  layout-preserving extraction needs, the model-weights trust story
  (digest-pinned weights via module fields; where upstream hashes come
  from), the `ondemand` daemon shape, GPU/driver field sketch. Keeps the
  queued "design it standalone" posture.

## Track 90 — Signed curated skill index

A first-party `rhizome` registry provider in `pkg/skills`, signed like the
module catalog:

- `pkg/skills/rhizome_registry.go` (new provider via
  `RegisterRegistryProviderBuilder("rhizome", …)`): fetch `index.json` +
  `index.json.sig` from `registries.rhizome.base_url` (default: the
  `stpinkie/rhizome-skills` repo raw URL — impl-time detail: dedicated repo
  vs `docs/`-hosted file, decide with repo creation); verify Ed25519 via
  `modules.VerifyCatalogSignature` (extract the verify helper to a shared
  spot — `pkg/sigverify` or export-and-call, impl-time call); unsigned or
  bad-sig → refuse + warn.
- Index entries: `{slug, display_name, summary, version,
  source:{github:"owner/repo[@ref][/path]"}, sha256?}`. Install resolves
  `source` → delegates to the existing GitHub installer path (guard scan +
  provenance apply unchanged); optional `sha256` pins the bundle when the
  publisher supplies one.
- Cache the verified index under `<RHIZOME_HOME>/skills-index-cache/`
  (~1 h TTL, stale-serve on fetch failure — the `catalog-cache/` pattern
  from Track 70). Enabled-default matches clawhub's posture.
- Content: initial `rhizome-skills` index + signing via the existing
  `MODULE_CATALOG_SIGNING_KEY` secret; `docs/operations/
  skill-index-signing.md` mirrors `module-catalog-signing.md`. Hub UI gains
  a "curated" source badge (the violet Mesh-badge precedent).
- Events/audit: `skill.index.merged|rejected|stale` mirroring
  `module.catalog.*`.

## Acceptance criteria

- `go build -tags goolm,stdjson ./...` green; `go test -p 1 -tags
  goolm,stdjson ./...` green on touched packages; `golangci-lint` v2.13.2 →
  0 issues; `lint-docs.sh` OK; no new dependencies (binary-size delta ≈ 0).
- v0.11.0 and v0.12.0 tags pushed and releases verified (archives, GHCR
  pull, `rhizome version` in an artifact).
- Real stdio ACP drive (Zed or scripted client): mode switch mid-session
  changes permission posture (deny→prompt prompts again; allow→deny stops
  approving), emits `current_mode_update`, and survives `session/load`.
- Model config-option: lists `model_list` entries; switching affects only
  the calling session (a second session keeps the agent default); survives
  `session/load`; unknown ids/values error cleanly.
- External-agent auth: a mock/stdio agent advertising `env_var` auth
  authenticates when vars are present in `acp.env`, fails with a
  named-missing-vars error otherwise; `terminal` honored only under
  `terminal_policy=allow`; `agent` drives its own flow under allow and is
  refused clearly under deny.
- External-agent sessions: `persistent` mode reuses one session across two
  `acp_run` calls (verified via the mock agent's session count); media
  blocks reach an image-capable agent; `acp.mode` forwards when the agent
  advertises modes.
- Metering: a two-node task returns `usage` when both peers advertise
  `usage_report`, stays absent when unadvertised, and a mixed-version pair
  (new caller → old callee) completes a task with no signature errors.
- `rhizome mcp serve`: a real MCP client lists only allowlisted tools and
  can call one end-to-end; deny-all default proven (enabled=false → error;
  empty allow → zero tools).
- Skill index: signed index installs a skill end-to-end; tampered/unsigned
  index refused; stale-cache path serves on fetch failure.
- enc2: v0.12.0-era `node.json` + `keys.json` load and operate; new writes
  carry `cipher:"xchacha20poly1305"`; a re-saved legacy record migrates and
  the downgrade caveat is documented.
- Module trust: a declared upstream signature verifies and a failing one

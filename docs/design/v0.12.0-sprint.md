# v0.12.0 Sprint Plan — Agentic Web3

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **Web3 Stage 2 completes.** The agent gains a wallet, gated signing,
and a first-class contract-call surface — an ABI registry, `web3_contract_*`
tools, ERC-20/721 helpers, ENS — plus the operations depth that makes signing
usable day to day: dashboard approval/wallet panels, log watches, and
channel approvals (the last two are stretches). First, we cut v0.11.0 at its
merged scope.

## Framing correction

Sprint planning originally sketched a "mesh economy" arc (metered remote work,
price sheets, signed receipts, a bilateral ledger, on-chain settlement) as the
payload for the web3 rails. On review: **the mesh economy was never the point
of the web3 integration.** Web3 exists for agentic operations on-chain —
wallet management and contract calls under operator policy. The economy idea
is deferred to an optional module (`docs/design/mesh-economy-module.md`);
nothing economy-shaped lands in core mesh this sprint. Its one durable
finding — remote task responses carry no usage report — is recorded in the
seed doc as a real gap independent of billing.

## Decisions

- **No `go-ethereum`** (carried): secp256k1 + Keccak-256 + RLP + minimal ABI
  only — `dcrec/secp256k1/v4` and `x/crypto` are already in the module graph.
  Record binary-size delta per dep-adding track (+15% warn / +30% fail gate).
- **Signing approval is async** (carried): the pending-approval queue is the
  mechanism — tools return `pending_id`, humans resolve via CLI/daemon API/UI;
  `hook.approve_tool` gets first pass; timeout/cancel → deny.
- **`web3_rpc` stays read-only.** All state-changing paths go through the
  policy+pending-gated tools (`web3_send`, `web3_contract_send`, ERC-20/721
  writes). The passthrough allowlist in `pkg/web3/methods.go` does not grow
  send/sign/subscription methods — gated tools are the *only* write surface.
- **Contract surface is registry-backed but not registry-bound.** Contract
  args resolve `0x` literal → ABI-registry label → ENS name; raw
  `to`+`data` calls still work without an ABI. Policy `allow_methods`
  accepts `"<label-or-addr>:<method-name>"` alongside raw `0x` selectors —
  names resolve to selectors via the registry at eval time, so a readable
  allowlist (`usdc:transfer`) is enforceable, not just display sugar.
- **Signer scoping is a first-class policy dimension.**
  `tools.web3.signing.from_addresses` bounds which local addresses may sign —
  an agent cannot drain an imported cold address by naming it `from`.
- **Channel approvals are scope-bound and off by default.** Approving from an
  IM channel is convenient and dangerous; `tools.web3.approval_channels[]`
  lists the only channel/chat scopes whose `/web3` commands are honored
  (default empty = CLI/UI only). Stretch.
- **Mesh economy → optional module, seed only.** Recorded as a one-page design
  seed + `.todo.md` queue line; no metering/price/receipt code this sprint.

## Track 77 — Web3 wallet + gated signing (carried v0.11.0 Track 69)

Spec carried unchanged from `docs/design/v0.11.0-sprint.md` — it was already
at implementation depth; summary:

- `pkg/web3/keys.go` — secp256k1 keys (`dcrec/secp256k1` v4, promote
  indirect→direct), Keccak-256 addresses (`x/crypto/sha3`
  `NewLegacyKeccak256`). Store `<RHIZOME_HOME>/web3/keys.json` (dir `0700`,
  file `0600`): per-key AES-256-GCM under a wallet master key in the OS
  keyring (`go-keyring`, account `web3-wallet`), passphrase fallback via
  `RHIZOME_WALLET_PASSPHRASE` + scrypt (the `pkg/rhizome/identity`
  KeyProvider posture — needed on headless Linux). import/generate; `reveal`
  gated behind `--confirm` + masked output.
- `pkg/web3/abi.go` — minimal ABI codec: `MethodID(sig)` (keccak256[:4]),
  encode/decode for address/uint\<M\>/int\<M\>/bool/bytes/string/bytesN +
  dynamic types covering ERC-20 (`transfer`/`approve`/`balanceOf`/
  `decimals`/`symbol`) + ERC-721 basics; table-tested vs published spec
  vectors (`transfer` = `0xa9059cbb`, `approve` = `0x095ea7b3`).
- `pkg/web3/rlp.go` — minimal RLP encode (~100 lines). No dep.
- `pkg/web3/tx.go` — `TxRequest{To, ValueWei, Data, GasLimit, GasFeeCap,
  GasTipCap, Nonce, ChainID}`; EIP-1559 (type `0x02`) + legacy fallback;
  ECDSA sign over keccak256(sigPayload) w/ EIP-155 `v`; broadcast via
  `eth_sendRawTransaction`; nonce via `eth_getTransactionCount(addr,
  "pending")`; gas via `eth_estimateGas` + `eth_maxPriorityFeePerGas` +
  latest `baseFeePerGas`. Keys never leave the box.
- `pkg/web3/policy.go` — `tools.web3.signing = {enabled:false,
  allow_contracts:[], allow_methods:[], max_value_wei_per_tx,
  max_value_wei_per_day, chain_ids:[], from_addresses:[]}`; `Evaluate(req)` →
  allow / deny-with-reason; spend ledger `<RHIZOME_HOME>/web3-ledger.jsonl`
  (append-only `0600`, rotate ~10 MB × 3 — the `mesh-tasks.jsonl` pattern).
  Daily cap sums UTC-day sends. *v0.12.0 delta vs the v0.11.0 spec:*
  `from_addresses` joins the policy fields (Track 79 decision — signer
  scoping lands with the policy engine, not after).
- `pkg/web3/pending.go` — approval queue, `<RHIZOME_HOME>/web3-pending.json`
  (bounded ~100, expired pruned on read, atomic write). Entry `{id,
  created_at, expires_at, kind: send|sign|approve|contract, chain_id, from,
  to, value_wei, data, selector, summary, status, tx_hash, error}`. Daemon
  owns resolution when running; daemonless CLI last-writer-wins documented.
- Tools in `pkg/tools/web3/signing.go`: `web3_send`, `web3_sign` (EIP-191),
  `web3_approve` (ERC-20 convenience), `web3_wallet` (addresses+balances;
  never key material), `web3_pending`, `web3_send_status`. AND-gate on
  `tools.web3.enabled && signing.enabled` in `IsToolEnabled`.
- CLI `cmd/rhizome/internal/wallet/` (`rhizome wallet create|import|list|
  reveal`, daemonless) + `cmd/rhizome/internal/web3/` (`rhizome web3
  pending|approve|reject`). Daemon `pkg/gateway/web3api.go` (`GET
  /web3/pending`, `POST /web3/approvals/{id}`) + launcher `/api/web3/*`
  proxies + pending badge. Events `web3.pending|approved|rejected|sent|
  failed` → activity feed + audit.
- **Canary posture:** `signing.enabled` defaults false; docs testnet-first.

## Track 78 — Contract interaction (ABI registry + contract tools + ERC-20/721 + ENS)

The agent-facing call surface: contract calls by *name* instead of raw
calldata, common-token helpers, and name resolution.

- **ABI registry** `<RHIZOME_HOME>/web3/abi/` (dir `0700` — ABIs are public
  data but the web3 dir stays uniform): `<label>.json` holding `{label,
  address?, chain_ids?, abi:[…], added_at}` — bounded ~200 files, ~512 KB
  per file, labels match `^[a-zA-Z0-9][a-zA-Z0-9_.-]{0,63}$`. CLI `rhizome
  web3 abi add <label> <file> [--address 0x…] [--chain-ids 1,11155111]` /
  `abi list` / `abi show` / `abi remove` (`cmd/rhizome/internal/web3/`).
- **Address resolution** (`pkg/web3/resolve.go`): contract args accept `0x…`
  literal → registry label → ENS name, in that order. Shared by every
  contract tool; `allow_contracts` entries may also use labels (normalized
  to addresses at eval time).
- `web3_contract_call {contract, method, args[]}` (`pkg/tools/web3/
  contract.go`) → resolve → ABI method lookup by name + arg count
  (overloaded names with arity mismatch → clear error listing candidates)
  → encode via Track 77 `abi.go` → `eth_call` → decode outputs → JSON.
  Read path — no approval.
- `web3_contract_send {contract, method, args[], value_wei?}` → same
  encode → `policy.Evaluate` → pending-approval → sign+broadcast. Uses
  Track 77 machinery end-to-end; pending entries record `kind:"contract"`,
  the resolved selector, and a human summary (`usdc.transfer(0x…, 5e6)`).
- **Policy upgrade**: `allow_methods` entries of form
  `"<label-or-addr>:<method-name>"` resolve to selectors via the registry at
  eval time; raw `0x` selectors still match contracts without an ABI.
  Unknown contract + no selector match → deny.
- `web3_erc20 {action: balance|allowance|transfer|approve, token, to?,
  owner?, spender?, amount}` and `web3_erc721 {action: ownerOf|balanceOf|
  tokenURI|name|symbol|transferFrom, token, …}` — embedded minimal ABIs (no
  registry needed); write actions route through `web3_contract_send`'s
  policy+pending path. Amounts are decimal strings against `decimals()`
  for ERC-20.
- `web3_ens {name}` forward resolve + `{--reverse 0x…}` (`pkg/web3/ens.go`
  + `pkg/tools/web3`): `eth_call` to the ENS universal resolver; namehash
  computed locally (keccak per label — the Track-77 `sha3` dep). Chain-gated
  to networks with a deployed resolver — resolver addresses per chain are
  an impl-time verification item; unsupported chains error clearly.
- Events `web3.contract.call|send|rejected` → activity feed + audit;
  `web3_pending`/`web3_send_status` cover contract sends unchanged.

## Track 79 — Wallet & operations depth

- Wallet management: `rhizome wallet set-default <addr>` / `rename <addr>
  <label>`; `web3_wallet` marks the default; `from` defaults to the wallet
  default so agents don't have to carry addresses.
- Daemon wallet endpoints: `GET /web3/wallet` (addresses, labels, default —
  never key material) beside Track 77's `GET /web3/pending` +
  `POST /web3/approvals/{id}`; launcher `/api/web3/*` proxies with file
  fallbacks for reads (addresses/pending are local files).
- **Dashboard** (`web/frontend/src/components/web3/` + `web/backend/api/
  web3.go`): wallet card (addresses, labels, default, balances via
  `eth_getBalance`), pending-approvals panel (list + approve/reject → POST),
  tx status view (`web3_send_status` data). Same card/panel idiom as the
  Modules and Browser pages.
- **Stretch 1 — log watches:** `tools.web3.watches[] = {name, contract,
  topics?, interval_seconds}` — bounded ~8 watches, interval floor 30 s.
  Daemon poller on `eth_getLogs` (the nimbus proxy has no subscriptions —
  polling is the only option; lookback capped by `max_log_range`) →
  `web3.event` runtime events → activity feed. `web3_watch` tool
  (list/add/remove) is read-gated; watch definitions persist in config.
- **Stretch 2 — channel approvals:** `/web3 pending|approve|reject` handled
  in `pkg/commands` for scopes in `tools.web3.approval_channels[]`
  (channel + chat-id allowlist; default empty). Anti-spoof posture: the
  command is honored only from an allowlisted scope, and every channel
  resolution writes the same `web3.approved|rejected` event + audit line
  as a CLI/UI approval.

## Track 80 — Mesh depth (carried v0.11.0 Track 73, unchanged)

- Role-aware `rankedCandidates`/`PickPeer` behind `mesh.routing.role_aware`
  (`RoutingConfig` under `MeshConfig`, non-omitempty bool like
  `NATTraversal`; default true): worker bonus ~`1<<19` — below the
  direct-conn term `1<<20` so a down/full-capacity worker still loses to a
  healthy full; infra ops prefer `full`.
- Coordinator preference: `Role` on `pingPayload` (additive — older peers
  ignore it; swarm payloads sign raw bytes so inner fields are safe) +
  `Member`/`MemberInfo`; `capProbeFunc` extends to return `cfg.Mesh.Role`
  via `Mesh.Role()` (ripples: `queue.go`, `SetCapProbe` in
  `pkg/gateway/swarm.go`); `reelectLocked` = `sort.SliceStable` on
  `(roleRank, peerID)`. Mixed-version election flap is transient and
  documented (advisory duties only).
- Topology panel: `web/frontend/src/components/network/topology-panel.tsx` —
  hand-rolled SVG radial fed by `/api/network/status` `peers[].conns`;
  direction → arrow/dash, transport → edge color, latency → thickness,
  `role` → badge; click-through to the peer-detail `Sheet`; no new JS dep.
- Cost/token-aware dispatch is **not** in this track — that belonged to the
  deferred economy; the seed doc carries it.

## Impl-time verification checklist

- ERC-20/ABI edge vectors; EIP-1559 fields vs the nimbus proxy's supported
  tx types (baseFee presence; legacy fallback path).
- ENS universal-resolver address per supported chain (mainnet + sepolia?);
  whether the nimbus proxy serves the resolver's `eth_call` shape.
- Overload/arity semantics in the ABI codec (arg-count disambiguation is
  the v1 rule — type-aware resolution is a follow-up).
- `pkg/commands` dispatch surface for `/web3` (how channel commands reach
  the command layer; which scope metadata is available for the
  `approval_channels` check).
- Whether `eth_getLogs` on the nimbus proxy tolerates the watch poller's
  cadence/block range (proxy is a light client — log serving may be
  partial; cap lookback conservatively).
- `mcpServers` schema in the pinned ACP SDK + `session/load` replay
  semantics (carried from v0.11.0's checklist).
- Frontend: which existing page best hosts the wallet/approvals cards —
  new `/web3` route vs folding into an existing page (impl-time call;
  Modules/Browser card pattern either way).

## Risk register

| Risk | Mitigation |
| --- | --- |
| Signing ships real-money risk | `signing.enabled` default false; allowlist + caps + `from_addresses` + pending-approval mandatory; spend ledger; testnet-first docs |
| No built-in human approver outside ACP | Pending-approval queue (CLI + daemon API + UI panel); `approve_tool` hook gets first pass |
| Hand-rolled RLP/ABI/ENS-namehash bugs | Published spec vectors as table tests; minimal surface (ERC-20/721 + universal resolver) |
| Contract-arg ambiguity (overloads, label vs address vs ENS) | name+arity match with explicit ambiguity errors; documented resolution order |
| Channel approvals spoofing | `approval_channels` default empty; scope-bound auth; same events/audit as CLI; stretch only |
| Log-watch polling burns endpoint quota | Bounded watches (~8), ≥30 s interval, `max_log_range` lookback; stretch only |
| Dashboard expands frontend surface | Reuse card/panel idioms; panel half is a declared cut line |
| Track 77 is the critical path | Ordered first among code tracks; independent tracks flex; 78/79 degrade to reads-only if it slips |
| Sprint breadth (8 tracks, heavy 77) | Declared cut lines: 82 → 79 stretches → 79 dashboard → 80 topology |

# v0.20.0 Sprint Plan — Module Ecosystem

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **the catalog becomes an ecosystem.** The companion-module system
(v0.10.0 Track 60) shipped install + supervision; v0.11.0 added the signed
catalog and a curated remote index; v0.13.0/v0.14.0 deepened trust
(`signature` pins), wire access (`protocols` + the stream bridge), manifest
adverts (`ModuleAdverts`), and the v5 extraction machinery (`binary_path(s)`,
arch aliases, digest-pinned `fetch`). Seven tenants shipped — every one of
them operator infrastructure (Ethereum×3, IPFS, the market, llama.cpp×2).
What the system lacks is everything after "the binary is verified":

- **No lifecycle past install.** `rhizome module` can install, start, stop,
  and uninstall — but `module update` doesn't exist. The `<id>/current`
  version pointer exists; nothing moves it deliberately. Upgrading means
  uninstall + reinstall with no rollback, so operators run stale pins
  forever and a bad upstream release is unrecoverable.
- **Modules are opaque binaries.** The catalog knows how to *run* a module,
  not what it *provides*. Every consumer surface is hand-wired operator
  config: `module start llama-cpp` then a hand-written
  `openai-compatible` provider entry pointing at a hand-copied port (the
  llama.cpp design doc defers exactly this "consumer story" to impl time).
- **Tenants serve the operator, not the agent.** Nothing in the catalog
  extends the agent itself: no local speech-to-text (`pkg/audio/asr`
  already speaks the OpenAI transcription shape a whisper server would
  serve), no wrapped external agents (`agents.list[].acp` bindings have
  existed since v0.12.0 Track 81 but agents must be hand-installed — and
  the schema's `npm` install method is *declared but unimplemented* in
  `pkg/modules`), no module-shipped MCP servers.
- **Single-source discovery.** The embedded catalog plus at most one
  remote index verified against the baked-in release key; the market
  index is single-curator by the same shape (v0.16.0 Track 125 defers
  federation explicitly). A third party can run a signed index today only
  under the first-party key — federation is the difference between "a
  catalog" and "an ecosystem."

This sprint gives modules a real lifecycle (`update`/`rollback`), a
declarative `provides` contract so a module registers agent-facing
surfaces instead of inert binaries, the first agent-surface tenants
(whisper.cpp, wrapped ACP agents, an MCP server), federation on both
indexes, and the published spec that lets external authors ship modules
without a PR to this repo.

## Decisions

- **`provides` is declarative and type-keyed.** `ModuleSpec.Provides`
  gains a list of typed surface declarations — a module may declare
  several; consumers map by *type*, never by module id (no per-tenant
  logic in core). v1 types: `openai_compatible` (chat/embeddings
  endpoint template + `models_hint`), `openai_audio` (transcription
  endpoint), `acp_agent` (agent id + argv/env template + runtime/policy
  defaults), `mcp_server` (stdio command template + tool allowlist).
  Unknown types are ignored by older builds — the reserved-type registry
  lives in the Track 178 spec. Emit-when-set, so v6 is declared only
  when an entry actually uses it (the `catalogVersionRequired` gate
  keeps v5-era builds clean).
- **`module://` is the consumer contract.** A provider `base_url` of
  `module://llama-cpp` resolves through the catalog's provides endpoint
  template against the module's resolved field values — never a
  hand-copied port. Resolution is read-only: a disabled/stopped module
  yields a provider-construction error naming the module, not a silent
  cloud fallback. Opt-in `module_autostart` on the binding starts an
  ondemand module on first use — default **off**, because a multi-GB
  weights fetch triggered by an agent call is an operator decision, not
  a surprise.
- **Generated config is owned config.** Agent-facing surfaces
  materialize configuration: an `acp_agent` provide writes a generated
  `agents.list` entry, `mcp_server` writes a `tools.mcp` entry. Module-
  owned entries are marked generated, disable/uninstall with the module,
  and collide fail-closed — a hand-written binding with the same id is a
  config error naming it, never a silent merge.
- **npm via `npm pack`, never `-g`.** The `npm` install method becomes
  real as `npm pack <pkg>@<exact-version>` → verify the tarball against
  the registry-published `dist.integrity` sha512 recorded in the release
  pin → extract under `<id>/<version>/` → the package `bin` resolves via
  the existing binary path logic. Exact versions only — no ranges, no
  `latest`. Honest-limits documented: registry TLS + integrity pin is
  the same trust class as github-release + sha256. Node presence is a
  detect precondition with a clean error.
- **Update keeps the pin floor.** `module update` = install the newest
  catalog pin + flip `current` + restart-if-running. Nothing ever
  auto-updates. Remote-index refresh is best-effort (offline → embedded
  pins only). `module rollback` flips `current` back — fields, secrets,
  and `fetch`ed artifacts live outside `<version>/`, so rollback never
  re-downloads weights. Retention keeps the two newest versions and GCs
  older ones on update — never the running one, never `current`.
- **Federation pluralizes; it doesn't democratize trust.** `module_index`
  gains `indexes[] {name,url,pubkey}` — each index is independently
  key-pinned (a non-first-party index *requires* an inline pubkey; the
  release key remains the first-party default — no key discovery, ever).
  Merge precedence: embedded > earlier index > later index; first wins
  an id collision, with a logged warning. The existing singular `url`
  maps to `indexes[0]` for back-compat.
- **Market-index federation mirrors it module-side.** `market_index_*`
  fields pluralize to `market_indexes[]`; per-publisher keys, merged
  dedup by provider peer id, and an `unvetted` provenance marker on
  non-first-party entries everywhere they surface.
- **No new libp2p protocols, no bundled runtimes, no new Go deps.**
  `npm pack` unpacking rides `archive/tar`+`gzip`; Node and Docker stay
  external detects.

## Track 171 — `module update` / `rollback` + version retention (core)

- `rhizome module update <id>`: refresh the remote index (best-effort) →
  resolve the newest pin → install to `<id>/<version>/` → flip `current`
  → restart if running. `--check` reports pending updates without
  writes; `--all` walks installed modules.
- `rhizome module rollback <id>`: flip `current` to the previous kept
  version; restart if running. Fields, secrets, and `fetch`ed artifacts
  are module-dir scoped, so rollback never re-downloads.
- Retention: keep the two newest version dirs; GC older on update (never
  `current`, never the running one). `uninstall` still removes the whole
  module dir.
- `Info` gains `installed_versions` + `update_available` (populated only
  when the index is reachable). Managed methods only (`github-release`,
  `npm`) — `detect`/`config` installs report but never update.
- Daemon endpoints mirror the verbs (`POST /modules/<id>/update`,
  `/rollback`, `GET /modules/updates`); CLI works daemonless for
  non-running modules.
- Tests: install→update→current flip, rollback fidelity, GC bounds,
  offline update = embedded pins, update-when-not-installed error.

## Track 172 — Catalog schema v6: `provides` + `module://` provider surface (core)

- `ModuleSpec.Provides []ProvideSpec` — emit-when-set; v6 only declared
  on entries that use it (old builds gate on `catalogVersionSupported`).
  v1 types per the Decisions section; unknown types ignored forward-
  compat.
- `module://<id>` `base_url` resolution: the provider factory gains a
  resolver seam (interface); the daemon/agent wiring resolves via
  `modules.Manager` — endpoint template expanded against resolved fields,
  module must be catalog-known + enabled; stopped → error naming the
  module + the `module start` remediation.
- `module_autostart` opt-in on the binding (default off).
- `module status <id>` lists declared surfaces + their resolved targets.
- `llama-cpp` / `llama-cpp-vulkan` gain `provides` —
  `base_url: module://llama-cpp` becomes the documented zero-config
  local-inference path.
- Tests: resolution across enabled/disabled/stopped states, template
  expansion, autostart opt-in only, v6 gating on a provides-bearing
  entry vs v5-compat on the rest.

## Track 173 — `whisper-cpp` tenant + `openai_audio` provide-type (tenant)

## Acceptance criteria

- `go build -tags goolm,stdjson ./...` green; `go test -p 1 -tags
  goolm,stdjson ./...` green on touched packages; golangci-lint v2.13.2
  → 0 issues; `lint-docs.sh` OK; no new Go deps, no new libp2p
  protocols.
- v0.14.0–v0.19.0 released + verified.
- `module update` installs the newest pin, flips `current`, and restarts
  a running module; `rollback` restores the prior version with
  fields/secrets/fetched weights intact; `--check` writes nothing;
  detect/config installs report but never update.
- `base_url: module://llama-cpp` serves chat with zero manual provider
  config; a disabled/stopped module errors naming it; autostart is
  opt-in only.
- `whisper-cpp` installs, fetches digest-verified weights, and
  transcribes a fixture clip entirely locally.
- An enabled `acp_agent` module materializes a working binding
  (delegate/route reach it), disables cleanly, and conflicts
  fail-closed; `npm pack` artifacts verify against pinned integrity;
  missing Node → clean error.
- Federation: multi-index merge precedence holds; per-index signatures
  enforced; collisions first-win + logged; offline falls back to
  embedded.
- `module-catalog.md` matches the implementation (conformance-checklist
  test over reserved provide-types).
- Release: docs updated, `config.example.json` validates, release notes
  + tag.

## Impl-time verification checklist

- whisper-server's actual endpoint shape — OpenAI-compatible
  `/v1/audio/transcriptions` vs native `/inference` → real adapter vs
  honest deferred-compat doc.
- `gemini-cli`'s real ACP flag (`--acp` vs `--experimental-acp`) and
  whether a `@zed-industries/*-acp` adapter packages better.
- `npm pack` `dist.integrity` details (sha512, subresource syntax) and
  whether a `npm_registry` field is needed for mirrors.
- `current`-flip atomicity on Windows and running-module update order
  (stop → flip → start vs flip-then-supervised-restart).
- Generated-binding storage model — a generated config section vs an
  in-memory overlay. Prefer real config writes so daemonless reads see
  the bindings too.
- Whether `provides.acp_agent` needs `session_mode`/`auth_method`
  fields or rides binding defaults.
- The `module://` resolver seam — `providers.CreateProviderFromConfig`
  has no `modules.Manager` handle today; define the interface and who
  wires it (gateway vs agent loop).
- `models_hint` → `mesh.advertise_models` auto-derivation — tempting,
  keep out of v1; record.
- Index fetch bounds and refresh cadence — match the market index's
  1 h cache / stale-serve posture for consistency.
- Schema v6 gating — confirm `catalogVersionRequired` marks only
  provides-bearing entries v6 so v5-era builds keep installing the
  rest.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Wrapped agents run with ambient operator privileges | Generated bindings ride `acp.runtime` exec/sandbox/container + permission/terminal policies; docs recommend `container` for third-party agents; provenance marked generated |
| npm supply chain weaker than digest-pinned GitHub releases | `npm pack` + pinned `dist.integrity` sha512 + exact versions only; honest-limits doc; never ranges/`latest`/`-g` |
| `module://` resolution fails mid-agent-loop | Resolution at provider construction; error names the module + remediation (`module status`/`start`); autostart off by default |
| Autostart pulls multi-GB weights on an agent call | Opt-in per binding; start failure = provider error, never silent cloud fallback |
| Index federation → id shadowing/collision attacks | Embedded > ordered precedence; per-index pinned keys; first-wins + logged; no key discovery |
| Third-party index fetch becomes a telemetry channel | HTTPS GET of the index document only — no client metadata; documented |
| Schema v6 rejected by old builds | `provides` is emit-when-set; the version gate marks only v6-using entries |
| `update` flips `current` under a running module | Stop → flip → start; supervised restart; version dirs immutable once written; rollback never re-fetches |
| Smoke CI flakes on upstream asset rot | Advisory posture, never a merge gate — detection is the point |
| Generated bindings corrupt hand-written config | Owned-entry marking; same-id conflict fails closed; disable/uninstall removes cleanly |

# v0.21.0 Sprint Plan — Agent Surfaces

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **the catalog's agent-facing half grows up.** v0.20.0 ("Module
Ecosystem") gives modules a lifecycle (`update`/`rollback`), a declarative
`provides` contract (schema v6: `openai_compatible`, `openai_audio`,
`acp_agent`, `mcp_server`), `module://` resolution, the `npm pack` install
method, the first agent-surface tenants (`whisper-cpp`, `gemini-cli`), index
federation, and a published spec. What it does not ship:

- **The surface set is four types.** Voice output, image generation, and
  JSON-RPC endpoints have no provide-type — `pkg/audio/tts` still requires a
  hand-configured cloud key (`providerFromModelConfig` returns nil without
  `APIKey`), and `pkg/web3` hand-wires its module lookups (override →
  `ethereum-rpc` fields → nimbus probe) instead of reading declared surfaces.
- **No way to know a surface works.** `module start` + a health probe say the
  process is up; nothing verifies the *agent-facing contract* — that
  `/v1/models` lists models, that an `acp_agent` answers `initialize`, that a
  declared endpoint speaks the protocol it claims.
- **The queued tenants are unstarted.** `claude-code-acp`, `codex-acp`, piper
  TTS, and image-gen ports all sit in the v0.21.0+ queue — each a packaging
  exercise plus, for piper/image, a new consumer surface.
- **Recorded defers.** `models_hint` → `mesh.advertise_models` derivation was
  deliberately kept out of provides v1 ("record" in v0.20.0); `npm_registry`
  for mirrors is an open field question.
- **TEE posture is a dead pointer.** `attestation.report_url`/`evidence_hash`
  advert fields ship (v0.16.0 Track 131) but nothing serves them — the design
  doc's roadmap "Next" step is a challenge-bound seller-side report.

This sprint widens the provide-type vocabulary, ships the queued tenants, adds
the operational tooling a surface-bearing catalog needs (`module probe`),
retires the hand-wired web3 resolver onto declared surfaces, lands the
recorded `models_hint` defer, and takes the next honest TEE step — serving
evidence, still without claiming verification.

## Decisions

- **New provide-types are vocabulary, not a schema bump.** `openai_tts`,
  `openai_images`, `ethereum_rpc`, and `skill` are values inside the v6
  `provides` list — emit-when-set, ignored by v0.20.0-era builds
  (forward-compat fixture pins this). `catalogVersionRequired` stays v6
  unless impl-time review finds the gate counts values, not versions.
- **Every new surface gets a probe.** The probe registry is keyed by
  provide-type, not by module — `module probe` never grows per-tenant code.
  Probes are operator-invoked, bounded-timeout, never automatic (a probe
  that runs a TTS synth or an ACP `initialize` spends resources; the
  scheduler doesn't get to spend them).
- **The web3 rewrite is a parity exercise, not a redesign.** Legacy implicit
  precedence (override → `ethereum-rpc` fields → nimbus probe) maps onto
  declared `ethereum_rpc` surfaces; fixtures assert byte-identical resolution
  for existing configs. `tools.web3.endpoint` additionally accepts
  `module://<id>` — new capability, old configs untouched.
- **Module-shipped skills ride the skill provenance pattern.**
  `.skill-origin.json` gains `origin_kind:"module"` + `module:<id>` — the
  `mesh:` provenance shape applied to a local source. Install is
  guard-scanned exactly like a mesh pull; disable/uninstall removes the
  skill. No skill ships executable hooks in v1.
- **`models_hint` stays a hint.** Derivation marks manifest adverts as
  hint-sourced; a Track-184 probe result (`models_seen`) supersedes it where
  available. Hints never masquerade as a verified model list — the honest
  marking is what makes derivation safe.
- **TEE groundwork serves evidence; it verifies nothing.** Track 191
  implements the `report_url`/`evidence_hash` serving side plus a buyer-side
  fetch-and-record — the doc's boundary stands: no collateral fetch, no
  chain verification, no attested execution, and no claim language that
  implies any of them.
- **No new libp2p protocols, no bundled runtimes, no new Go deps** without
  per-track justification — Track 191's quote-source helper is the only
  candidate and prefers a `detect`-method helper over a vendored dep.

## Track 183 — Provide-type registry expansion (core keystone)

- `ProvideSpec` type vocabulary gains (emit-when-set, unknown types ignored
  by older builds — the forward-compat fixture is the acceptance test):
  - `openai_tts {endpoint, models_hint?, voices_hint?}` — OpenAI

  - `ethereum_rpc {endpoint, chain_hint?}` — a JSON-RPC endpoint the web3

    Track 189).
- Resolution seams per type: `module://<id>` accepted as `base_url` on TTS
  and image model entries (the v0.20.0-172 resolver seam, new consumers),
  and in `tools.web3.endpoint` (Track 187 wires the path).
- `module status <id>` surfaces every declared provide-type with resolved
  targets — extends the 172 status listing.
- Generated-config ownership posture identical to v0.20.0: module-owned
  entries, same-id collisions fail closed, disable/uninstall removes.
- Tests: catalog validate per new type; old-build ignore fixture;
  `catalogVersionRequired` behavior pinned.

## Track 184 — `rhizome module probe` (core)

- `module probe <id> [--type <t>]`: runs the per-type checks against
  resolved surfaces — `openai_compatible` → `GET /v1/models`;
  `openai_audio`/`openai_tts` → endpoint-shape check (+ a bounded synth
  fixture for tts at impl-time if cheap); `openai_images` → endpoint-shape
  check; `ethereum_rpc` → `eth_chainId`; `acp_agent` → ACP `initialize`
  handshake (spawn under the module's declared runtime); `mcp_server` →
  `tools/list`; `skill` → load + `pkg/guard` scan.
- Results persist as `last_probe {at, per-type ok|fail|skipped, detail}` in
  module state; `module status` renders them; daemon endpoint
  `POST /modules/<id>/probe` + launcher proxy; CLI daemonless for stopped
  surfaces where the probe doesn't need a running module.
- Bounded timeouts per check; one failure never aborts the others; probes
  are explicit-only (no scheduler, no autostart trigger).
- Tests: each prober against a fixture server/fake; timeout bounding;
  failure isolation; status rendering.

## Track 191 — TEE-evidence groundwork (module/design)

  (buyer-side verify) stays out.

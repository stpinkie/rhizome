# v0.16.0 Sprint Plan — Market Graduation

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **market graduation.** v0.14.0 shipped the Open Agent Work Market
*experimental* — fixture settlement rail default, direct-peer discovery via
signed-manifest `ModuleAdverts`, bound-but-unverified escrow. This sprint is
the graduation arc queued at both prior revisions: real discovery tiers
(curated index + DHT rendezvous), reputation plumbing, a verified escrow
contract with the **recorded two-node testnet E2E as the graduation gate** —
and, per the megaplan decision, **all four Stage-D horizon items pull in**:
session drawdown settlement, decentralized arbitration, TEE/attestation
(design + posture), and portable signed reputation.

End-state definition: the market is **testnet-verified, still experimental** —
the recorded E2E proves the rails on Sepolia; docs drop "unverified" but keep
the experimental marking. Mainnet deploy remains out of scope.

## Decisions

- **The bridge gains non-splice request/response actions.** The module
  stream bridge today is byte-splice only (`bridgeHello{token, action:
  dial|accept, peer, protocol}`). This sprint adds `dht_provide`, `dht_find`,
  and `peer_score` actions that return a JSON response instead of splicing —
  one token-gated loopback seam, many verbs. Rejected alternative: a second
  module API listener — the bridge already owns the loopback + per-module
  token + protocol-allowlist posture; duplicating it buys nothing.
- **Reputation writes go through the daemon, never shared files.**
  `PeerScoreStore` is owned by the mesh; a module writing
  `peer-scores.jsonl` directly risks concurrent-writer corruption and format
  coupling. The `peer_score` bridge action is the write path.
- **The graduated escrow contract is designed once, in Track 127** — its
  surface anticipates `release(sessionId, amount)` partials (drawdown) and
  ERC-792-style dispute hooks (arbitration) so later tracks extend bindings,
  not deployments.
- **One first-party curated index.** `stpinkie/rhizome-market-index`,
  catalog-signing-key pattern, CI-published. Federation is documented and
  deferred — resolves the design doc's open question "who signs; one index
  vs federated".
- **Drawdown via contract partial releases, not vouchers.** On an L2 gas is
  cheap; cumulative off-chain vouchers (Lightning-style) save gas but add a
  signature-verification path — documented as the rejected alternative.
- **Arbitration is a pluggable adapter.** `arbiter` field: `address` =
  designated (default, never removed) or `kleros:<court>` = ERC-792/1497
  escalation. Evidence = the `_rhizome.receipt` JSON + terms hash.
- **Portable reputation is additive evidence, not a ledger.** Buyer-signed
  attestations are carried by the seller (advert + index) and verifiable
  against the attesting peer id — but a seller can withhold negatives, and
  docs say so plainly. The operator's local score store remains the truth.
- **TEE/attestation ships design + posture only.** Advert schema + platform
  probe + verification docs; **no attested execution** this sprint.
- **The market stays marked experimental** after the E2E — "testnet-verified"
  is the graduation mark, not production-hardened. Mainnet is explicitly out.

## Track 124 — Market reputation substrate (core seam)

Market outcomes must reach `PeerScoreStore` without the module touching the
mesh's file — the seam is the bridge.

- `PeerScore` gains market-outcome fields riding v0.15.0-118's `OpStats`
  shape: op labels `market_buy`/`market_sell` carrying outcome counts +
  `session_id` refs + a `value_hash` commitment — **no raw amounts** in the
  score file (privacy posture: payment graph stays off the node's files).
- Bridge action `peer_score {peer, op, outcome, ref}`: token-gated,
  per-module allowlisted, bounded payload; daemon validates peer-id shape +
  outcome enum and writes via the mesh's store (rounds through
  `recordPeerCall`-equivalent semantics — market outcomes feed the same
  decay/rank math).
- Module side: after each session settles (release/claim/resolve), record
  the outcome; disputes record a pending marker resolved at `resolve`.
- `PeerScoreView` + `mesh peer <id>` surface the market split; `market
  sessions` (Track 133) cross-references it.

## Track 125 — Curated provider index (ops/infra)

The index is a repo, not a service — the module-catalog architecture cloned.

- `stpinkie/rhizome-market-index` repo: `index.json` +
  `index.json.sig` (Ed25519, curator key — the `MODULE_CATALOG_SIGNING_KEY`
  pattern), envelope `{signer, seq, expires_at}` + entries `{peer_id,
  addrs, offers, payout, runtime_posture, attestations[], manifest_sig}`;
  bounds 1 MiB / 500 entries.
- Publish pipeline: CI job validates schema + bumps `seq` + signs on tag;
  `docs/operations/market-index-signing.md` written from the
  `skill-index-signing.md` posture (key custody, rotation, revocation).
- Admission policy doc: who gets listed v1 (single first-party curator;
  federation deferred — the design doc's open question answered).
- The Track-103 generic index client already validates `sig` + caches —
  this track supplies what it points at; `market_index_url` default becomes
  the first-party index at graduation.

## Track 126 — DHT rendezvous tier `rhizome-market-v1` (core seam + module)

The unvetted discovery tier — Sybil-resistant curation is the index's job;
this is reachability when the index is down or a provider isn't listed.

- Bridge actions `dht_provide {ns}` / `dht_find {ns}` → daemon calls
  `Discovery`'s `Provide`/`FindProviders` on the namespaced CID
  (`rhizome-market-v1`); response JSON returns peer ids + addrs.
  Non-splice hello extension — same token gate + bounds; `ns` is a
  prefix-locked allowlist (`rhizome-market-*` only, not arbitrary CIDs).
- Module side: `market.dht` field (default **off**; requires host
  `dht.enabled` — documented hard dep) → serve advertises, buy queries.
- `market find` merge precedence: **index → DHT → cache**; DHT results
  carry the `unvetted` marker everywhere they surface (CLI + dashboard +
  docs).
- Loopback fixture: two nodes, provide → find → connect, mDNS/NAT isolated
  per the networked-test rules.

  (reentrancy, window arithmetic, refund path, arbiter key custody).

## Track 128 — Session-drawdown settlement (Stage-D)

Funded sessions instead of per-task escrows — the real settlement UX win.

- Module fields: `escrow.settlement = per_task|drawdown` (default
  per_task), `session_budget`, `draw_interval`.
- Flow: `open` once with budget → each task's `_rhizome.receipt` triggers
  a partial `release(sessionId, amount)` → session `close` refunds the
  remainder; module-side drawdown ledger + enforcement against
  `buy_max_cost_per_{task,day}` (both rails check the same caps).
- Contract side uses 127's partial-release surface; fixtures cover
  partial-release sequences, budget exhaustion, dispute mid-drawdown.
- Rejected alternative documented: cumulative off-chain vouchers (seller
  claims latest on-chain once) — gas savings don't justify the extra
  signature-verification path on cheap L2s.

## Track 129 — Decentralized arbitration (Stage-D)

The arbiter slot becomes pluggable: designated → Kleros.

- `escrow.arbiter` accepts `address` (designated, default — never removed)
  or `kleros:<court>` (ERC-792/1497 escalation via the Track-101-surveyed
  binding; if the survey ruled Kleros undeployable, this track binds the
  next-best adapter or cuts).
- `dispute` on an arbiter-bound session escalates: fees paid per the
  arbiter's model (documented), evidence = the `_rhizome.receipt` JSON +
  terms hash via `submitEvidence`, ruling maps to `sellerBps` at `resolve`.
- Dispute-desk ops doc: filing, evidence format, timeline expectations,
  fee responsibility.

## Track 130 — Portable signed reputation (Stage-D)

Completion attestations a provider can carry across buyers and meshes.

- Attestation schema: `{provider_peer_id, session_id, outcome, terms_hash,
  task_hash, issued_at, buyer_peer_id, signature}` — buyer-signed, node key.
- `market attest <session_id>` issues one (buyer-side, **opt-in** — never
  automatic; the buyer's signature is evidence they choose to give).
- Sellers carry newest-N (~32, bounded) in `advert.json.attestations` +
  index entries (125's schema has the slot); `market attest verify`
  validates signature → peer id → terms/session hash chain.
- Write path: sellers register received attestations locally; buyers record
  issued ones via the `peer_score` bridge verb (124).
- Honest-limits doc: attestations are **additive evidence** — a seller can
  withhold negatives; they raise confidence, they are not the ledger.

## Track 131 — TEE/attestation (Stage-D; design + posture; first cut line)

## Track 132 — Recorded two-node testnet E2E (the 104 tail; graduation gate)

The sprint's proof artifact — deferred twice before; here it's the gate.

- On Sepolia, two real nodes: `market buy` → ERC-20 `approve` + `open` →
  session (prompt → result) → `_rhizome.receipt` verify → `release`.
- `dispute` → arbiter `resolve` split (adapter path if 129 landed;
  designated arbiter otherwise).
- Seller `claim` after the dispute window lapses.
- If 128 landed: a drawdown session (open-once, two task settlements,
  remainder refund).
- **Tx hashes recorded in `.todo.md` acceptance notes** — the v0.12.0 E2E
  convention.

## Impl-time verification checklist

- `bridgeHello` non-splice actions: request/response framing inside the
  4 KiB hello bound vs a response line on the same conn — pin the shape in
  the first track to touch it (124).
- `PeerScore` market fields: `OpStats` op labels vs a dedicated
  `MarketOutcomes` map — confirm the v0.15.0-118 shape this rides.
- Index entry schema: does `attestations[]` belong in the signed index
  entry (curator re-signs on updates?) or fetched peer-side — pick at 130.
- `release(sessionId, amount)` vs `releaseWithPercent` for arbitration
  splits — 127's contract design must serve both 128's partials and 129's
  rulings.
- Kleros adapter: confirm `MultipleArbitrableTokenTransaction` Sepolia
  address + fee model from the Track-101 survey before binding; fallback
  adapter documented if the survey ruled against.
- Drawdown: `close` refund path + dispute-during-drawdown semantics —
  settle before the E2E track runs it.
- `market.dht` + host `dht.enabled` interplay: `--no-dht` daemon → module
  gets a clean "dht disabled" error, not a hang.
- Bridge verb allowlist: `peer_score`/`dht_*` actions restricted to
  modules whose catalog spec declares them (new `ModuleSpec` field? or
  unrestricted-for-first-party — impl-time pick, record it).
- Whether `market attest` signatures chain to `web3` addresses or peer
  ids — peer ids recommended (node key signs; no on-chain cost).

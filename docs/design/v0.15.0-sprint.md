# v0.15.0 Sprint Plan — Mesh & Swarm Depth

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **mesh & swarm depth.** The v0.14.0 revision considered this work and
dropped it for market scope; this sprint picks it up whole. Three lanes:

1. **Dispatch depth** — routing and claiming that actually use the capability
   surface we already sign and exchange (models, skills, score, load), plus
   serve-side capacity controls so a saturated node fails fast instead of
   silently queueing work.
2. **Ops hardening** — the restart and lifecycle gaps: run records that say
   "running" forever after a daemon restart, offers that vanish on reboot,
   subtasks that can't express requirements, runs that can't be retried or
   cancelled, and no way to ask "is my swarm converged?".
3. **Observability depth** — the activity feed is a 200-entry memory ring and
   the peer score has no decay or per-op breakdown; this sprint persists the
   feed, adds filter/trace verbs, and makes scores honest about age and op.

The Open Agent Work Market tail — Track 105 (curated index + DHT tier +
reputation fields) and the Track 104 recorded testnet E2E — is **deferred a
second time**, to a market-graduation sprint (v0.16.0 candidate). This is a
recorded decision, not silent slippage: the market ships experimental in
v0.14.0 and nothing in this sprint depends on it.

- **Track 98** — module stream bridge + `acp.remote`: swarm/mesh diagnostics
  stay inside the existing protocols; no bridge interplay planned.
- **Track 99** — `Capability.ModuleAdverts` (emit-when-set): the

- **Track 109** — llama.cpp module: requirement-aware dispatch is what makes
  a local-model node *findable* by model advert; the two compose but do not

- Track numbers are monotonic and never reused; v0.14.0 consumed 97–111, so
  this sprint runs **112–122**.

Tracks that slip in v0.14.0 prepend the v0.15.0 queue ahead of these tracks —
the standing slip policy. Cut lines below assume the slip-free case; a large
slip revises the sprint like the v0.14.0 mid-implementation revision did.

## Decisions

- **Requirements are hard filters over existing manifest fields.**
  `Requires{Models, Skills}` matches against `Capability.Models`,
  `Capability.Skills`, `Capability.ShareableSkills`; a manifest that omits a
  class never satisfies a requirement for it — strict-by-construction, same
  posture as `swarm offer --require-*` (which evaluates real local resources
  via `CapMatcher`). No new `Capability` struct fields: per the `Role`/`Role`
  precedent, a new field makes a node's manifest unverifiable to the whole
  pre-change fleet, and nothing here needs wire-level novelty. Operators
  who want requirement-filtered routing set `advertise_models`/
  `advertise_skills` — documented in the guide, enforced by a clear
  "no capable peer" error.
- **Explicit-peer verbs get no requirement flags.** `delegate`, `spawn`, and
  `network task` take a peer multiaddr — there is no pick to constrain.
  Requirements live on `route`, `scatter`, and the failover candidate list
  inside `SubmitRemoteTaskWithPeer`.
- **Capacity rejection is a distinct class, failover-steering.** A saturated
  callee rejects with `"capacity: ..."` — `isFailoverRetryable` today treats
  `StatusRejected` errors as retryable-by-default (the substring list only
  covers policy rejections), so same-peer retries would burn attempts on a
  busy peer. The track adds the class and makes it skip same-peer retries,
  moving straight to the next ranked candidate.
- **The serve-side cap bounds *running* work, not queue length.** The
  existing `maxStoredTasks` eviction (which today can cancel *running* tasks
  on overflow) stays as a backstop; `mesh.max_concurrent_tasks` makes the
  steady-state bound explicit and rejectable.
- **Offer persistence replays via `retryOffer`, not a resume protocol.** On
  restart, persisted open offers re-broadcast with `Attempt++` — members
  already treat a bumped attempt as a fresh offer, so the re-drive reuses
  proven machinery. Offers observed (not published) are not persisted: the
  offerer's own retry/TTL handles them.
- **`prefer_connected` election is opt-in.** Coordinator candidacy stays
  roster-deterministic by default; excluding not-currently-connected members
  trades a little convergence purity for never handing the pen to a node we
  can't reach. Default off; the diagnostics (Track 117) show you *why* the
  coordinator is stale without changing election semantics.
- **Score decay is gradual, never a cliff.** Counts halve per idle half-life
  (`mesh.score_half_life`, default 7 days) — a peer that was good a month ago
  ranks above a never-seen peer but below an actively-good one. Persisted
  decay state applies at `Get`/`Ranked` read time so the file format is
  append-only-compatible.
- **No new Go dependencies; no new libp2p protocols.** The diagnostics verb
  reuses `MsgQuery`/`MsgQueryResp`; the activity log is a JSONL sibling of
  `mesh-audit.jsonl`; blob resume is a frame-level addition inside
  `/rhizome/blob/1.0.0` (peers that don't implement it see a clean fallback).
- **Integration CI is advisory, like `test-parallel`.** A weekly +
  dispatch-only workflow running the integration scripts; it never gates a
  PR — the flake-hunt posture, upstreamed into a cron.

## Track 113 — Requirement-aware mesh dispatch (core)

The pick path currently matches agent id + `Allows` only
(`capabilityServes`, `pkg/rhizome/mesh/mesh.go`); `Models`/`Skills`/
`ShareableSkills` are signed into manifests but never consulted.

- `type Requirements struct{ Models, Skills []string }` in `pkg/rhizome/mesh`
  (a mesh-local type — not the swarm `OfferRequirements`, though the shape
  deliberately mirrors it; conversion helper if needed).
- `PickPeer`/`PickPeerRanked`/`rankedCandidates`/`SubmitRemoteTaskWithPeer`
  gain the parameter (or a `RemoteCall.Requires` field that flows through —
  impl-time pick; the call-struct route keeps signatures stable).
- `capabilityServes` gains the requirement check: for each requested class,
  the manifest's corresponding list must intersect non-empty. Absent class
  → unmatched (see Decisions).
- CLI: `--require-model` / `--require-skill` on `mesh route` and
  `mesh scatter`; `FanoutRequest.Requires` so scatter branches filter
  identically; `RemoteCall.Requires` steers failover candidates.
- Agent-facing surface: the `delegate`/`spawn` tool gets an optional
  `requires` arg only if it stays a thin pass-through — impl-time call.
- Ranking is unchanged: requirements filter the candidate set *before*
  scoring; a requirement never reorders within it.

## Track 114 — Inbound capacity controls (core)

`handleTaskSubmit` accepts every well-formed submit and spawns a task
goroutine; the 256-entry store bound evicts *running* tasks on overflow
(`taskstore.go` `evictLocked`), so a churning trusted peer can cancel real
work. This makes the bound explicit.

- `mesh.max_concurrent_tasks` (default 8): the global cap on non-terminal
  remote tasks; `mesh.acl[].max_concurrent` per-peer override (negative =
  unlimited, the `rate_limit` precedent).
- Saturated → reject with `"capacity: node at N/N remote tasks"` (per-peer
  variant `"capacity: peer at M/M"`). The class is a stable `"capacity:"`
  prefix, not a new status — wire-compat is untouched.
- Caller side: `submitRemoteTask` already maps rejections to errors; teach
  the retry loop that a `capacity:` rejection skips remaining same-peer
  attempts and falls through to the next ranked candidate — it is *not*
  added to `nonRetryable` (failover should still try other peers).
- `ActiveTasks` in the manifest already steers picks; saturated peers drop
  naturally once pickers see the count. No manifest change.

## Track 115 — Swarm claim scoring + subtask requirements (swarm)

- `resolveOffer` currently picks the least-`ActiveTasks` claim
  (`queue.go`); rank claims by (offerer's `PeerScoreStore` score desc,
  `ActiveTasks` asc, claim order) instead. New seam:
  `Swarm.SetScoreLookup(func(peer.ID) (mesh.PeerScore, bool))` wired in
  `pkg/gateway/swarm.go` to `m.PeerScore`. Claimants with no score record
  rank below any scored peer — new members must earn claims.
- `Claim.CapDigest` stays advisory: surface it (and the resolved score) in
  `swarm offers --json` claim detail so operators can *see* the pick
  rationale — `OfferInfo` gains a `Claims []ClaimInfo` view (published
  offers only).
- `Subtask` gains `Requires *OfferRequirements`, `Tools []string`,
  `Model string`, `Timeout time.Duration`; `RunGoal` forwards all of them
  into `OfferRequest` (today it drops everything but `AgentID`/`Task`);
  `depsFailed`/`planWaves` unchanged.
- Decomposer prompt (`pkg/gateway/swarm.go`) documents the new subtask
  fields; `parseSubtasks` passes them through (tolerant parser already
  handles unknown-but-wellformed fields).

## Track 116 — Restart reconciliation + run lifecycle (swarm ops)

- `runStore.Load` sweeps records still `status:"running"` → `"interrupted"`
  at startup (the `TaskStore.Load` "daemon restarted" precedent) +
  `swarm.run.interrupted` event.
- Published-offer persistence: non-terminal entries of `q.offers` serialize
  to `swarm-offers.jsonl` (bounded ~256, the taskstore posture); `Start`
  loads them and re-drives each via the existing `retryOffer` path with
  `Attempt++` — claimants treat the bumped attempt as fresh per the
  duplicate-suppression rule already in `onOffer`. Offers whose TTL elapsed
  while down land `expired` directly.
- `swarm run-cancel <run-id>`: cancel all pending/offered subtasks through
  `CancelOffer`; run record → `cancelled`.
- `swarm run-retry <run-id>`: re-offer subtasks in `failed`/`expired`/
  `dead_letter`/`timeout` whose `depends_on` all resolved `done`; creates a
  new `RunRecord` with `retry_of` linking to the source run. `run-status`
  prints the linkage.
- `OfferInfo`/`RunRecord` JSON shapes stay additive (new fields only).

## Track 117 — Coordinator & roster diagnostics (swarm ops)

- `SwarmInfo` gains `last_state_write` (coordinator-side) / epoch age —
  enough for `swarm status` to answer "is coordination fresh?".
- `rhizome swarm doctor <id>`: `MsgQuery` every known member (bounded to
  `max_members`, per-peer 5s timeout), diff rosters — members we know vs
  members who list us — report coordinator reachability and per-member
  epoch if returned (additive `queryRespPayload` field — same additive-safe
  envelope precedent).
- `swarm.coordination.prefer_connected` (default false): when set,
  `reelectLocked` excludes members not currently connected; documented as
  an availability-over-determinism trade.
- No new envelope types; the verb consumes `MsgQuery`/`MsgQueryResp`.

## Track 118 — Observability: persisted feed, filters, trace, score depth

- Activity feed persistence: `mesh.activity_log` (default true) appends the
  same entries to `<RHIZOME_HOME>/mesh-activity.jsonl`, size-rotated like
  `mesh-audit.jsonl` (10 MB × 3). The in-memory ring stays the live tail;
  `mesh activity --since` reads back across restarts.
- Filters: `mesh activity --kind mesh.*|swarm.*|web3.* --peer <id>
  --swarm <id> --since <dur|rfc3339>`; daemon `GET /network/activity`
  gains the same query params.
- Trace verbs: `mesh trace <task-id>` (taskstore snapshot + audit lines +
  activity events, correlated by task_id/correlation_id) and
  `swarm trace <offer-id|run-id>` (offer lifecycle events + run record +
  audit). Pure read-path assembly — no new wire surface.
- `PeerScore` gains per-op counters (`OpStats map[string]OpStat` —
  delegate/spawn/task success+failure+latency) and read-time decay:
  `mesh.score_half_life` (default 168h) halves success/failure counts per
  idle half-life since `LastSeen`; `Score()` evaluates the decayed view.
  `PeerScoreView` + `mesh peer <id>` show the per-op breakdown.
- `recordPeerCall` carries the op label through (submit/result/cancel/
  delegate/spawn); stored JSON gains fields additively.

## Acceptance criteria

- `go build -tags goolm,stdjson ./...` green; `go test -p 1 -tags
  goolm,stdjson ./...` green on touched packages; `golangci-lint` v2.13.2 →
  0 issues; `lint-docs.sh` OK; no new Go dependencies.
- v0.14.0 released + verified (archives, GHCR pull, `rhizome version`).
- `--require-model`/`--require-skill` on route/scatter filter picks; a peer
  whose manifest omits the class is excluded; a satisfying peer is picked;
  unchanged wire format (no new `Capability` fields).
- Capacity: a callee at `max_concurrent_tasks` rejects `capacity:`, the
  caller fails over to a second peer without burning same-peer retries,
  and the rejection lands in audit + `mesh peer` score as a failure.
- Claim scoring: given two claimants, the higher-score one wins at equal
  `ActiveTasks`; `swarm offers --json` shows per-claim score/load detail.
- Subtask requirements: a `swarm run` whose decomposer emits
  `requires.models` routes that subtask's offer only to members matching.
- Restart: daemon restart marks running run records `interrupted`; a
  published open offer re-broadcasts with `Attempt++` and completes;
  `swarm run-cancel`/`run-retry` behave per spec including dep-gating.
- Diagnostics: `swarm doctor` reports roster asymmetry + coordinator
  reachability; `swarm status` shows epoch freshness.
- Observability: activity entries survive a restart via the JSONL log;
  filters narrow output; `mesh trace`/`swarm trace` print a correlated
  lifecycle; `mesh peer` shows per-op score split and decayed score.
- Blob resume: a restarted transfer completes byte-identical (fixture test);
  `mesh blobs` lists the store.
- Integration workflow exists, ran once green (advisory); upstream triage
  doc records the new sync ref.
- Docs: new/changed surfaces documented; `config.example.json` validates
  under the strict loader; release notes + tag.

## Impl-time verification checklist

- `Requirements` shape: mesh-local struct vs reusing swarm's
  `OfferRequirements` — confirm import direction stays clean
  (`pkg/rhizome/swarm` already imports `pkg/rhizome/mesh`; the type must
  live mesh-side or in a shared leaf to keep it so).
- `RemoteCall.Requires` field vs explicit pick-parameters — the
  call-struct route keeps `SubmitRemoteTaskWithPeer` signature stable;
  confirm `swarm`'s `TaskSubmitter` seam still fits.
- `capacity:` rejection string stability — it's the failover contract;
  freeze the prefix in `agenttask` or a shared const.
- `SetScoreLookup` seam signature — `func(peer.ID) (PeerScore, bool)`;
  `m.PeerScore` already matches.
- Offer persistence: serialize `trackedOffer`'s `info` only (channels
  rebuilt on load); confirm `Offer` is the persistable unit and claims
  don't need replay.
- `queryRespPayload` additive epoch field — additive-safe like `Role`'s
  emit-when-set rule for envelopes (omitempty only).
- Activity log rotation vs `auditLogger` — share the rotation helper or
  clone it; don't open-code a third rotator.
- Score decay read-time vs write-time — read-time keeps the JSONL
  append-only; confirm `Ranked`/`Get` both evaluate the decayed view.
- Blob resume verb: offset-resume inside the existing protocol vs a new
  frame type — impl-time pick, fixture-tested either way.
- `swarm doctor` per-member `MsgQuery` timeout and member-cap handling.
- Integration workflow: whether the integration scripts run headless on a
  bare Linux runner today (two local daemons, no external deps) or need a
  shim first — check before promising the cron.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Requirement filtering silently empties fleets where nobody sets `advertise_*` | Hard-filter documented; error message names the missing advert; `mesh status --peers` shows advertised classes |
| `capacity:` string drifts and failover regresses | Shared const + fixture test pinning both directions |
| Offer persistence resurrects stale offers forever | Persisted offers carry original `CreatedAt`; TTL-elapsed ones land `expired` on load, never rebroadcast |
| Score decay surprises operators ("my peer forgot me") | Half-life config + docs; decayed-vs-raw both visible in `mesh peer` |
| `swarm doctor` spam on big rosters | Bounded to `max_members` (32 default), 5s per-member timeout, one-shot verb |
| `prefer_connected` invites split-brain pens | Default off; docs describe the trade; deterministic election unchanged |
| New JSONL files grow unbounded | Same size-rotation posture as `mesh-audit.jsonl`; counts documented |
| Trace verbs correlate across rotated files | Trace reads current files only; rotation boundary documented |
| Sprint size (11 tracks) | Declared cut lines above; 112/113/115/122 never cut |
| Second market-tail deferral looks like drift | Recorded as an explicit decision in this doc + `.todo.md`; the market ships experimental in v0.14.0 by design |

# v0.17.0 Sprint Plan — Paired Settlement

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **paired-operator settlement — the trusted tier of the economy story.**
v0.14.0–v0.16.0 built the *untrusted* market: escrowed work between strangers,
graduating to a verified contract in v0.16.0. This sprint implements the
appendix seed in `docs/design/mesh-economy-module.md`: bilateral credit
ledgers between *paired* operators — peers joined through
`/rhizome/pair/1.0.0` who trust each other enough to swap invoices instead of
funding escrows. Mutual credit accrues per task; balances close out
periodically, either off-band (`ledger` backend — signed invoice exchange +
reconciliation) or on-chain (`web3` backend — a plain transfer to the peer's
manifest-signed payout address via the v0.12.0 wallet/policy/pending
machinery).

Why a separate tier instead of reusing the market rails: escrow exists
because strangers defect. Paired operators already share trust
(`mesh.trusted_peers`, signed manifests, replay-guarded envelopes); an escrow
per task is gas-burning overkill. The ledger tier is also the only shape that
makes sense for *continuous* mesh work — swarms and routine delegation — where
per-task on-chain settlement never fit.

Boundary with the market: `mesh.economy` meters the *internal* task
protocols (`/rhizome/agent/1.0.0`, `/rhizome/agent-task/1.0.0` — delegate,
spawn, task, route, scatter, swarm offers). Paid ACP sessions stay on the
`rhizome-market` module's escrow path; the two systems never share a ledger.

End-state definition: paired settlement ships **experimental** — real signed
charges, convergent bilateral ledgers, an auditable settle handshake, and an
optional web3 close-out; honesty limits (usage is callee-reported; a ledger
is bookkeeping, not consensus) documented plainly.

## Decisions

- **Paired settlement is core, not a module — deliberately inverting the
  market's packaging.** The market is opt-in stranger commerce and lives in
  `rhizome-market`; bilateral billing extends a trust surface the mesh
  *already owns* (trusted peers, signed envelopes, usage metering), and its
  write path (ledger, score store) is core state. Core carries it inert —
  a node has zero economy surface unless `mesh.economy.enabled` is set.
- **Billing is scoped by explicit peer allowlist, never implied by trust.**
  `mesh.trusted_peers` mixes an operator's own nodes with paired foreign
  nodes; charging your own fleet is bookkeeping noise. `mesh.economy.
  bill_peers` is the only thing that makes a caller billable — pairing
  establishes trust, billing is a second opt-in on top of it.
- **Wire fields are manifest-negotiated, both directions.** Request/
  response signatures re-marshal the decoded struct, so *any* new envelope
  field breaks verification on the far side's older build — the same
  constraint Track 94 solved by gating `want_usage` on `allows.
  usage_report`. This sprint clones that pattern: the caller sets
  `Request.Econ` only when the peer's signed manifest advertises
  `economy`; the callee emits `Response.Charge` only when the request
  carried `Econ`. Unnegotiated calls send byte-identical pre-sprint wire
  data. `Capability.Economy` itself is emit-when-set with the `Role`/
  `ModuleAdverts` posture — old builds reject the manifest wholesale, which
  is correct: a peer they can't price shouldn't be routed work anyway.
- **Charges are callee-computed, caller-verified.** The callee meters the
  run and returns `charge{unit, amount, usage, sheet_digest}` inside the
  already-signed response; the caller recomputes `sheet·usage` against the
  advertised sheet and compares `sheet_digest`. Mismatch → the ledger entry
  lands `disputed`, the score records a failure — the receipt is evidence,
  not trust.
- **Two new rejection classes, both failover-steerable.** `price_floor:`
  (the peer's minimum exceeds the caller's cap — pre-send refusal; callers
  move to the next ranked candidate like `capacity:`) and `econ:` (billing
  policy refusals — a `bill_peers` caller that didn't send `Econ`, a unit
  the callee won't accept). Stable prefixes, never new wire statuses.
- **The settle handshake converges both ledgers before money moves.**
  `/rhizome/econ/1.0.0` carries signed `settle_offer`/`settle_ack`/
  `settle_reject`/`ledger_query` frames — the payer proposes a cutoff +
  total, the payee verifies against its own receivables, and only then do
  both write `settled` markers. Divergence refuses cleanly; nothing marks
  settled unilaterally (except the documented `--mark-only` fallback).
- **`SettleBackend`, not `SettlementRail`.** The appendix's iface name is
  taken — `pkg/settlement.Rail` is the escrow lifecycle. The close-out
  abstraction is `pkg/rhizome/econ.SettleBackend` with `ledger` (mutual-
  credit marker exchange) and `web3` (transfer to the manifest-signed
  payout address) impls. The web3 path is a plain token transfer through
  the pending-approval queue — no escrow, no contract.
- **Amounts are decimal strings; math is `big.Rat`.** Units are freeform
  ("credits", "USDC") — the ledger stores canonical decimal strings,
  charge math accumulates in `big.Rat` (the Track-103 buyer-cap posture),
  quantization happens once at record time.
- **Swarm price is a filter, not an auction.** `Offer.MaxPrice` bounds
  which claims are eligible; `Claim.Quote` reports the claimant's sheet
  price; the pick ordering stays score-first (v0.15.0-115). Quotes are
  advisory honesty, not bidding.
- **Disputes stay operator-to-operator.** A paired-settlement dispute is a
  ledger state + a conversation — no arbiter, no fees. Contested work
  between untrusted parties is what the market tier exists for.

## Track 138 — `mesh.economy` config + `Capability.Economy` advert (core seam)

The foundation every later track reads.

- `MeshConfig.Economy`:
  `enabled, unit ("credits"), price_sheet{per_task, per_1k_prompt_tokens,
  per_1k_completion_tokens, per_second, min_charge}, accept_units[],
  bill_peers[], max_cost_per_task, max_cost_per_day, settle_threshold,
  settle_backend ("ledger"|"web3"), payout{chain_id,address,asset}` —
  strict-loader fields, validation (unit set when enabled; bill_peers
  entries decode as peer ids; payout required iff settle_backend=web3).
- `Capability.Economy` emit-when-set:
  `{unit, price_sheet, payout?, accepts[]}` — carries the *seller's* side
  publicly (sheet + destination); `accept_units`/`max_cost_*`/`bill_peers`
  stay private buyer-side policy. Fixture test pins the old-build
  re-marshal failure (the `Role`/`ModuleAdverts` precedent test shape).
- Pair-bundle economy block: `network pair --create` gains an optional
  `economy` payload (sheet + payout echo); `pair --accept` prints the
  counterparty's terms and offers to pre-fill `bill_peers`/`accept_units`
  — pairing becomes the natural moment the billing agreement is struck.
  Impl-time keep/drop inside the track; the bundle stays verifiable either
  way.
- `peeradverts` journal records `economy` alongside module adverts so the
  `mesh peer`/dashboard surfaces can show a peer's sheet without a live
  manifest fetch.

## Track 139 — Charge negotiation + signed charge fields (core wire)

The Track-94 pattern, applied to billing.

- `agentrpc.Request`/`agenttask.Request` gain `Econ *EconTerms` —
  `{accept:true, max_charge, unit}` — set only when the callee's manifest
  advertises `economy` (else the field stays absent → byte-identical
  request). `Econ` is signed inside the existing envelope; no new envelope
  type.
- `agentrpc.Response`/`agenttask.Response` (+ `TaskInfo`) gain
  `Charge *EconCharge` — `{unit, amount, usage, sheet_digest, truncated}` —
  populated only when the request carried `Econ` *and* the caller is in the
  callee's `bill_peers`. The response signature covers it; `charge.usage`
  carries the metered usage snapshot regardless of `want_usage`, so the
  receipt is self-contained evidence.
- Charge computation: `min(sheet·usage, req.econ.max_charge)`;
  `truncated:true` when the sheet price exceeded the cap (buyer pays the
  cap, seller signaled). Success-only — failed runs emit no charge.
- Rejection classes: callee refuses upfront with `price_floor:` when
  `sheet.min_charge > req.econ.max_charge`; refuses `econ:` when a
  `bill_peers` caller omits `Econ` (unaccepted billing = no free ride) or
  the `unit` isn't in the callee's sheet unit.
- Caller side: verifies `sheet_digest` against the cached manifest and
  recomputes `amount ≤ sheet·usage`; violations → `econ:charge_mismatch`
  caller-side error class + score failure.
- Tests pin both wire directions: negotiated-on ↔ fields present;
  unnegotiated ↔ byte-identical to pre-sprint encodings (the
  track94_test.go fixture posture).

## Track 140 — Bilateral ledger store (core)

`pkg/rhizome/econ` — the bookkeeping both sides keep.

- `economy-ledger.jsonl` under `<RHIZOME_HOME>`: entries
  `{ts, peer_id, direction: payable|receivable, task_id, correlation_id,
  unit, amount, usage, result_sha256, sheet_digest, state:
  accrued|settled|disputed|written_off, settle_id?, settle_tx?}` —
  size-rotated ~10 MB × 3 (the mesh-audit posture), atomic appends.
- Write hooks: callee records `receivable` when it emits `Charge`; caller
  records `payable` when a verified `Charge` arrives (async task path
  records on `result` retrieval). Both land `mesh.econ.charge` audit lines
  + `mesh.econ.*` runtime events.
- Balance views: per-peer `accrued − settled` in each direction, per-unit
  sums, day-window sums for `max_cost_per_day` enforcement (the store
  answers "committed in the last 24 h").
- `state` transitions: accrued → settled (Track 142/143) | disputed
  (`mesh economy dispute`) → resolved (`--credit` re-accrues / `--drop`
  writes off). Disputed entries never settle.
- Concurrent-writer rule mirrors the score store: the mesh owns the file;
  CLI verbs read it daemonless where possible, mutations go through the
  daemon API when it's running.

## Track 141 — `rhizome mesh economy` verbs (CLI)

- `rhizome mesh economy balance [peer]` — per-peer/unit accrued balances,

- `rhizome mesh economy ledger [--peer] [--since] [--state] [--json]` —

- `rhizome mesh economy invoice <peer>` — emit the signed settle proposal

- `rhizome mesh economy settle <peer> [--backend ledger|web3]

  `resolve <task-id> --credit|--drop` — dispute lifecycle on own entries.
- Mirrored under `rhizome network economy …` per the mesh/network verb
  convention.

## Track 142 — Settle handshake `/rhizome/econ/1.0.0` (core wire)

A small signed-envelope protocol — the pair/blob/skill precedent — so both
ledgers mark the same entries settled.

- Ops: `settle_offer {peer_id, unit, entries[] (task_id refs or a
  from..to cutoff), total, cutoff_ts, nonce, ts}` → `settle_ack
  {accepted, settle_id}` | `settle_reject {reason}` | `ledger_query
  {peer_id, unit, since}` → `ledger_view {entries_digest, balance}` for
  divergence checks.
- Flow: payer builds the offer over its accrued `payable` set → payee
  verifies the entries match its `receivable` set (task ids, amounts,
  digests) → both write `settled` markers keyed by a shared `settle_id`
  (hash of the offer). Mismatch → `settle_reject` + `econ:diverged`
  audit; operators reconcile via `ledger_query` view.
- Replay guard: nonce + timestamp inside the signature, per-peer bounded
  nonce cache — the standing mesh posture.
- No new dependencies; one protocol id; handler gated on
  `mesh.economy.enabled` + trusted peers (billed or not — a payee must be
  able to ack even between billing agreements).

## Track 143 — Web3 close-out backend (core)

`settle_backend=web3` turns the handshake into a real payment.

- Payer side: `settle` computes the balance, opens the Track-142 offer —
  and on `ack` sends `payout.asset` (ERC-20 transfer or native send) on
  `payout.chain_id` to the peer's **manifest-signed** `payout.address`
  through the existing machinery: `pkg/web3` policy evaluation →
  pending-approval queue (`web3-pending.json` — every close-out surfaces
  in the CLI/UI approval flow by default; `settlement_signer=wallet`
  reuse is an operator opt-in, same posture as the market).
- The settle offer gains an optional `tx_hash` field; the payee's ack
  path (or a `ledger_query` follow-up) lets the payee verify the transfer
  on-chain (`eth_getTransaction` + receipt status) before marking settled
  — verification is explicit in docs, not assumed.
- Payout staleness: the destination is re-read from the peer's *current*
  signed manifest at settle time; rotation mid-ledger settles to the
  current advert (documented).
- Fixtures: FakeChain serves `eth_getTransaction`/`eth_getTransaction
  Receipt`; E2E-shaped unit test covers offer→ack→transfer→verify→
  settled-markers on both sides.

## Track 144 — Cost-aware dispatch + `--max-cost` (core)

The pick path gets a price signal — the appendix's `est_cost` term.

- `RemoteCall.MaxCost` / `FanoutRequest.MaxCost` (decimal-string amounts in
  the callee's unit) + `mesh.MaxCostFor(peer)` resolution: caller-side
  cap = min(`--max-cost`, `economy.max_cost_per_task`).
- `rankedCandidates`/`PickPeer` order changes only for billed peers: the
  filter drops candidates whose advertised `min_charge` exceeds the
  caller's cap (`price_floor:`-eligible before a request is ever sent),
  and the rank adds a bounded cost term — cheaper advertised sheet ranks
  higher among score-comparable candidates (exact weighting is the
  impl-time checklist item; free peers are never *deprioritized* —
  absence of an economy advert means absence of a price, ranked as cost
  zero).
- CLI: `--max-cost` on `mesh route`, `mesh scatter`, `network delegate`,
  `network spawn`, `network task submit` — explicit-peer verbs need it
  too: the peer is fixed but the spend cap still binds the request's
  `Econ.max_charge`.
- The `delegate`/`spawn` agent tools gain an optional `max_cost` arg —
  thin pass-through, same as `requires`.
- `price_floor:`/`econ:` rejections slot into the Track-114 failover
  steering: skip same-peer retries, next ranked candidate.

- Wire-compat: `Offer`/`Claim` are additive-JSON envelopes inside the
  swarm protocol — new fields are omitempty; members on old builds
  ignore `max_price`/`quote` (claims proceed unpriced — documented).

## Impl-time verification checklist

- `Request.Econ` / `Response.Charge` field placement on the agenttask
  async path: `Charge` lives on `TaskInfo` + `Response.result` — pin
  which surface the async caller reads first.
- Whether `Econ.max_charge` zero-means-unlimited or zero-means-absent —
  pick the `rate_limit` precedent (negative unlimited, zero unset) or
  explicit nil; record it.
- `sheet_digest` scope: hash of the canonical `economy` advert block vs
  the whole manifest — the block is the cheaper stable target; confirm
  the canonical form matches `signCapability`'s input.
- Charge math quantization: `big.Rat` accumulate → single quantize at
  ledger write; decide the decimal-string precision (4 dp? per-unit?).
- Free-peer ranking: `est_cost` for a peer with no advert must not rank
  it *below* billed peers — absent price = cost zero, not unknown.
- `bill_peers` vs `mesh.acl[]` overlap: an acl rule restricting a peer's
  agents stays orthogonal to billing; validate no interaction.
- `settle_threshold` trigger surface: prompt on `balance` view + an
  event, not auto-settle — auto-settlement stays operator-initiated v1.
- Pair-bundle economy echo: whether `pair --accept` pre-fills config
  (writes `config.json`) or only prints suggested values — the strict
  loader + operator-consent posture favors print-then-confirm.
- `Claim.Quote` honesty: quote is the claimant's *advertised* sheet, not
  a negotiated price — nothing binds it beyond the charge-verify path
  already in 139.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Callee over-reports usage to inflate charges | Caller verifies amount ≤ sheet·usage and duration vs observed wall time; mismatches land `disputed` + score failure; honest-limits doc states usage is callee-reported |
| Ledger divergence (crashes mid-settle, clock skew) | Signed settle handshake converges entry sets before marking; `ledger_query` divergence check; `disputed`/`written_off` states; `--mark-only` documented as last resort |
| Wire-compat regression: econ fields leak to old builds | Manifest-gated negotiation (Track-94 pattern) + byte-identical fixtures pinned both directions; `economy` advert is itself fail-closed on old builds |
| Operators bill their own nodes accidentally | `bill_peers` is the only billing scope; own nodes simply aren't listed; docs call this out |
| Payment-graph privacy (web3 backend) | Aggregate close-outs (one tx per settle, not per task); payout address is manifest-signed; docs state the payment graph is public when web3 settles |
| spend caps bypassed via agent-initiated delegation | `delegate`/`spawn` tools inherit `RemoteCall.MaxCost`; day cap enforced in the ledger write path, not the CLI |
| Scope creep toward "real money" | The tier is explicitly bookkeeping-first: `ledger` is the default backend, disputes have no arbiter, settlement is operator-initiated; market stays the stranger-commerce tier |

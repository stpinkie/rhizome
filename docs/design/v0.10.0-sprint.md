# v0.10.0 Sprint Plan — Extensibility, Interop & Mesh Depth

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: a companion-module sidecar system (first tenant: a verified Ethereum
JSON-RPC proxy), Agent Client Protocol (Zed ACP) client + server, mesh
observability, and Track C footprint closure.

## Ordering & dependencies

Landed as one PR per track, in this order:

```
Track 60  pkg/modules companion-module system ──┐
Track 65  nimbus-verified-proxy tenant ──────────┘ (65 depends on 60)
Track 61  rhizome acp — ACP server ─────────────┐
Track 62  ACP client — external agent ids ───────┘ (62 shares pkg/acp + the SDK with 61)
Track 63  mesh observability (independent)
Track 64  footprint + worker tier (independent)
Track 66  docs & release (last)
```

Rationale: the module system is proven by its first tenant before more surface
area is added; the ACP server lands before the client so both share one
`pkg/acp` + SDK foundation; observability and footprint are independent and
flex around the big tracks.

## Decisions

- **ACP wire protocol:** `github.com/coder/acp-go-sdk` — typed schema,
  agent- and client-side connections, maintained and tracking the upstream
  ACP schema. All SDK usage stays inside `pkg/acp` so a future swap is
  internal. Pin a version ≥7 days old; record the binary-size delta in the
  Track 61 PR (the size gate warns at +15%).
- **First module tenant:** `nimbus-verified-proxy` (`status-im/nimbus-eth1`),
  not helios. It serves the same verified local execution JSON-RPC but ships
  linux/darwin/**windows** binaries; helios has no Windows asset and becomes
  a queued linux/darwin catalog entry. `ethereum-rpc` (config-only) is the
  zero-binary answer on any platform.
- **Module spec gains `platforms`** (`goos/goarch` list) — install/status
  report `unsupported` off-list. Needed by any future helios entry too.

## Track 60 — Companion module system

Generalizes the `pkg/browser` catalog + install-manager pattern into managed
sidecar binaries. Base binary stays lean; optional capabilities install under
`~/.rhizome/modules/`.

- `pkg/modules`
  - `catalog.go` — `ModuleSpec{ID, Name, Description, License, Kind: daemon|ondemand|config, Platforms, Install{Method: github-release|npm|detect|config, Repo, TagTemplate, AssetTemplate, OSAliases, Releases []ReleasePin{Version, Build, SHA256|SHA512{platform}}, Binary}, Run{ArgsTemplate, Env, Workdir}, Health{Type: tcp|http|jsonrpc, Target, Method}, ConfigFields}`.
    `ConfigField` mirrors `browser.AuthField` (`pkg/browser/catalog.go`) as an
    own type — no cross-package import.
  - `manager.go` — `Status` (`missing|installed|configured|unhealthy|stopped|running|unsupported`);
    `Install` (resolve platform asset → HTTPS GET → pinned digest verify →
    tar.gz extract to `~/.rhizome/modules/<id>/<version>/`, binary flattened
    to the version-dir root); `Uninstall`; `Logs(tail)` from bounded log files.
  - `supervisor.go` — daemon-kind lifecycle: auto-start `enabled` modules at
    boot, restart-on-exit with backoff (1s→30s, jittered), `StopAll` with
    TERM→grace→KILL, `module.install/start/stop/crash` events on the bus.
    Launch via `pkg/isolation.Start` with plain `cmd.Start` fallback when
    isolation is disabled or unsupported.
  - `state.go` — `module-state.json` per module (pid, version, started_at,
    restarts, last_exit) so `status` works while the daemon is down.
- Config: `modules.<id> = {enabled, …fields}` map section + defaults +
  `rhizome validate` coverage; secret fields join the sensitive-data cache
  so `FilterSensitiveData` masks them. Map sections are a new config shape —
  the `SaveConfig` write-back round-trip gets a test.
- CLI: `rhizome module list|status|install|uninstall|enable|disable|start|stop|logs <id>`.
  install/enable are local (fs + config write-back); lifecycle verbs proxy to
  the daemon via `daemonBaseURL()` (the `swarm offer` pidfile+token pattern)
  with on-disk fallback.
- Daemon: `GET /modules`, `GET /modules/<id>`,
  `POST /modules/<id>/{install,uninstall,start,stop,enable,disable}`,
  `GET /modules/<id>/logs?tail=N` — same mux registration block as
  `/network/*`; manager reaches the gateway via `gateway.SetModuleManager`
  (the `SetPairManager`/`SetSwarm` pattern). Startup wiring in
  `cmd/rhizome/internal/daemon/command.go`: supervisor starts after mesh/swarm
  wiring, `StopAll` runs before mesh teardown.
- Web: `/api/modules*` launcher proxy (daemon proxy + config-file fallback)
  and a `/modules` page (card grid à la Browser page).
- Security invariants: HTTPS-only downloads; a catalog-pinned digest
  (sha256 or sha512) is mandatory per platform — no fetched checksums files
  in v1; no user-defined download URLs; module dirs `0700`; secrets masked
  in logs/UI.

## Track 65 — `nimbus-verified-proxy` (first tenant)

- Catalog: `github-release` against `status-im/nimbus-eth1`; asset
  `nimbus_verified_proxy-<goos>-<goarch>-v{version}-{build}.tar.gz`. Asset
  names embed a commit-hash suffix; upstream publishes **sha512** sums in
  release-notes text (no checksums file) → `ReleasePin` carries
  `SHA256`/`SHA512` maps + `Digest(platform)`, and `InstallSpec.OSAliases`
  maps `darwin`→`macos` in `{goos}` asset expansion. Pinned v0.4.1
  (`ec214533`); install verified end-to-end against the real Windows asset.
- Platforms: linux amd64/arm64, windows amd64, macos arm64 — confirmed no
  darwin-amd64 asset exists upstream.
- Config fields (verified against `nimbus_verified_proxy_conf.nim`; the
  draft's `--web3-url`/`--rpc-port` guesses were wrong):
  `execution_api_url` (`--execution-api-url`, required, secret — untrusted
  EL RPC; provider URLs may embed keys), `beacon_api_url`
  (`--beacon-api-url`, required, secret — light-client data provider, missed
  by the draft), `trusted_block_root` (`--trusted-block-root`, required —
  bootstraps the LC), `network` (`--network`, default mainnet), `listen_url`
  (`--listen-url`, default `http://127.0.0.1:8545` — a full URL, not a port).
- Health: JSON-RPC `eth_chainId` POST to `{listen_url}`.
- `ethereum-rpc` sibling: `endpoint_url` (required) + optional `api_key`;
  config-only, no daemon.
- Scope guard: "just available" — **no agent tools** (Web3 Stage 2, queued).

## Track 61 — ACP server (`rhizome acp`)

Editors (Zed, JetBrains) drive Rhizome over stdio JSON-RPC.

- `pkg/acp/server.go` — implement the SDK's `Agent` interface behind
  `acp.NewAgentSideConnection(agent, os.Stdout, os.Stdin)`:
  - `initialize` → protocolVersion negotiation; `agentCapabilities`:
    `promptCapabilities` text (+image via resource_link where supported),
    `loadSession:false`, `mcpCapabilities` honored if per-session MCP wiring
    is cheap (verify `pkg/mcp`); `authMethods:[]` (local stdio).
  - `session/new` → Rhizome session key `agent:<agent-id>:acp:<uuid>` —
    the legacy explicit-key form, because `resolveScopeKey` only preserves
    `IsExplicitSessionKey` keys (an `acp:<uuid>` key would silently collapse
    onto the shared route session).
  - `session/prompt` → `AgentLoop.ProcessInbound` (new seam carrying the
    full `bus.InboundMessage`: media refs + explicit session key) on
    channel `acp`, chatID = sessionId. Streaming flows through the
    `bus.Streamer` delegate seam (`pipeline_streaming.go`), not runtime
    events — `agent.llm.delta` exists but is never emitted in production.
    The server installs itself as an in-process `bus.StreamDelegate`
    answering only for channel `acp`, and a suffix-diffing streamer turns
    accumulated provider output into `agent_message_chunk` /
    `agent_thought_chunk` updates. `agent.tool.exec_start/end/skipped`
    runtime events filtered by `Scope.SessionKey` → `tool_call` /
    `tool_call_update` notifications, correlated by a new `CallID`
    (`tc.ID`) field on the tool payloads. `stopReason` =
    `end_turn|cancelled`.
  - `session/cancel` → cancels the per-turn context.
  - `session/load`, `session/set_mode` — not advertised in v1.
- `pkg/acp/permission.go` — in-process `agent.ToolApprover` (the `ApproveTool`
  seam in `pipeline_execute.go`): approval requests on channel `acp` emit
  `session/request_permission` (allow-once / allow-always / reject-once /
  reject-always) → `ApprovalDecision`; `*_always` answers cache per tool per
  session. `acp.server.permission_policy` = `prompt|allow|deny`, default
  `prompt`; client error/timeout/cancel → **deny** (never auto-approve).
  `ToolApprovalRequest` gained `CallID` so the permission prompt and the
  tool-call updates share the provider's correlation id.
- `pkg/acp/session.go` — acp sessionId → rhizome session key + streamer +
  cached decisions + lifecycle.
- `pkg/acp/stream.go` — the `bus.StreamDelegate`/`bus.Streamer` bridge.
- `pkg/acp/events.go` — runtime tool-event → ACP tool-call bridge.
- `cmd/rhizome/internal/acp/command.go` — `rhizome acp [--agent <id>]`;
  builds the loop like `agentCmd` but keeps stdout protocol-clean:
  `main()` skips banner/TZ prints under `stdioProtocolCommand()` and the
  command calls `logger.DisableConsole()` before `LoadConfig` (diagnostics
  via `RHIZOME_LOG_FILE`). `--agent` injects a leading dispatch rule
  (`when.channel == "acp"`) so normal routing applies; model streaming is
  force-enabled in-memory and a process-local `Channels["acp"]` entry
  satisfies the channel streaming gate (no global channel type registered).
- Config: `acp.server.permission_policy` + `acp.client.permission_policy`.
- Docs: `docs/guides/acp.md` — Zed `agent_servers` + JetBrains snippets.
- Binary-size delta recorded in the PR: **+593,920 B (+0.57%)**.

## Track 62 — ACP client (external agents as agent ids)

`agents.list[].acp = {command, args, env, cwd}` binds an external ACP agent
(`gemini --acp`, `claude-code acp`, …) as a routable agent id.

- `pkg/acp/client.go` — `ClientManager` owns per-agent processes spawned via
  plain `exec.Command` (not `pkg/isolation`; the external agent needs its own
  fs/env — trust posture documented in the guide); `initialize` advertises
  `fs:{readTextFile,writeTextFile}` served by us through the workspace
  sandbox (`restrict_to_workspace` + allow_*_paths) and `terminal:false`;
  `session/new` per delegation; `session/prompt` → accumulate
  `session/update` → final text; `session/cancel` on ctx done; process reuse
  across delegations, respawn on connection loss.
- `pkg/acp/client_handler.go` — `acpsdk.Client` impl: streamed-text
  accumulation, sandboxed fs serving, permission-policy evaluation, terminal
  refusal. Registry/config resolved lazily (registry swaps on reload).
- External `session/request_permission` → `acp.client.permission_policy` =
  `deny`(default)|`allow-read-only`|`allow` (read-only = read/search/think/
  fetch tool kinds; `fs/write_text_file` is not advertised under it).
- `pkg/acp/spawner.go` — `Spawner implements tools.SubTurnSpawner`; chain
  in `pkg/gateway/gateway.go`: `remoteSpawner` → `acpSpawner` → `local`
  (or `acpSpawner` → `local` when mesh is off).
  `remoteSpawner.hasLocal(id)` stays true for ACP-bound ids (they're in the
  registry) so they never route off-box.
- **Correction to the draft:** remote peers delegate via `runFunc` →
  `agentLoop.ProcessRemoteDispatch`, which bypasses the spawner chain. The
  loop gains an `ExternalAgentRunner` seam (`SetExternalAgentRunner`) so
  ACP-bound ids resolve to the ACP client on that path too — otherwise remote
  delegation to an ACP id silently falls to local dispatch and fails.
- `pkg/tools/acp_run.go` — explicit one-off invocation of a configured ACP
  agent id (escape hatch); registered only when a `tools.ACPInvoker` is
  installed on the loop.
- Manifests advertise ACP-bound agents like locals (peer-bound to the host);
  remote peers delegate into them under existing ACL.
- Tests use a mock ACP stdio agent built on the same SDK (Track 61's server
  harness) — no real external agent needed in CI.

## Track 63 — Mesh observability

- `PeerStatus` (`pkg/rhizome/mesh/mesh.go`) gains `conns[]` {remote_multiaddr,
  direction, transport (quic|tcp|relay — detected via `/p2p-circuit` and
  `/quic` in the remote addr), stream count, opened_at},
  `latency_ms` (peerstore `LatencyEWMA`), `score` (from `PeerScoreStore`),
  `last_seen`.
- `libp2p.BandwidthReporter(metrics.NewBandwidthCounter())` wired into the
  host options in `pkg/rhizome/network/host.go`; totals + per-peer in/out
  rates surface on `NetworkStatus`/`PeerStatus`.
- Activity feed: bounded in-memory ring buffer (~200) of `mesh.*`/`swarm.*`
  events with timestamps (subscribed like `Mesh.TaskEvents`); `GET
  /network/activity?tail=N`; unified `GET /network/events` SSE;
  `rhizome mesh activity [--tail N]`; `rhizome mesh peer <id>` detail view
  (conns, score, caps, manifest fingerprints, recent tasks — daemon-required
  via `daemonBaseURL()`).
- `mesh status` gains conn/score columns. Launcher proxies
  `/api/network/activity` + `/api/network/events`. Frontend: peers panel
  transport/relay badges + score tooltips + detail drawer; new Activity panel
  (SSE with polling fallback). No graph viz — topology stays queued.
- In-memory only; `mesh-audit.jsonl` remains the durable trail.

## Track 64 — Track C closure

- `scripts/measure-footprint.sh`: stripped build; three profiles — one-shot
  CLI (`agent -m hi`), worker (`daemon --no-dht --no-gateway` with
  `mesh.role=worker`), full daemon; sample `/proc/<pid>/status` VmRSS ~60s to
  steady state + cold-start timing; JSON out → refresh
  `docs/architecture/footprint-audit.md`. (`.ps1` variant optional.)
- Worker tier: `mesh.role: "full"|"worker"` (default `full`). `worker` forces
  `dht_enabled=false`, `relay_service=false`, `nat_service=false` (role wins
  over explicit config; startup warn on contradiction). `role` joins the
  signed `Capability` **emitted only for `worker`** — the signature covers
  the re-marshaled manifest, so an always-present new field would fail
  verification on pre-v0.10.0 peers; a worker simply cannot be verified by
  them, which is fine because worker-aware consumers require this version.
  Surfaces in `PeerCapability`/status badges. Gateway stays a separate flag; docs pair
  `role=worker` with `daemon --no-gateway`. Seam noted for later role-aware
  `PickPeer`/coordinator preference (queued).

## Risk register

| Risk | Mitigation |
| --- | --- |
| acp-go-sdk API churn / dep weight | pin; isolate behind `pkg/acp`; report size delta |
| Module supervision on Windows is thin (no job objects) | document orphan behavior; `StopAll` best-effort kill |
| ACP-bound ids bypass local dispatch for remote calls | `ExternalAgentRunner` seam in `ProcessRemoteDispatch` |
| stdio protocol pollution by logs/prints | stderr-only logger in `rhizome acp`; audit print paths |
| Nimbus asset naming/hash suffix churn | per-release `ReleasePin` pins exact asset+sha256 |
| Scope creep (session/load, terminal cap, topology graph, web3 tools) | explicitly queued post-v0.10.0 in `.todo.md` |

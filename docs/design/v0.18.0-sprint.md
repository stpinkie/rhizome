# v0.18.0 Sprint Plan — Agent Autonomy

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **agent autonomy — self-evolution depth.** `pkg/evolution` shipped as a
closed loop: the hot path records turn outcomes, the cold path clusters them
into patterns, an LLM drafts skill updates, and `apply` mode writes them —
but `docs/architecture/agent-self-evolution.md` documents three honest gaps:
**no user-facing trigger or review surface** (the `manual` cold-path trigger
is reachable only from code; drafts quarantine silently; there is no `rhizome
evolution` verb tree at all), **a narrow local draft scanner** that
"does not reliably detect prompt injection", and **manual-only rollback** —
the `SkillVersionEntry.Rollback`/`RollbackReason` fields exist but nothing
writes or reads them.

This sprint opens that loop to the operator without loosening its safety
posture. Three lanes:

1. **Operator surface** — `rhizome evolution` verbs + daemon API: status,
   manual cold-path run, draft list/show/accept/reject, skill profiles,
   lifecycle, retention. The machine proposes; the human disposes.
2. **Safety hardening** — `pkg/guard` + `pkg/redact` wired into draft review
   (the scanner the doc admits is narrow), rollback verbs riding the existing
   backup machinery, apply-mode policy gates (`require_review`, rate cap,
   protected skills), provenance sidecars on evolved skills.
3. **Sharing + provenance** — evolved skills shareable over
   `/rhizome/skill/1.0.0` with `generated` provenance marking, and signed
   agent manifests gain an evolved-skill attestation so peers can weight
   machine-written skills accordingly.

End-state definition: an operator can run evolution entirely in `draft` mode
with confidence — every candidate visible, scannable, diffable, accept/
rejectable, and reversible — and `apply` mode becomes safe enough to leave on
behind a review gate. Auto-apply stays available but the sprint's posture is
**review-first by default**.

## Decisions

- **The operator surface is verbs-first, panel-later.** Evolution state
  already lives under `<workspace>/state/evolution` (`evolution.state_dir`
  override); read verbs (`status`, `drafts`, `draft show`, `skills`,
  `records`) work daemonless off the state dir — the ledger-read posture
  from v0.17.0. Mutations (`run`, `draft accept|reject`, `rollback`,
  `archive`, `prune`, `feedback`) go through daemon endpoints
  (`/evolution/*`) because the running agent owns cold-path scheduling and
  the applier — `daemon required` errors, not parallel writes.
- **`draft` mode is the honest default; `apply` earns it back through
  review.** Today `apply` auto-writes whatever survives `ReviewDraft`.
  Track 152 adds `evolution.apply_require_review` (default **true**):
  apply-mode drafts land `candidate` like draft mode and only apply on
  explicit `draft accept` — or when `false`, apply directly but still
  under the hardened scanner. The config's `AutoAppliesDrafts` semantics
  change only through that field; `mode:apply` +
  `apply_require_review=false` restores today's behavior exactly.
- **The scanner upgrade reuses `pkg/guard`, not a third scanner.**
  `ReviewDraft` gains guard passes: `ContainsPromptInjection` over
  `body_or_patch` + `human_summary`, the tool-arg scan pattern over
  structured draft fields, and `pkg/redact`'s secret-pattern set for
  credential-shaped substrings — findings land in `ScanFindings` with a
  `guard:`/`secret:` prefix so quarantines explain themselves. The local
  structural checks stay (they catch what guard doesn't).
- **Rollback rides the existing backup path.** `Applier` already
  snapshots before replace/merge; rollback adds a read of
  `VersionHistory` + restore + a `Rollback:true` history entry (the
  dormant fields' intended purpose). Rollback applies through the same
  validation path as apply — a restored skill is still a skill write.
- **Evolved skills are marked, never silently laundered.** Applied skills
  get `.evolution-origin.json` (the `.skill-origin.json` mesh precedent):
  `{origin_kind:"evolution", draft_id, pattern_id, applied_at, review}`
  — `accept` vs `auto` recorded. Sharing (156) carries the marker; pulled
  copies show `generated:true`. Peers weight machine-written skills
  accordingly; nothing hides provenance.
- **Feedback records inform, never cluster.** `RecordKindFeedback`
  entries join the evidence set the success judge and draft generator
  see (a user-marked-bad "success" is the highest-value signal the system
  can learn) but never become cluster members — one angry flag must not
  birth a skill.
- **No new Go dependencies; no new libp2p protocols.** Skill sharing uses
  the existing `/rhizome/skill/1.0.0` pull path; the manifest field is
  emit-when-set additive.

## Track 149 — `rhizome evolution` verbs + daemon API (core + gateway)

The documented gap, closed: a real operator surface.

- `rhizome evolution status` — mode, trigger, last cold-path run
  (run_id, workspace, admitted/processed counts), pending candidates,
  quarantined count, profile totals by lifecycle state; `--json`.
- `rhizome evolution run [--workspace|--agent X] [--all] [--dry-run]` —
  manual cold-path trigger (the `manual` mode finally reachable).
  `--dry-run` reports what *would* be drafted/applied without writes.
  Daemon endpoint `POST /evolution/run` → the agent registry's
  evolution bridge `Trigger`/`RunColdPathOnce` seam (new accessor —
  impl-time pick: expose `ColdPathRunner.Trigger` for async parity with
  `after_turn`, or a synchronous admin call; the verb waits for a run
  summary either way).
- `rhizome evolution drafts [--state candidate|quarantined|accepted]` +
  `evolution draft show <id> [--diff]` (renders the before/after for
  append/replace/merge — the review artifact operators actually need).
- `rhizome evolution draft accept <id>` / `reject <id> [reason]` —
  accept runs the full `Applier` path (backup + validate + write +
  profile sync + history entry); reject marks quarantined with the reason
  in `ReviewNotes`.
- `rhizome evolution records [--kind task|pattern|feedback] [--limit]` —
  the learning-record stream (bounded read).
- `rhizome evolution skills` — `SkillProfile` board: name, version,
  status, origin (evolved vs manual vs mesh), use count, retention score.
- Daemon: `GET /evolution/status|drafts|records|skills`,
  `POST /evolution/run`, `POST /evolution/drafts/<id>/accept|reject`;
  launcher proxies `/api/evolution/*` (the `/api/network/*` precedent).
- Read verbs work daemonless off `evolution.state_dir`; mutations require
  the daemon and error plainly otherwise.

## Track 150 — Draft-review hardening (core)

The scanner the architecture doc calls "a narrow guardrail" gets the
real one.

- `ReviewDraft` gains: `guard.ContainsPromptInjection` over
  `body_or_patch` + `human_summary`; the arg-scan idiom over structured
  fields (`intended_use_cases`, `preferred_entry_path`, `avoid_patterns`);
  `pkg/redact` secret-pattern scan for credential-shaped substrings.
- Findings land in `ScanFindings` prefixed (`guard:injection:…`,
  `secret:…`, `structure:…`) so `draft show` explains the quarantine.
- Policy fields on `EvolutionConfig`: `review_auto_quarantine` (default
  true — any guard/secret finding quarantines; structural warnings stay
  notes), `max_draft_bytes` (default 64 KiB — over-size quarantines),
  `review_min_confidence`? — impl-time drop if no honest signal exists.
- Quarantined drafts never self-recover: they surface in `evolution
  drafts --state quarantined` and only `draft accept --force` (explicit
  override, logged) or `reject` moves them.
- Tests: injection-shaped draft bodies quarantine; benign drafts pass;
  findings serialize to `drafts.json` entries readable by the CLI.

## Track 151 — Rollback + version UX (core)

- `rhizome evolution rollback <skill> [--to <version>] [--dry-run]` —
  restores the pre-apply backup (`Applier.backupCurrentSkill`'s artifact)
  or a named version's snapshot; writes a `SkillVersionEntry{Rollback:
  true, RollbackReason}` (the dormant fields' purpose); restored content
  re-validates through `validateAppliedSkillBody`.
- `rhizome evolution skills history <name>` — the `VersionHistory` view:
  version, action, draft link, rollback marks.
- Backup retention: bounded per skill (e.g. last 5 backups — config
  `evolution.backup_keep`, default 5); rollback beyond kept backups fails
  with the archived-path hint.
- Tests: apply→rollback→content-identical; `--to` picks the right
  backup; history records the rollback entry; missing backup errors
  cleanly.

## Track 152 — Apply-mode policy + provenance (core)

`apply` mode graduates from "trust the scanner" to gated.

- `evolution.apply_require_review` (default true): apply-mode drafts land
  `candidate` and apply only via `draft accept`; `false` restores direct
  auto-apply. `AutoAppliesDrafts` consults it.
- `evolution.apply_max_per_day` (default 3): auto-applies beyond the cap
  park as candidates — rate-limiting model-written writes even without
  review.
- `evolution.protected_skills []` (optional, cut line): named skills are
  never auto-applied over — `create`-adjacent names collide safely, and
  append/merge/replace onto a protected target needs `draft accept`.
- Applied skills write `.evolution-origin.json`:
  `{origin_kind:"evolution", draft_id, source_pattern_id, applied_at,
  review:"accept"|"auto"}`. `SkillProfile.Origin` gains `evolution`.
- Tests: require_review gates apply mode; day cap parks; protected target
  refuses auto-apply; origin file + profile field written.

## Track 153 — Lifecycle + retention ops (core)

Skill profiles already carry `active|cold|archived|deleted` and
`RunLifecycleOnce` runs inside the cold path — this surfaces and bounds
it.

- `rhizome evolution skills archive <name>` / `restore <name>` — manual
  lifecycle transitions through `ApplyLifecycleState`.
- `evolution.retention_{task_records_days,drafts_days}` (defaults 90/30):
  `RunLifecycleOnce` additionally prunes expired records/drafts; bounded
  store growth stops being an implicit assumption.
- `rhizome evolution prune [--dry-run]` — manual sweep, reports counts.
- Tests: transitions serialize; retention prunes old records but never
  unsettled drafts or accepted-history entries.

## Track 154 — Feedback signal records (core; flex)

Explicit user signal is the cheapest accuracy upgrade the loop can get.

- `RecordKindFeedback` records: `{signal: good|bad, linked_record_id|
  session_key, reason?}` — written by `rhizome evolution feedback
  <good|bad> [--session KEY] [--reason "…"]` (defaults to the last
  turn of the current/most-recent session) and an optional in-session
  `/feedback` affordance.
- Feedback records never cluster; they join the judge's evidence input —
  a `bad`-linked task record drops out of admitted records even when its
  status was `completed`; a `good` mark lifts its pattern's confidence
  inputs (documented weighting — impl-time detail).
- Bounded: feedback entries share the record retention window (153).
- Tests: feedback record shape + linkage; `bad` flag excludes the task
  from admitted set; clustering ignores feedback records.

## Track 156 — Evolved-skill sharing + manifest provenance (core + mesh)

  `.evolution-origin.json` into the served bundle → add to
  `mesh.skill_share` (with an operator-visible note: sharing publishes
  machine-written skill text to trusted peers).
- Pulled evolved skills keep the origin marker; `skills list` /
  `mesh skill` surfaces show `generated` provenance — the pull-side
  guard scan is unchanged (it already treats remote bundles as

- `agentmanifest.Manifest` gains an emit-when-set `evolved_skills`

- Honest-limits doc paragraph: evolved skills are LLM-authored prompt
  text — reviewed by the operator who generated them, not endorsed by

## Impl-time verification checklist

- The bridge seam for `POST /evolution/run`: `ColdPathRunner.Trigger`
  (async, after_turn parity) vs a synchronous admin `RunColdPathOnce` —
  pick synchronous-with-timeout for the CLI's run-summary UX, record it.
- Multi-workspace addressing: `--agent` vs `--workspace` flag semantics
  when one agent's workspace hosts another's state dir.
- `draft show --diff` rendering for `create` (no base) and `merge`
  (three-way) kinds — fall back to full-text display where a diff is
  meaningless.
- Whether `reject` deletes the draft body or quarantines it — the audit
  posture favors quarantine-with-reason; confirm the store supports a
  terminal `rejected` state vs reusing `quarantined`.
- `.evolution-origin.json` field name alignment with `.skill-origin.json`
  (`origin_kind` values: `evolution` vs the mesh's `mesh`) — keep the
  schema identical so both markers parse with one reader.
- `evolved_skills` manifest summary shape: count+digest vs name list —
  digest bounds manifest size; name list is friendlier. Pick at impl.
- `feedback` linkage when `--session` is omitted: "last turn" resolution
  must be per-workspace; confirm the record store can answer it cheaply.
- `protected_skills` matching: exact name vs prefix — exact only,
  documented.
- Whether `evolution run` in `observe` mode is a no-op (today's early
  return) or an explicit "observe mode produces no drafts" message —
  prefer the message; silence reads as breakage.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Operator surface invites `apply` complacency | `apply_require_review` defaults true; apply mode unchanged only behind an explicit flag; day cap bounds unreviewed writes |
| Guard findings false-positive on legit drafts | Findings are structured + shown in `draft show`; `accept --force` override exists and is logged — review, not refusal |
| Rollback restores a draft that quarantines today | Restores pass through `validateAppliedSkillBody` + the hardened review path; rollback writes its own history entry |
| Feedback channel becomes a prompt-injection vector | `RecordKindFeedback` never clusters and carries only signal+linkage — no free-text reaches the generator's prompt (reason is operator-side audit only) |
| Evolved-skill sharing launders weak skills into meshes | Provenance marker survives the pull (`generated:true`), share requires explicit verb + `skill_share` allowlist, docs mark evolved skills operator-reviewed not mesh-endorsed |
| Retention prunes evidence an audit wants | Retention bounds task records/drafts only; audit log + accepted history are exempt; `--dry-run` shows the sweep first |
| Cross-workspace state ambiguity | Every verb resolves workspace explicitly; `status` enumerates all known workspaces instead of guessing |

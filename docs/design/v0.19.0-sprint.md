# v0.19.0 Sprint Plan — AIEOS Depth

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **AIEOS depth — manifests that carry claims, lifecycles, and
attestations.** `pkg/rhizome/agentmanifest` (v0.9.0 Track 58) shipped signed
per-agent identity documents — `{agent_id, name, persona fingerprint, models,
skills, peer_id, issued_at}` — embedded in capability announcements, verified
on receipt (`filterAgentManifests`), and persisted to `<workspace>/agents/`
so manifests sync to swarm peers. That is the identity *spine*; what it
lacks is everything after "who issued this":

- **No claims** — the manifest is descriptive, not enforceable. A peer can
  read another node's agent names but cannot learn (let alone require)
  its sandbox posture, tool allowlist, or evolution mode.
- **No lifecycle** — `issued_at` but no `revision`, `expires_at`,
  `supersedes`, or revocation. Persisted manifests linger; a stale
  identity claim is indistinguishable from a live one.
- **No operator surface** — manifest fingerprints show in `mesh peer`
  detail; there is no list/show/verify/revoke verb and no qualified
  `agent@peer` addressing.
- **No attestation** — every manifest is self-issued. There is no
  signed statement a third party can make *about* a manifest — no
  endorsement, no review receipt — so reputation and provenance stop
  at "the issuer said so."

This sprint turns the manifest from a name-tag into a policy artifact:
claims peers can enforce, lifecycles receivers can reason about, verbs
operators can use, and an attestation primitive that lets trust travel.
It builds directly on v0.18.0 Track 156 (the `evolved_skills` summary is
the first claim-shaped field) and feeds the paired-economy story —
an attestation is how v0.17.0's bilateral trust gets exportable.

## Decisions

- **Claims are signed manifest fields, not config leaks.** `Manifest`
  gains `claims` (emit-when-set, under the existing signature — the
  v0.9.0 envelope is already additive-safe on re-marshal). v1 vocabulary
  is small and verifiable: `tools` (allowed tool names), `sandbox`
  (`none|subprocess|sandbox-exec`, read off `IsolationConfig`),
  `evolution` (`off|observe|draft|apply`, read off `EvolutionConfig`),
  `policy_digest` (sha256 of the node's dispatch policy — *that* a
  policy exists, not its contents). Claims are **posture assertions by
  the issuer** — a receiver verifies authenticity, not truth; claim
  trust derives from peer trust, which is the honest ceiling anyway.
- **Lifecycle is receiver-enforced, issuer-declared.** `revision`
  (monotonic per agent+peer), `expires_at` (default TTL 24h via
  `mesh.manifest_ttl`; absent = non-expiring for wire compat),
  `supersedes` (prior fingerprint). Revocation = a signed tombstone
  (`agents/<id>.revoked.json`, `{agent_id, revoked_at, supersedes_rev}`).
  Receivers drop expired/revoked/stale-revision manifests inside
  `filterAgentManifests` — same fail-closed seam, no new protocol.
- **One predicate, both directions.** `require_claim` matching is
  `key=value` exact-match over the claims map (v1: no ranges, no globs
  — documented). Outbound: `--require-claim sandbox=sandbox-exec`
  filters `PickPeer` candidates by their advertised claims, and swarm
  `OfferRequest.RequireClaim` steers claims the same way `requires`
  steers capabilities. Inbound: `MeshACLRule` gains `require_claims`
  — the callee refuses remote calls from peers whose *own* manifests
  don't claim the required posture (e.g. only accept delegation from
  sandboxed issuers). `claim_mismatch` rejection class, mirrored in
  audit.
- **Attestations are receipts, not channels.** `Attestation{issuer_peer,
  subject, kind, payload, issued_at, expires_at, signature}` — subject
  is a `sha256:` fingerprint (manifest revision or `.evolution-origin`
  draft id); kinds are `endorsement` (operator vouches: "ran N tasks,
  score s") and `review` (operator attests a draft/skill was human-
  reviewed). Bounded store (`mesh.attest_max`, default 512); received
  attestations only count from trusted peers — an attestation can never
  widen authority, only annotate existing trust.
- **The spec is a deliverable, not a comment.** Track 167 writes
  `docs/specs/agent-manifest.md` — canonical encoding, signature scheme,
  claim vocabulary, lifecycle rules, attestation schema — and stamps
  `manifest_version` so external implementations get a stable version
  hook. The AIEOS story becomes a published artifact, not folklore in
  `manifest.go` comments.
- **No new protocols, no new deps.** Everything rides the existing
  capability envelope, `agents/` sync, and the blob/skills transports.

## Track 160 — Manifest claims (core)

- `Manifest.Claims map[string]string` — emit-when-set, signed. Reserved
  v1 keys: `tools` (comma list), `sandbox`, `evolution`, `policy_digest`.
- `Input` gains a claims source; the gateway populates from real config
  — `IsolationConfig.EffectiveBackend()`, `EvolutionConfig.
  EffectiveMode()`, tool allowlists — so claims assert measured posture,
  not operator hope.
- `mesh.advertise_claims` (default true — posture claims are the point;
  the flag exists for minimal-footprint nodes).
- `filterAgentManifests` unchanged for claims (they ride the signature);
  unknown claim keys pass through (forward-compat, documented).

## Track 161 — Manifest lifecycle (core)

- `revision` (per-agent monotonic — persisted counter under
  `agents/.revisions.json`), `expires_at` (`mesh.manifest_ttl`, default
  24h), `supersedes` (prior fingerprint when re-issuing).
- Revocation tombstones: `agents/<id>.revoked.json` — signed
  `{agent_id, revoked_at, revision}`; syncs alongside manifests.
- Receiver rules in `filterAgentManifests`: drop expired, drop
  lower-than-seen revision, drop revoked (tombstone wins over manifest).
- Persisted manifests age out on read — `LoadAll` skips expired/revoked;
  `mesh manifest list` annotates state.

## Track 162 — `rhizome mesh manifest` verbs + `agent@peer` (core + cli)

- `mesh manifest list [--peer <id>] [--state live|expired|revoked]`
  — local + received manifests: agent, fingerprint, revision, expiry,
  claims summary.
- `mesh manifest show <agent>@<peer>` — the qualified address form
  (`agent@peer-id` resolves against stored manifests; bare `agent`
  resolves local).
- `mesh manifest verify <agent@peer|file>` — signature + lifecycle
  check against the issuer's recorded key.
- `mesh manifest revoke <agent>` — daemon-required; writes the
  tombstone, triggers re-announce (next capability emit excludes the
  revoked agent's manifest).

## Track 163 — Claim-gated outbound dispatch (core + swarm)

- `--require-claim k=v` (repeatable) on `delegate`, `route`, `spawn`,
  `task submit`, `scatter` — `PickPeer` filters candidates whose
  manifests carry the claims (all-of matching); no candidate → the
  existing no-capable-peer error names the unmet claim.
- `OfferRequest` gains `RequireClaim map[string]string` (emit-when-set);
  `swarm offer --require-claim k=v` steers claims like `requires`
  steers capabilities — cut line keeps dispatch flags.
- `mesh peer`/route dry-runs show claim match/miss reason fields.

## Track 164 — Inbound claim admission (core)

- `MeshACLRule.RequireClaims map[string]string` — inbound remote calls
  (delegate/spawn/task/blob-gated surfaces) check the *caller's* node
  claims (the calling peer's advertised posture, from its node-level
  claims or its manifests' issuer posture — impl-time pick, documented).
- Mismatch → `claim_mismatch` rejection class (the `capacity:`/
  `price_floor:` precedent); audited with the missing claims listed.
- Empty predicate = today's behavior exactly.

## Track 165 — Attestation schema + verbs (core)

- `pkg/rhizome/attest`: `Attestation` type + sign/verify/persist under
  `agents/attestations/` (JSONL, bounded by `mesh.attest_max`,
  default 512 — oldest expired evicted first).
- `rhizome mesh attest endorse <agent@peer> [--score N] [--tasks N]
  [--note "…"]` — issues an endorsement attestation.
- `rhizome mesh attest list [--subject <fp>] [--kind]`,
  `show <id>`, `verify <id>` — receipts are inspectable.
- Receipts ingest: attestations arriving embedded in capability
  announces from **trusted peers only** are stored; untrusted senders'
  attestations drop with an audit line.

## Track 166 — Attestation consumers (core)

- **Endorsement → peer-score seeding**: a trusted peer's endorsement
  seeds `PeerScoreStore` for the subject — flagged `source:attested`,
  capped weight (endorsements can warm a score, never outrank observed
  history), decayed by the existing half-life.
- **Review attestation → evolved-skill provenance**: `evolution draft
  accept` (v0.18.0) gains `--attest` — mints a `review` attestation
  bound to the draft fingerprint; `.evolution-origin.json` carries
  `review_attestation_id`, so a pulled evolved skill's "human reviewed"
  claim verifies against the issuer's key. Degrades to Track 156's
  self-claim when the flag is absent.
- Both consumers are additive: no attestation → v0.18.0 behavior.

## Track 167 — AIEOS spec formalization (docs)

- `docs/specs/agent-manifest.md` — the published artifact: canonical
  encoding, signature coverage, claim vocabulary + reserved keys,
  lifecycle rules (revision/expiry/revocation), attestation schema,
  receiver algorithms. Written for an external implementor — the AIEOS
  interop story made real.

## Acceptance criteria

- `go build -tags goolm,stdjson ./...` green; `go test -p 1 -tags
  goolm,stdjson ./...` green on touched packages; golangci-lint v2.13.2
  → 0 issues; `lint-docs.sh` OK; no new Go deps, no new protocols.
- v0.14.0–v0.18.0 released + verified.
- Claims: a manifest advertises measured `sandbox`/`evolution` posture;
  old builds accept and ignore unknown claim keys.
- Lifecycle: expired manifests drop on receipt and on `LoadAll`;
  revocation tombstones win over live manifests; stale revisions drop.
- Dispatch: `--require-claim sandbox=sandbox-exec` excludes non-claiming
  candidates; inbound `require_claims` rejects with `claim_mismatch`
  and audits the missing keys.
- Attestations: endorsement seeds peer-score bounded + flagged; review
  attestation verifies against issuer key and lands in the pulled
  skill's provenance; untrusted issuers' attestations drop.
- Spec: `agent-manifest.md` matches the implementation (a conformance
  checklist test asserts the reserved vocabulary).
- Release: docs updated, config validates, release notes + tag.

## Impl-time verification checklist

- Whether node-level posture claims live once on the capability or
  per-manifest — `Capability` claims vs per-agent `Manifest.Claims`;
  per-agent is the v0.18.0-156 precedent but node-level avoids
  repetition. Pick per-agent for 160; revisit if payload grows.
- `require_claims` on inbound calls checks the caller's *own* manifest —
  confirm the calling peer's posture is actually extractable at the
  callee (capability store vs the request's embedded identity).
- `policy_digest` input: digest of *what* — `mesh.acl` + dispatch config
  canonicalized. Define the input set tightly or the digest churns.
- Revision counter persistence location (`agents/.revisions.json` vs
  mesh state dir) — manifests sync, counters should not.
- Attestation subject encoding for `review` kind — draft fingerprint vs
  `.evolution-origin.json` digest; pick the one a *receiver* of a pulled
  skill can recompute.
- Endorsement score semantics — scale, cap, and how `source:attested`
  blends with observed ops in `PeerScoreStore`.
- `agent@peer` parsing ambiguity with agent ids containing `@` —
  `ValidAgentID` already excludes `@`; confirm and document.
- Whether revocation tombstones need `supersedes` chaining (a
  re-issued agent after revoke) — v1: tombstone carries `revision`,
  a later manifest with higher revision supersedes the tombstone.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Claims become unverifiable promises peers rely on | Claims are documented as issuer posture *assertions* weighted by existing trust; dispatch admission combines claims with observed behavior — never claims alone |
| Claim vocabulary ossifies too early | Reserved-key registry in the spec; unknown keys pass through; v1 vocabulary deliberately tiny |
| Lifecycle expiry strands long-lived peers' manifests | TTL default 24h with re-announce on capability emit; absent `expires_at` ≡ non-expiring keeps old builds valid |
| Revocation replay (old manifest resurrected) | Tombstones carry revision; receivers keep the tombstone until a higher-revision manifest supersedes it |
| `--require-claim` confuses "claim absent" vs "claim false" | Absence never satisfies a predicate — documented as all-of exact-match; error names the unmet claim |
| Attestations inflate reputation via sybil issuers | Trusted-issuer-only ingest, `source:attested` flag, capped weight, existing half-life decay — endorsements warm, never crown |
| Attestation store bloat / gossip storm | `attest_max` bound, expiry, trusted-only ingest, no re-broadcast in v1 |
| `agent@peer` grammar collisions | `@` already invalid in `ValidAgentID`; grammar documented in spec |
| Spec freezes a schema impl then diverges | Conformance checklist test over reserved vocabulary; spec is generated-adjacent (derived from constants where possible) |

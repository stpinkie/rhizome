# v0.14.0 Sprint Plan — Open Agent Work Market

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: **Open Agent Work Market.** `docs/design/mesh-economy-module.md` lays
out the design: paid agent work between *mutually untrusted* operators — a
buyer locks payment in an on-chain escrow, opens an **ACP session** to a
seller's node, and the seller runs the task inside a sandboxed or
containerised agent. Prompts in, results out — buyers never execute seller
code. The market ships **only** as the opt-in `rhizome-market` companion
module; core carries generic, inert seams. This sprint lands the full arc:
core seams → module skeleton → sell-side → buy-side → escrow → discovery —
plus the ACP follow-ons tail.

## Decisions

- **`rhizome-market` lives in-repo at `cmd/rhizome-market`.** The design
  requires linking first-party packages (`pkg/web3` — shared RHIZOME_HOME
  wallet, `policy.Evaluate`, `web3-pending.json`; `pkg/isolation`;
  `pkg/acp`; `pkg/rhizome/stream`; `pkg/rhizome/identity` for receipt
  signing). In-repo keeps the module's version locked to the core seams it
  depends on and reuses the existing release pipeline: GoReleaser ships
  separate `rhizome-market_{goos}_{goarch}` assets via a dedicated build +
  archive id — **never in the base archives**.
- **No market keys in the core config schema.** All market config lives
  under `modules.rhizome-market.fields` / `.secrets` — the design's hard
  rule. A node has zero market surface without
  `rhizome module install rhizome-market` + `enable`.
- **`ModuleAdverts` wire-compat is the `Role` precedent — with a correction.**
  `verifyCapability` re-marshals the *decoded* struct and verifies the
  signature over those bytes. `Allows` map keys survive an old build's
  unmarshal/re-marshal byte-identically (Go maps marshal sorted); a **new
  struct field does not** — an old build drops `module_adverts` on decode,
  re-marshals different bytes, and rejects the entire manifest. The design
  doc's "byte-identical re-marshal" claim holds only for map keys.
  Consequence accepted per `Role`: a market-serving node's manifest is
  unverifiable to the whole pre-v0.14.0 fleet — so emission is gated on
  `serve_enabled` (a node burns compat only when actually serving), and the
  docs state plainly that market peers must run ≥v0.14.0. A fixture test pins
  both behaviors. The alternative — fetching advert content out-of-band —
  was rejected for v1: the signed manifest is the cheapest authenticated
  advert channel we have, and buyers need the new build regardless.
  **Revision note:** with Track 105 deferred, the manifest advert is the
  *primary* discovery channel this sprint, not just a seam for the index.
- **The bridge is a dedicated loopback listener, not the gateway mux.**
  Modules must work under `rhizome daemon --no-gateway`, so the stream
  bridge is its own `net.Listener` on `127.0.0.1:0` with a per-module bearer
  token minted at install (`<module_dir>/bridge-token`, 0600) and injected
  via env (`RHIZOME_BRIDGE_ADDR` / `RHIZOME_BRIDGE_TOKEN`) the same way
  `{module_dir}` and field envs already are. HTTP-hijack through the gateway
  was considered and rejected for the no-gateway posture.
- **Escrow: adopt an existing contract.** The survey (Track 101) evaluates
  real candidates — Kleros `MultipleArbitrableTokenTransaction`
  (ERC-792/1497, real juror arbitration) vs Smart Invoice (designated
  arbiter, factory clones, battle-tested but never formally audited) — with
  the design's ~200-line custom contract only as documented fallback. The
  sprint commits to the adopt-existing direction; the *pick* is the survey's
  output.
- **`acp.remote` ships with the bridge as the design's "free byproduct".**
  `agents.list[].acp.remote = "<peer-multiaddr>"` dials a trusted peer's
  `/rhizome/acp/1.0.0` through the same stream path; `acp.server.remote`
  serves the existing ACP server over an inbound stream. Trusted-peers-only —
  remote ACP inside one operator's mesh is a trust-domain feature, not a
  market surface.
- **`market_serve` advertises posture; it does not require a runtime.** A
  seller's sandbox/container claim is self-attested and unverifiable —
  buyers price the risk; the advert carries `runtime_posture` as data.
- **Per-task escrow granularity for v1** (per the design's open question):
  one escrow session = one task. Session drawdown is a Stage-D horizon item.
- **No new Go dependencies in core.** The module links existing `pkg/*`
  only; the bridge is stdlib `net`; container spawn shells `docker|podman`;
  escrow binding uses `pkg/web3`'s ABI/RLP machinery. Binary-size delta ≈ 0
  for the base build; the market binary is a separate artifact with its own
  baseline.
- **v0.14.0 market posture: experimental.** The fixture `SettlementRail`
  is the shipped default; `escrow_contract` opts into the bound-but-
  unverified rail (the recorded E2E is v0.15.0). Discovery is
  signed-manifest adverts between direct peers plus manual provider
  addressing — no curated index, no DHT tier, no reputation fields until
  Track 105 lands.
- **ACP-over-HTTPS uses WebSocket via `gorilla/websocket`** — already a
  direct dependency (IM channels + browser CDP), so the no-new-deps rule
  holds. acp-go-sdk v0.13.5 ships no WS transport (`coder/websocket` sits
  in the module graph only as an indirect). The wire spec — WS upgrade at
  `/rhizome/acp`, then the identical `_rhizome.session_open` presentation
  — is frozen in Track 107's docs so non-Rhizome counterparties can
  implement against it.
- **llama.cpp promotes from the queue.** Its design was landed
  decision-ready in Track 95; it is the market's ToS-clean inference
  story (local-model offers dodge provider resale terms — the design's
  documented recommendation) and exercises the module system beyond
  infra daemons. Catalog additions (`binary_path`, field-fed asset
  substitution, weights fetch) emit schema **v5** — v4 is Track 98's
  `protocols`; emit the lowest covering version per the Track-95
  precedent.
- **Upstream is a fixes-only cherry-pick source.** Track 108 picks defect
  fixes individually (`git cherry-pick -x`); feature ports need explicit
  sign-off — the divergence is deliberate.

## Track 97 — ACP runtime modes + network-isolation knob (core)

External ACP agents run unsandboxed today by design (`client.go`
trust-posture comment). This track adds `agents.list[].acp.runtime =
exec|sandbox|container`, per-binding override of `acp.client.runtime`,
plus `acp.client.container = {engine:auto|docker|podman, image,
network:none|bridge|allowlist, mem_mb, cpus, pull:missing|never}`.

- `pkg/config/config.go`: `ACPPolicyConfig` gains `Runtime string` and
  `Container *ACPContainerConfig`; `ACPAgentConfig` gains `Runtime string`
  (a per-binding container image override is an impl-time call — keep the
  per-binding surface minimal).
- `pkg/isolation`: today's API is process-global — `Configure`/`CurrentConfig`
  set one isolation state and the module supervisor calls
  `isolation.Start(cmd)` under it. A daemon must run unsandboxed module
  spawns and sandboxed ACP agents side by side, so add a per-invocation
  path: `type Options{ Enabled bool; Root string; NetMode string; Mounts
  []MountRule }`-style parameter + `StartWith(cmd, *Options)`, with the
  existing `Start`/`Run` delegating under `CurrentConfig` unchanged.
  Sandbox runtime gets a **scratch instance dir per ACP session** — not
  RHIZOME_HOME.
- Network knob: bwrap `--unshare-net` on Linux (a slirp-based allowlist is
  stretch), a sandbox-exec profile that *omits* `network-outbound` on
  darwin (`platform_darwin.go` currently emits `(allow network-outbound)`
  unconditionally — parameterize it), and a Windows job-object + WFP /
  restricted-token rule. Platforms that can't express the requested net
  mode fail the spawn with a clear error — never silently run unsandboxed.
- `pkg/acp/client.go` `spawn()`: dispatch on the effective runtime —
  `exec` = today's path byte-for-byte; `sandbox` = `isolation.StartWith`
  under the scratch dir + net mode; `container` = `docker|podman run -i
  --rm --network <mode> --memory <mb> --cpus <n> <image>` — stdio pipes
  are the ACP transport, so containerised agents need **zero protocol
  change**. `engine:auto` resolves docker → podman → a named-both error.
  The existing `m.dial` seam covers tests.
- `pull:missing` does `docker pull` when the image is absent; `never`
  fails fast. Image is required for `container` runtime (no default).

## Track 98 — Module stream bridge + `acp.remote` (core) — LANDED (PR #46)

The design's core seam: a sidecar module can't reach the libp2p wire today,
so the daemon bridges declared protocols to the module's loopback listener —
inert when no module declares protocols.

- `pkg/modules/catalog.go`: `ModuleSpec.Protocols []string` (catalog schema
  v4); `Manager.Info` surfaces it; `validate.go` enforces well-formed ids
  and **rejects collisions with core-registered protocols**
  (`/rhizome/caps|agent|agent-task|swarm|git-sync|pair|skill|blob` and any
  other id the node itself binds — maintain a registry list) so a module
  cannot shadow core traffic.
- Bridge (daemon-side, new `pkg/rhizome/bridge` or `pkg/modules/bridge` —
  impl-time pick): a loopback `net.Listener` on `127.0.0.1:0`.
  - Inbound: for each enabled module declaring protocols, the daemon
    registers `node.Host().SetStreamHandler(protocol.ID, handler)` that
    dials the module's bridge port and splices bytes both ways (raw
    `io.Copy` — the daemon is a dumb pipe; framing is the module's).
  - Outbound: the module connects to the bridge and sends a JSON hello
    `{token, peer, protocol}`; the daemon validates token → module →
    declared-protocol-set, opens `host.NewStream(ctx, pid, proto)`, and
    splices back.
  - Auth: token minted at install (`<module_dir>/bridge-token`, 0600;
    rotated on reinstall); `RHIZOME_BRIDGE_ADDR`/`RHIZOME_BRIDGE_TOKEN`
    env injected in `commandBase` only for protocol-declaring modules.
    Undeclared protocols and bad tokens are refused + logged.
  - Wired in `cmd/rhizome/internal/daemon/command.go` after mesh start and
    supervisor start; works under `--no-gateway`.
- **`acp.remote` byproduct**: `agents.list[].acp.remote = "<peer-multiaddr>"`
  — `ClientManager` gains a `RemoteDialer` seam (wired from the mesh node's
  host in `pkg/gateway/gateway.go` where `acpManager` is constructed);
  `spawn` opens `/rhizome/acp/1.0.0` to the peer instead of exec'ing, then
  runs the identical initialize handshake over the stream.
  Trusted-peers-only via `mesh.IsTrusted`. Serve side:
  `acp.server.remote = true` registers a stream handler wrapping the
  existing `rhizome acp` server (already `io.Reader`/`io.Writer`-shaped —
  a thin adapter). Daemonless CLI paths keep today's behavior.
- Networked tests follow the AGENTS.md isolation posture
  (`testutil.NewIdentity`, `DisableMDNS`, `DisableNATPortMap`, explicit
  `BootstrapPeers`).

## Track 99 — Module capability adverts + `rhizome market` CLI stub (core)

- `mesh.Capability` gains `ModuleAdverts map[string]json.RawMessage`
  (emit-when-set). Wire-compat per Decisions: gated on `serve_enabled`;
  a fixture test pins that a non-serving node's manifest bytes are
  identical to today and that an old-build struct drop fails verification
  exactly as `Role` does.
- `mesh.SetModuleAdvertProvider(func() map[string]json.RawMessage)` — the
  daemon supplies a reader over `<home>/modules/<id>/advert.json` for
  enabled modules: size-bounded (~16 KB), JSON-validated, unreadable →
  advert dropped (never block manifest signing). When any advert declares
  market serving, `localCapability` sets `Allows["market_serve"]=true` —
  the map key that *is* old-build-safe.
- `cmd/rhizome/internal/market/`: `rhizome market` verb tree — `find`,
  `buy`, `session`, `receipt` — thin client to the module's localhost API
  (addr + token read from `<module_dir>/api.addr` / `bridge-token`).
  Without the module: "rhizome-market module not installed — run
  `rhizome module install rhizome-market`" (the browser-backend /
  daemon-required precedent). This track ships the tree + not-installed
  posture; verb flesh lands in Tracks 102–104.

## Track 100 — `rhizome-market` skeleton (module)

- `cmd/rhizome-market/main.go`: standalone daemon-kind binary. Flags/env
  take `RHIZOME_HOME`; reads its config from
  `modules.rhizome-market.fields`/`.secrets` via the config loader;
  serves a loopback HTTP API (the surface `rhizome market` calls);
  writes `advert.json` on field change and interval. Links `pkg/web3`,
  `pkg/isolation`, `pkg/acp`, `pkg/rhizome/stream`, `pkg/rhizome/identity`
  — same trust level as the daemon by design; install is a real trust
  decision mitigated by digest-pinned signed-catalog delivery.
- Catalog entry: `kind:daemon`, `protocols:["/rhizome/acp/1.0.0"]`,
  `install.method:"github-release"`, `repo:"stpinkie/rhizome"`,
  `asset_template:"rhizome-market_{goos}_{goarch}.{ext}"` — **chicken-and-egg
  documented**: pinned digests need released assets, so the entry lands
  with `releases:[]` (present but uninstallable) and the first pin is added
  in Track 107 once assets exist — or the release pipeline emits digests
  for catalog pinning (impl-time pick; same class of problem as
  `binary-size-baseline.txt` updates).
- `.goreleaser.yaml`: build id `rhizome-market` (`CGO_ENABLED=0`,
  `goolm,stdjson` tags, same ldflags; linux/darwin/windows amd64+arm64 —
  the container serving runtime justifies the narrower platform set) and a
  separate `archives` entry so it stays out of base archives;
  `checksums.txt` covers it for catalog pinning. `goreleaser check` stays
  green in `pr.yml`.
- Field schema (flat `ConfigField` strings — no market keys in core
  config): `serve_enabled`, `offers_json` (JSON array of `{id,
  agent_binding, price_sheet{per_task, per_1k_prompt_tokens,
  per_1k_completion_tokens, min_charge, asset, chain_id}}` — flat fields
  can't carry nested lists, so either `offers_json` or an
  `offers.json` file under the module dir; impl-time pick), `runtime`,
  `payout_chain_id`, `payout_address`, `payout_asset`,
  `max_concurrent_sessions`, `session_ttl`, `buy_max_cost_per_task`,
  `buy_max_cost_per_day`, `export_allow_attachments`, `export_redact`,
  `export_require_review`, `market_index_enabled`, `market_index_url`,
  `escrow_chain_id`, `escrow_contract`, `escrow_token`, `escrow_arbiter`,
  `escrow_dispute_window`.
- Module-local audit: `market-audit.jsonl` under the module dir (bounded,
  the `mesh-tasks.jsonl` posture); `market.*` events in module logs —
  daemon-side event relay is impl-time optional (a bridge `POST
  /events`-style verb if it stays small).

## Track 101 — Escrow survey + `SettlementRail` + mock (module/docs)

Sequenced early so 102/103 code against a concrete ABI shape.

- `docs/design/escrow-survey.md` — candidates:
  - **Kleros `MultipleArbitrableTokenTransaction`** (escrow-contracts
    repo): ERC-792 arbitration + ERC-1497 evidence; ERC-20 variant exists
    alongside the ETH one; a *real* arbitration mechanism (Kleros Court
    jurors, appeal rounds, loser-pays-fees) which answers the design's
    arbiter-model open question with an actual protocol rather than a
    designated address. Caveats to verify: arbitration fees paid in native
    token; Kleros Court V1 runs mainnet+Gnosis, V2 on Arbitrum — check
    Sepolia/testnet deployability for the E2E; the "Multiple" contract
    keys escrows by transaction id — map to `session_id`.
  - **Smart Invoice / SmartEscrow** (lexDAO/RaidGuild): factory-clone per
    invoice; deposit → milestone `release` → `lock` → arbitration-provider
    `resolve` — a near-exact lifecycle match, and the designated-address
    arbiter is precisely the design's v1 model. Caveats: **never formally
    audited** (self-described beta; battle-tested by RaidGuild since
    ~2020); per-session = one clone deployment (gas cost ~cheap on L2,
    pricey on L1 — fine for Sepolia-first); safety-valve date maps to the
    dispute window.
  - **OpenZeppelin Escrow/RefundEscrow/ConditionalEscrow**: pull-payment
    primitives with no dispute/arbitration semantics — documented as
    rejected.
  - **Fallback**: the design's ~200-line minimal contract
    (`open/release/claim/dispute/resolve` + designated arbiter) — only if
    the survey finds nothing deployable with an acceptable trust posture.
  - Decision criteria: Sepolia/cheap-L2 deployability, ERC-20 (USDC)
    support, dispute window + arbiter semantics matching
    open/release/claim/dispute/resolve, session-id/bytes32 keying,
    `eth_getLogs` event surface for watches, audit/battle status, license.
- `SettlementRail` Go interface in the module: `Open(ctx, sessionID,
  terms) (txHash, error)`, `VerifyLock(ctx, sessionID, terms) (bool,
  error)` (the `eth_call` pre-work check), `Release`, `Claim`, `Dispute`,
  `Resolve` — plus a fixture/mock implementation that Tracks 102/103 code
  and test against.
- `escrow_*` fields resolve against the pick; the contract ABI ships
  bundled in-module (the `pkg/web3` abireg pattern), not fetched.

## Track 102 — Sell-side: session manager + receipts (module)

- Inbound `/rhizome/acp/1.0.0` (bridge-spliced): the session opens with a
  presentation `{session_id, task_hash, offer_id}` — either a pre-ACP
  handshake line or a `_rhizome.session_open` extension method (impl-time
  pick; the SDK validates `_`-prefixed names either way). The
  presentation handler takes an `io.ReadWriteCloser`-shaped transport
  (the `RemoteMux.Serve` precedent) so Track 110's HTTPS path reuses the
  identical gate and session machinery unchanged.
- Gate: the module verifies the offer is enabled **and**
  `SettlementRail.VerifyLock` returns a confirmed on-chain lock with
  matching terms — **before spawning anything**. Unpaid prompts can never
  burn LLM budget (the design's inbound-DoS bound).
- Serving posture: the offer's `agent_binding` spawned via `pkg/acp` client
  machinery under the configured `runtime` (`sandbox`/`container`;
  `permission_policy=deny` forced; no fs/terminal capabilities advertised;
  scratch cwd; container egress `none` or a model-endpoint allowlist —
  bounds prompt exfiltration as well as host exposure).
- Metering: session duration + agent self-reported tokens where the agent
  answers a `_rhizome.usage` extension query; honest-nil otherwise
  (external ACP agents can't be metered by the Track-94 pipeline — the
  design's documented caveat).
- `_rhizome.receipt` (SDK `ExtensionMethodHandler` — verified in
  acp-go-sdk v0.13.5: `CallExtension`/`NotifyExtension` on both connection
  types, `HandleExtensionMethod` for receivers): `{session_id, offer_id,
  duration_ms, usage, result_sha256, terms{price, asset, chain_id},
  signature}` — signed with the node key via `pkg/rhizome/identity`;
  verifiable against the seller's peer id. This is the escrow-release
  payload.
- `market-audit.jsonl` partition; per-peer rate limits +
  `max_concurrent_sessions` + `session_ttl` enforced.

## Track 103 — Buy-side: `market buy` + export policy (module)

- Provider index client: `<market_index_url>/index.json` + `.sig`
  (Ed25519, curator key) — reuse the Track-90 shared verifier
  (`pkg/sigverify`); ~1 h TTL cache + stale-serve under the module dir
  (the `catalog-cache` pattern). The client lands generic — it works
  against any operator-supplied index URL; the first-party curated index
  arrives with Track 105 in v0.15.0.
- `rhizome market find <service>` → index query when `market_index_url`
  is set; otherwise scans connected/trusted peers' manifests for
  `ModuleAdverts["rhizome-market"]` — the direct-peer discovery path that
  carries the experimental market (offers, price sheet, payout, runtime
  posture, manifest fingerprints).
- `market buy <provider> <offer> <task> [--max-cost]` — `<provider>` is a
  peer id or `/p2p/` multiaddr dialed through the bridge; `wss://`/
  `https://` providers arrive with Track 110:
  1. Export policy: task text only; attachments/media refused
     (`export_allow_attachments`); `pkg/redact` pass;
     `export_require_review` gates send.
  2. ERC-20 `approve` + escrow `open` via `web3_contract_send` → policy
     eval (`allow_contracts`/`allow_methods` label:method,
     `max_value_wei_*`) → pending-approval queue (the module submits into
     the shared `web3-pending.json`; approvals surface in the existing
     CLI/daemon/UI flow) → session id.
  3. Bridge `dial {peer, /rhizome/acp/1.0.0}` → session-open presentation
     `{session_id, task_hash, offer_id}` → ACP session runs.
  4. Receive `_rhizome.receipt` → verify signature against the peer id and

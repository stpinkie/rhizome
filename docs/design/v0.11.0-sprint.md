# v0.11.0 Sprint Plan — Agentic Operations & Trust

Sprint tracks and acceptance criteria live in `.todo.md`; this document is the
durable design record: ordering, per-track architecture, and the risk register.

Theme: the mesh grows **teeth and trust**. Web3 Stage 2 turns the
nimbus-verified-proxy endpoint into agent tools — reads first, then gated
signing with a human-approval queue. The module system gains a signed catalog
and curated index so tenants can ship out-of-band. ACP deepens (session/load,
MCP passthrough, terminal capability), the mesh becomes role-aware, and the
dashboard gets a topology view. First, we actually ship v0.10.0.

## Ordering & dependencies

One PR per track, in this order:

```
Track 67  Ship v0.10.0 ──────────────── first (clears the deck; ops, not code)
Track 70  Module trust (signed catalog + index) ──┐
Track 71  New tenants (helios, kubo) ──────────────┘ (71 rides 70's machinery)
Track 68  Web3 reads (pkg/web3 + web3_* tools) ────┐
Track 69  Web3 wallet + gated signing ─────────────┘ (69 depends on 68)
Track 72  ACP deepening (independent)
Track 73  Mesh depth + topology graph (independent)
Track 74  Security polish — stretch, first cut line
Track 75  Docs & release (last)
```

Rationale: the release gate clears before new work so `.todo.md` stays honest;
module trust lands before new tenants so they ride the signed-catalog path;
web3 signing builds on the read client; everything else is independent and
flexes around the big tracks.

**Sprint is deliberately large** (9 tracks vs v0.10.0's 7). Cut lines, in
order: Track 74 → the topology-graph half of 73 → the signing half of 69
(ship reads-only). Record cuts in `.todo.md` like previous sprints.

## Decisions

- **No `go-ethereum`.** Web3 needs secp256k1 + Keccak-256 + RLP + a minimal
  ABI codec — `decred/dcrd/dcrec/secp256k1/v4` and `golang.org/x/crypto` are
  already in the module graph (indirect deps); go-ethereum would blow the
  +15% binary-size warn gate. Record the delta per track.
- **Signing approval is async.** No built-in human approver exists outside
  ACP (`ToolApprover`/`approve_tool` is the generic seam —
  `pkg/agent/hooks.go`, `docs/architecture/hooks/hook-json-protocol.md`).
  The mechanism is a **pending-approval queue**: the tool returns a
  `pending_id`, the human resolves via `rhizome web3 approve <id>` or
  `POST /web3/approvals/<id>` (daemon + launcher + dashboard badge), and
  broadcast happens on approval. Works on every channel without
  channel-specific UX.
- **Module trust root = a Rhizome Ed25519 release key** baked into the
  binary (stdlib `crypto/ed25519` — no new dep; private key lives as the
  `MODULE_CATALOG_SIGNING_KEY` GitHub secret, base64 seed). `catalog.json`
  is canonical `json.MarshalIndent` output (struct field order + sorted
  map keys are already deterministic); `catalog.json.sig` is the base64
  signature alongside it (minisign-format compatibility optional —
  `aead.dev/minisign` is already in the graph). The embedded catalog
  remains the default; a remote curated index is opt-in via a **sibling
  `module_index = {url, enabled}` section** — not `modules.catalog_url`:
  `Config.Modules` is a `map[string]ModuleConfig`, so a `catalog_url` key
  inside it would decode as a module id. Unsigned/bad-sig catalogs are
  refused hard, and on id collision the embedded entry wins (remote can't
  shadow the trust-rooted set).
- **Topology graph is hand-rolled SVG** — `web/frontend/package.json` has no
  graph lib and we keep it that way (bundle-lean; radial layout: self
  center, peers ringed, edges colored by transport).
- **`enc2://` = XChaCha20-Poly1305**, transparent dual-decrypt with
  `enc://` (AES-256-GCM stays readable forever); new writes use enc2.
  `x/crypto/chacha20poly1305` is already in the graph.

## Track 68 — Web3 reads

**As executed (PR #15):** shipped as specced plus three hardening deltas —
`tools.web3.allow_private_endpoints` (default **false**: at false, endpoint
dialing routes through `utils.CreateSafeHTTPClient`'s SSRF guard, so nimbus
on loopback needs the explicit opt-in), a 30 s endpoint-resolution cache so
tool calls don't re-probe module health, and `url.Error` unwrapping so
endpoint URLs (which can embed path keys) never reach tool output.
`eth_accounts` is deliberately outside the `web3_rpc` allowlist.

- **`pkg/web3`** (new package — eth specifics stay out of `pkg/tools`):
  - `client.go` — JSON-RPC 2.0 client on stdlib `net/http` (no dep);
    `Call(ctx, method, params)`; timeout from `tools.web3.timeout_seconds`;
    optional Bearer header (`ethereum-rpc.api_key`).
  - `endpoint.go` — `EndpointResolver` precedence: `tools.web3.endpoint`
    override → configured `modules.ethereum-rpc` `endpoint_url`
    (`Manager.resolvedFields` incl. secret api_key) → **running+healthy**
    `nimbus-verified-proxy` `listen_url` → descriptive error. Endpoints are
    config-derived only — never agent-supplied at call time; http/https
    only (SSRF posture consistent with `pkg/guard`).
  - `types.go` — hex quantity codec, block/tx/receipt/log types.
- **Tools** under `pkg/tools/web3/` (facade like `pkg/tools/browser`):
  `web3_call` (eth_call), `web3_balance`, `web3_block`, `web3_transaction`
  (receipt+status), `web3_logs` (range-capped), `web3_chain` (chainId, gas,
  syncing), and `web3_rpc` — generic passthrough **restricted to a
  read-only method allowlist** (`eth_call`/`eth_get*`/`net_*`/
  `web3_clientVersion`; `*_send*`/`eth_sign*` excluded).
- Config `tools.web3 = {enabled:false, endpoint:"", chain_ids:[],
  max_log_range:10000, timeout_seconds:30}` — **disabled by default**;
  `chain_ids` constrains reachable networks. Registered per
  `cfg.Tools.IsToolEnabled` in `pkg/agent/agent_init.go`; `api_key` joins
  the sensitive-data replacer.

## Track 69 — Web3 wallet + gated signing

- `pkg/web3/keys.go` — secp256k1 keys (`dcrec/secp256k1` v4.4.1, promote
  indirect→direct), Keccak-256 addresses (`x/crypto/sha3`
  `NewLegacyKeccak256`; address = last 20 B of keccak over the
  uncompressed pubkey sans prefix). Store `<RHIZOME_HOME>/web3/keys.json`
  (dir `0700`, file `0600`): `[{address, enc_privkey, nonce, created_at,
  label}]` — per-key AES-256-GCM under a wallet master key in the OS
  keyring (`go-keyring`, account `web3-wallet`), passphrase fallback via
  `RHIZOME_WALLET_PASSPHRASE` + scrypt (the `pkg/rhizome/identity`
  KeyProvider posture — needed on headless Linux with no dbus).
  import/generate; `reveal` gated behind `--confirm` + masked output.
- `pkg/web3/abi.go` — minimal ABI codec: `MethodID(sig)` (keccak256[:4]),
  encode/decode for address/uint\<M\>/int\<M\>/bool/bytes/string/bytesN +
  dynamic types covering ERC-20 (`transfer`/`approve`/`balanceOf`/
  `decimals`/`symbol`) + ERC-721 basics; table-tested vs published spec
  vectors (`transfer` = `0xa9059cbb`, `approve` = `0x095ea7b3`).
- `pkg/web3/rlp.go` — minimal RLP encode (~100 lines: string/list,
  len<56/≥56 branches). No dep.
- `pkg/web3/tx.go` — `TxRequest{To, ValueWei, Data, GasLimit, GasFeeCap,
  GasTipCap, Nonce, ChainID}`; EIP-1559 (type `0x02`) + legacy fallback
  (when the endpoint lacks `baseFee` — nimbus-proxy verification item);
  ECDSA sign over keccak256(sigPayload) w/ EIP-155 `v`; broadcast via
  `eth_sendRawTransaction`; nonce via `eth_getTransactionCount(addr,
  "pending")`; gas via `eth_estimateGas` + `eth_maxPriorityFeePerGas` +
  latest `baseFeePerGas`. Keys never leave the box — only the signed raw
  tx crosses the wire.
- `pkg/web3/policy.go` — `tools.web3.signing = {enabled:false,
  allow_contracts:[], allow_methods:["0x…selector"], max_value_wei_per_tx,
  max_value_wei_per_day, chain_ids:[]}`; `Evaluate(req)` → allow /
  deny-with-reason; persistent spend ledger
  `<RHIZOME_HOME>/web3-ledger.jsonl` (append-only `0600`, rotate ~10 MB ×
  3 — the `mesh-tasks.jsonl` pattern; extract a shared jsonl-rotate helper
  or copy the ~30-line one). Daily cap sums UTC-day sends.
- **Approval queue** — `pkg/web3/pending.go`, file
  `<RHIZOME_HOME>/web3-pending.json` (bounded ~100, expired pruned on
  read; atomic write). Entry: `{id, created_at, expires_at, kind:
  send|sign|approve, chain_id, from, to, value_wei, data, selector,
  summary, status: pending|approved|rejected|sent|failed, tx_hash,
  error}`. Single-writer rule: a running daemon owns resolution (CLI
  proxies via `internal.DaemonRequest`); daemonless CLI resolves directly
  on the file — concurrent daemon+CLI approve is documented
  last-writer-wins.
  `web3_send`/`web3_sign` pass policy → enqueue → return
  `{pending_id, summary}` → human approves via `rhizome web3 approve|reject
  <id>` or `POST /web3/approvals/<id>` (+ launcher `/api/web3/*` proxy +
  dashboard badge) → sign+broadcast. External `hook.approve_tool` hooks
  still get first pass via `HookManager.ApproveTool` (runs for every tool
  call — `pipeline_execute.go`); timeout/cancel → deny.
  `web3_pending`/`web3_send_status` tools let the agent poll.
- Tools in `pkg/tools/web3/signing.go`: `web3_send`, `web3_sign` (EIP-191),
  `web3_approve` (ERC-20 convenience), `web3_wallet` (addresses+balances;
  never key material). Signing tools AND-gate on `tools.web3.enabled &&
  signing.enabled` in `IsToolEnabled`. CLI: `cmd/rhizome/internal/wallet/`
  (`rhizome wallet create|import|list|reveal`, daemonless) +
  `cmd/rhizome/internal/web3/` (`rhizome web3 pending|approve|reject`).
  Daemon `pkg/gateway/web3api.go` (`GET /web3/pending`,
  `POST /web3/approvals/{id}`) + launcher `web/backend/api/web3.go`
  proxies + frontend pending-approvals badge. Events
  `web3.pending|approved|rejected|sent|failed` → activity feed (extend the
  mesh/swarm kind matcher for the `web3.` prefix) + audit.
- **Canary posture:** `signing.enabled` defaults false; testnet-first docs.

## Track 70 — Module trust

- `pkg/modules/catalog.go` — embed the `releasePubKeyB64` const;
  `VerifyCatalog(data, sig)` helper; `Source` provenance flag on catalog
  entries (`"embedded"`/`"remote"`). `catalog.json` is produced at release
  time and signed by the Rhizome Ed25519 release key (signature covers
  every entry incl. digest pins → trust root is the key, not the
  network).
- `pkg/modules/remote.go` (new) — remote curated index behind the sibling
  `module_index = {url:"", enabled:false}` config (see Decisions — the
  `modules.catalog_url` shape collides with the `modules` map). HTTPS
  fetch of `{url}/catalog.json` + `.sig` (loopback exception for tests,
  same as downloads) → verify → cache under
  `<RHIZOME_HOME>/catalog-cache/` (~1 h TTL so `module list` isn't a
  per-call fetch) → `List()`/`Lookup()` merge embedded+remote; embedded
  wins on id collision (counted in `module.catalog.merged`'s `shadowed`
  field); unsigned/bad-sig/stale-schema → hard refuse +
  `module.catalog.rejected`.
- `rhizome module verify <id>` (`Manager.Verify`) — re-hash the installed
  binary against the sha256 recorded at install time in
  `<id>/<version>/.binary-digest`; daemonless. *As built*: the catalog pin
  covers the release archive, not the extracted binary — so install records
  the extracted binary's digest (the archive pin having already verified)
  and verify compares the on-disk bytes to that record.
- Release plumbing — a catalog emit command (`rhizome module catalog` or
  a `scripts/` generator) + a **secret-gated** `release.yml` step (same
  pattern as Docker Hub): when `MODULE_CATALOG_SIGNING_KEY` exists, sign +
  attach `catalog.json`/`.sig`; absent → skip, embedded catalog
  unaffected. Key generation documented under `docs/operations/`.
- Events: `module.catalog.rejected|merged`, `module.verify.ok|failed`.
- Stretch inside track: upstream cosign/GPG verification where upstreams
  actually sign (verification item; most candidates don't — deferrable).

## Track 72 — ACP deepening

- **`session/load`:** advertise `AgentCapabilities.LoadSession:true`;
  implement the SDK's `AgentLoader` (`LoadSession(ctx,
  LoadSessionRequest)` — confirmed at `agent_gen.go:381`, auto-dispatched
  once the agent implements it, no registration needed). Persist
  `acpSessionId → {agent_id, session_key, cwd, created_at, last_active}`
  at `<RHIZOME_HOME>/acp-sessions.json` (bounded, atomic; the empty
  `pkg/acp/sessions/` + `pkg/acp/memory/` dirs already in-tree look like
  intended homes — use one or delete them). On load: replay
  `SessionStore.GetHistory(session_key)` (`pkg/session/manager.go`) as
  `session/update` notifications — which update kinds clients expect is a
  verification item — then re-register in `s.sessions` so `Prompt` works;
  optionally restore cached `*_always` permission decisions.
- **MCP passthrough:** honor `McpServers` on `session/new` **and**
  `session/load` (both carry the field). Map
  `McpServerStdio{Command, Args, Env}` → `config.MCPServerConfig{Enabled,
  Type:"stdio", …}`; http/sse/acp variants refuse with a clear error (we
  don't advertise those capabilities). Per-session `mcp.Manager`
  (`NewManager` + `ConnectServer` per server, bounded ~4/session); env
  hygiene = declared `Env` plus minimal `PATH` only — exact inherit set is
  an impl-time call, documented. Tools surface namespaced
  (`mcp__<server>__<tool>`) via `tools.NewMCPTool` against the session
  manager. **`ToolRegistry` has no `Unregister` today** — either add it
  (map delete + version bump) or wrap session tools in a session-guard
  keyed on the existing session-scope ctx key; teardown on close/cancel +
  process exit, with a cross-session isolation test.
- **Terminal client capability:** `acp.client.terminal_policy` = `deny`
  (default) | `allow`. On `allow`, implement the `clientHandler` terminal
  methods (`CreateTerminal`/`TerminalOutput`/`KillTerminal`/
  `ReleaseTerminal`/`WaitForTerminalExit`) over the guarded shell path
  (`pkg/tools` shell-security checks + bounded output buffer +
  per-session terminal map); advertise `ClientCapabilities.Terminal` only
  when allowed; under `deny` keep the method-not-found stubs. High-risk →
  default deny.
- Keep stdout protocol-clean (`RHIZOME_LOG_FILE`/stderr discipline) in both
  directions.

## Track 73 — Mesh depth

- **Role-aware `PickPeer`** (`mesh.rankedCandidates`): new
  `RoutingConfig{RoleAware}` under `MeshConfig` (`mesh.routing` — a
  non-omitempty bool like `NATTraversal`/`RelayService` so `false`
  survives config write-back), default true. Semantics: task ops (all
  current `PickPeer` callers) prefer workers — bonus ~`1<<19`, sized
  below the direct-connection term (`1<<20`) so a disconnected or
  at-capacity worker still loses to a healthy full peer;
  infra-dependent ops would prefer `full`. Deterministic peer-id tiebreak
  unchanged.
- **Coordinator preference** (`swarm.reelectLocked`, currently lexicographic
  min peer id): add `Role` to `pingPayload` (additive JSON — older peers
  ignore it), `Member`, `MemberInfo`; local source = extend `capProbeFunc`
  to also return the configured role via a `Mesh.Role()` accessor (the
  signature change ripples to `queue.go` and the `SetCapProbe` wiring in
  `pkg/gateway/swarm.go`); `notePing` stores it. Election =
  `sort.SliceStable` on `(roleRank, peerID)` with `roleRank(worker)=1` →
  full members first, then workers, peer-id tiebreak — still fully
  deterministic given the same roster+roles.
  **Mixed-version caveat:** pre-v0.11.0 members never send `role`, so they
  elect pure-lexicographic; during a rolling upgrade old and new members
  can briefly disagree on the coordinator. Duties are advisory
  (shared-state writes, `swarm run` orchestration); the flap resolves once
  the fleet upgrades — document it, no protocol versioning. Surface `Role`
  through `SwarmInfo.Members` → `rhizome swarm members` + launcher/
  frontend member lists.
- **Topology graph:** `web/frontend/src/components/network/
  topology-panel.tsx` — hand-rolled SVG radial layout (self center, peers
  ringed) fed by `/api/network/status` `peers[].conns`: `direction` →
  arrow/dash, `transport` → edge color incl. `/p2p-circuit` detection,
  latency → thickness or tooltip; `role` → node color/badge (Track 64
  already surfaces `role` on peers). Click-through reuses the peer-detail
  `Sheet` from `peers-panel.tsx`; the panel slots into `network-page.tsx`
  like the other single-column sections. No new JS dep.
- Smart routing stays bounded to role + requirements matching; cost/token
  economics deferred (ties into Web3 Stage 3 mesh settlement).

## Track 74 — Security polish (stretch)

- `enc2://` in `pkg/credential`: XChaCha20-Poly1305 via
  `x/crypto/chacha20poly1305.NewX` (24-byte nonce); blob layout
  `salt(16)|nonce(24)|ct`, same HKDF-SHA256 derivation (impl-time call:
  bump the HKDF info string to `-v2` for domain separation — cheap
  insurance). `Resolve` dispatches on prefix (`enc://` decrypts forever);
  `Encrypt` writes `enc2:` — a **one-way door**: downgraded binaries
  can't read new secrets, so document the re-encrypt path and
  release-note it. Node-identity store stays AES-GCM this sprint (the
  `enc2` migration needs a version prefix on `NodeIdentity` — follow-up).
- OAuth residual — verified narrow during planning: `rhizome auth login`
  already has `--device-code` (deviceauth flow, codex endpoints) and
  `--no-browser` (manual-paste loop). Remaining work is a per-provider
  headless matrix — codex → device-code works; anthropic →
  `--setup-token` or manual paste; google-antigravity → verify which path
  applies (its config may lack deviceauth endpoints → ensure
  `--device-code` errors clearly rather than hanging) — plus a
  `providers.md` headless table.

## Risk register

| Risk | Mitigation |
| --- | --- |
| Signing ships real-money risk | `signing.enabled` default false; allowlist+caps+pending-approval mandatory; audit ledger; testnet-first docs |
| No built-in human approver outside ACP | Pending-approval queue (CLI + daemon API + UI badge) — Track 69's key mechanism |
| Heavy web3 deps | go-ethereum excluded; secp256k1 + sha3 + minimal RLP/ABI only (already in module graph) |
| Remote catalog = supply-chain surface | Signature mandatory, embedded catalog is trust root, unsigned remote refused |
